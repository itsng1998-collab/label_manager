# label_manager

Flutter 기반 레이블 관리 도구입니다. Windows 환경에서 실행되며, MS SQL Server와의 연동을 위해 FFI 및 ODBC를 사용합니다.

## 주요 구성
- Flutter UI 레이어: 사용자 인터페이스와 라벨 관리 기능을 지원하는 화면 및 상태 관리 코드.
- FFI 바인딩: Dart에서 Windows ODBC API를 직접 호출하기 위한 네이티브 연동 계층.
- 데이터 접근 계층: DbClient 추상화를 통해 MS SQL Server 쿼리를 수행하고 결과를 전달합니다.

## MS SQL Server 연동
- FFI를 사용해 네이티브 ODBC 드라이버에 접속하고, 연결/쿼리/결과 처리 전 과정을 Dart에서 제어합니다.
- mssql_connection 모듈은 ODBC 연결을 열고 닫으며, 파라미터 바인딩과 레코드 변환을 담당합니다.
- DbClient 구현체는 외부에서 동일한 인터페이스로 사용할 수 있도록 설계되어, 다른 데이터 소스로의 교체가 용이합니다.

### 발행내역 조회 인덱스 자동 준비
- 발행내역 조회 전에 현재 연결된 DB의 `IX_BM_RICH_PRINT_LOG_CustomerDate` 인덱스를 확인합니다. 다른 DB로 전환해도 이전 DB의 확인 결과를 재사용하지 않습니다.
- 인덱스가 없으면 테이블의 실제 스키마에 `(RICH_CUSTOMER_ID, RICH_DATE_YYYYMMDD) INCLUDE (RICH_DATETIME)` 비클러스터형 인덱스를 자동 생성합니다. 기존 데이터나 인덱스를 삭제하거나 조회 건수를 제한하지 않습니다.
- 생성 중에는 `인덱스 생성 중입니다.`와 대기 표시를 띄우고 조회 조건/버튼을 비활성화합니다. 생성과 상태 재확인이 끝난 뒤 목록과 합계를 조회합니다. 이미 준비된 인덱스는 다시 생성하지 않습니다.
- 최초 생성에는 테이블 크기에 따라 시간이 걸리고, DB IO/디스크 사용과 쓰기 대기가 발생할 수 있습니다. DB 계정에는 해당 테이블의 인덱스 생성 권한(`ALTER`)이 필요합니다. 권한 부족, 생성 실패 또는 사용할 수 없는 인덱스 상태는 오류로 안내하며 조회를 중단합니다.
- SQL Server 2017 및 DB 호환성 수준 100에서 동작하며, 진단 로그는 `printHistoryQuery`의 `indexCheckStarted`, `indexCreating`, `indexReady`, `queryFailed` 이벤트를 확인합니다.

## 자동 영양성분표 삽입
- 공용라벨관리에서 셀을 선택하고 **자동 성분표 삽입**으로 양식을 선택하면, 해당 영양성분 형식에 등록된 키워드·이름을 **영양성분** 사용 항목으로 자동 등록한 뒤 선택 셀에 표를 삽입합니다. `#N01` 등을 표에서 추측하지 않고 선택한 형식의 항목 정의를 사용합니다.
- 레거시와 동일하게 키워드가 하나라도 이미 등록되어 있으면 삽입을 거부합니다. 등록할 항목이 없거나 등록에 실패해도 표만 삽입하지 않고 오류를 표시합니다. 등록 중에는 입력을 차단합니다.
- 항목 등록은 삽입 시 기존 항목 저장 트랜잭션으로 수행하며, 기존 품목과 자동갱신 품목의 빈 내용도 준비합니다. 다른 미저장 필수등록·이미지 크기 변경은 저장하지 않고 유지합니다. 표 편집 내용은 라벨 **저장**으로 보관합니다.
- 표 삽입을 **실행 취소**해도 이미 등록된 사용 항목은 삭제하지 않습니다. 항목은 **항목 편집**에서 관리합니다. 실제 저장 후 목록 갱신 실패나 커밋 결과 불명은 별도 오류로 안내하므로, 이 경우 최신 항목을 다시 조회한 뒤 상태를 확인합니다.
- 진단 로그는 `nutritionTableInsert`의 `columnsRegistering`, `columnsRegistered`, `completed` 또는 `failed`를 확인합니다.

## 신규 사용자 로그인과 업데이트 공지
- 사용자 관리에서 등록한 계정에 업데이트 공지 행이 없어도 사용자 조회와 로그인을 계속합니다. 공지가 없는 경우 빈 공지 확인 창을 표시하지 않으며, 로그인 조회에서 공지 행이나 숨김 상태를 생성·저장하지 않습니다.
- 공지가 등록된 계정의 메시지·표시/숨김 상태는 그대로 적용됩니다. 실제 DB 조회 오류는 공지 없음으로 처리하지 않고 오류로 안내하며, 존재하지 않는 사용자와 틀린 비밀번호도 계속 거부합니다.
- 로그의 `updateNotice / lookupCompleted`에 `found=false`가 있으면 정상 조회 결과에 해당 계정의 공지 행이 없었다는 뜻입니다. 실제 조회 실패는 `lookupFailed`로 구분됩니다.

## 공용라벨 필수등록 저장
- 사용 항목의 **필수등록** 체크는 항목 편집의 **누락 키워드 검사**와 같은 편집값입니다. 체크 후 항목 편집에서 해제하고 **적용 → 저장**해도 저장할 수 있습니다.
- 본 테이블과 필수등록 보조 테이블의 기존 값이 서로 달라도 각각의 조회 원본값으로 동시 수정 여부를 비교합니다. 필수등록 변경을 저장하면 두 테이블에 선택한 값을 반영하며, 편집 시작 후 다른 사용자가 원본을 바꾼 경우에는 기존 충돌 검사와 트랜잭션 롤백을 유지합니다.
- 본 테이블의 선택 컬럼 유무를 조회하여 해당 컬럼이 없는 DB도 지원합니다. 공용라벨 저장만으로는 변경되지 않은 본 테이블 원본값을 갱신하지 않습니다.

## 기본 항목 사용자 정의 text
- 공용라벨관리의 **항목 편집**에서 기본 항목의 `사용자 정의 text`에 내용을 입력한 뒤 **적용 → 저장**합니다. 입력란 오른쪽 키워드 삽입 버튼을 누르면 큰 편집 창이 열립니다.
- 편집 창의 입력 항목을 **더블클릭**하거나 텍스트 입력란으로 **드래그**하면 현재 커서/선택 위치에 `#키워드`가 삽입됩니다. `#ITEMNAME`은 현재 품목명입니다. 직접 입력과 줄바꿈도 가능하며 200자까지 입력할 수 있습니다.
- 예: `#TEXT1 + #TEXT2 + #TEXT3 = 6`은 현재 품목값이 각각 `1`, `2`, `3`일 때 `1 + 2 + 3 = 6`으로 출력됩니다. 수식을 계산하지는 않습니다. 자기 키워드도 해당 품목의 원래 값을 사용하며, 치환된 값 속 키워드를 재귀적으로 확장하지 않습니다.
- **연한 하늘색은 현재 편집 항목**, **연한 보라색은 템플릿에 참조된 항목**입니다. 같은 행이 둘 다 해당하면 현재 편집 표시가 우선합니다.
- 설정한 내용은 품목의 출력내용 미리보기와 라벨/저울 발행에 적용되며, 품목 입력값과 자동증가 저장값은 덮어쓰지 않습니다. 빈 내용으로 적용·저장하면 다시 품목값을 출력합니다. 기존 기본 항목의 사용자 정의 QRData 형식도 읽을 수 있으며, 바코드·QR 전용 설정은 변경하지 않습니다.

## 이미지 파일 교체
- 공용라벨관리에서 이미지를 선택한 뒤 이미지 속성의 **파일 교체**를 누르면 파일 선택창이 열립니다. 새 파일을 선택하면 연결 설정과 위치·크기·회전·자르기 정보는 유지하고 이미지 파일만 바뀝니다. 라벨을 **저장**하여 변경 내용을 보관합니다.
- 파일 선택을 취소하면 기존 이미지가 유지됩니다. 파일을 읽지 못하면 속성에 오류가 표시되며 다시 파일을 선택할 수 있습니다.

## 공용라벨의 연결 이미지 표시
- 공용라벨의 이미지 연결 ID를 변경하고 **적용**하면, **품목관리에서 현재 선택한 품목**의 해당 이미지로 표시됩니다. 아직 저장하지 않은 품목 편집값도 사용하며, 품목을 바꾸면 표시 이미지가 갱신됩니다. 복제한 이미지에도 동일하게 적용됩니다.
- 선택 품목이 없거나 연결 항목의 값/이미지 파일이 없으면 이전 파일을 계속 표시하지 않고 연결 ID와 이미지 없음 안내를 표시합니다. **연결 안함** 이미지와 바코드는 이 표시 치환의 영향을 받지 않습니다.
- 선택 품목의 이미지는 화면 표시용입니다. 라벨에 보관된 원래 이미지 파일이나 품목 원본값을 덮어쓰지 않으며, 실제 품목 미리보기·발행에서는 각 품목의 이미지가 개별적으로 적용됩니다.
- 이미지·바코드·GS1바코드의 폭·높이는 개체 속성에서 지정합니다. 항목 편집에서는 중복 크기 입력란을 숨기며, 기존 저장값은 보존합니다. 공용라벨의 미저장 크기와 DB에 저장된 크기를 구분하고 실제 다른 사용자의 동시 수정 검사는 유지합니다.

## GS1 AI 표시와 바코드 형식
- GS1 AI 항목의 **GS1 code 표시**는 라벨 텍스트에만 `(AI)`를 붙입니다. 바코드 검증·조합 및 발행용 값에는 원본값을 사용합니다. 예를 들어 AI `00`의 품목값이 `123412341234123412`이면 텍스트는 `(00)123412341234123412`, 바코드 조합값은 `00123412341234123412`입니다. 표시를 켜거나 꺼도 검증 결과와 바코드 데이터는 같습니다.
- SSCC는 원본 18자리로 검사합니다. 자리수가 다르거나 원본값 자체에 `(00)`이 들어 있으면 계속 오류로 처리합니다. 앞자리 0은 보존하며 날짜형 포함 항목의 기존 날짜 계산과 FNC1 구분자 처리도 유지합니다.
- **GS1바코드** 항목은 GS1 code 사용을 항상 적용하고 해당 체크박스를 숨깁니다. 기존 해제값도 출력할 때는 GS1 방식으로 처리하며, 항목 **적용 → 저장** 시 사용 상태를 저장합니다. 항목 편집 및 GS1 연결 개체의 형식 목록에서 CODE39·MicroQRCode·CODE93을 제외합니다. 해당 형식으로 저장된 기존 설정은 임의 변환하지 않고 지원 형식 선택을 안내합니다.
- 모든 바코드는 개체에 지정된 형식을 유지합니다. **템플릿 바코드 형식 유지** 선택기와 삽입 창의 형식 고정 선택기는 숨기며 항상 켠 것으로 처리합니다. 기존 해제값도 자동 형식 변경을 허용하지 않습니다. 데이터가 맞지 않으면 CODE128 등 다른 형식으로 바꾸지 않고 미리보기 오류와 발행 차단으로 알립니다. 연결 항목을 바꿔도 기존 개체 형식은 유지되므로 필요한 형식 변경은 개체 속성에서 직접 지정합니다.
- 항목 편집에서 1D 바코드의 **Line check·Line size·회전**을 숨깁니다. 선은 도형 삽입, 회전은 개체 속성을 사용합니다. 속성의 **모듈 배율**은 2D일 때만 편집 가능하며, 1D 바코드 항목에 연결된 개체에서는 비활성화합니다.
- 회귀 테스트는 `test\item_code_data_resolver_test.dart`, `test\label_column_edit_dialog_test.dart`, `test\label_sheet_barcode_height_test.dart`와 `test\label_sheet_toolbar_test.dart`의 `GS1 SSCC` 테스트를 사용합니다. Windows 네이티브 인코더 DLL 경로를 `PATH`에 추가하고 `flutter test --no-pub --dart-define=BARCODE_GS1_NATIVE=true test\label_sheet_toolbar_test.dart --name "GS1 SSCC"`로 실제 PNG와 인쇄 이미지 변환을 확인할 수 있습니다. 실제 프린터 발행은 하지 않습니다.

## 바코드 사용자 정의 text
- 공용라벨관리의 **항목 편집 → 바코드 항목 → 사용자 정의 text** 오른쪽 추가 버튼으로 키워드 편집 창을 엽니다. 현재 사용 항목을 더블클릭하거나 입력란으로 드래그하면 `#키워드`가 삽입됩니다. 직접 입력과 고정 문구도 지원하며 최대 200자입니다.
- **미리보기 품목**을 선택하면 해당 품목의 실제 값으로 바코드 이미지와 하단 text를 확인할 수 있습니다. 예를 들어 `#TEXT1`의 품목값이 `1234`이면 하단에 `1234`를 표시합니다. 품목이 없거나 이미지 생성에 실패하면 안내를 표시하며 이전 이미지를 재사용하지 않습니다.
- **사용자 정의 text는 하단 글자만 변경하고 스캔값은 변경하지 않습니다.** `BARCODE=12345679123`, `TEST=2345`, 사용자 정의 text=`#TEST`이면 스캔값은 `12345679123`, 하단 글자는 `2345`입니다. 스캔값 연결은 기존 바코드 데이터 설정과 별개입니다.
- **적용 → 저장** 후 품목의 출력내용 미리보기와 라벨/저울 발행에 반영됩니다. **번호 표시**를 끄면 하단 글자는 출력하지 않습니다. 사용자 정의 text를 비워 저장하면 기존 바코드 번호 표시로 돌아갑니다. 참조 품목값이 비어 있으면 빈 글자로 치환하고, 수식이나 참조된 값 안의 키워드는 다시 계산하지 않습니다. 공용라벨 자체는 품목을 선택하지 않은 템플릿이므로 실제값 확인은 품목 선택 미리보기에서 합니다.

## 연결된 2D 바코드 데이터
- QR·Micro QR·Data Matrix 연결 항목은 **기본** 방식에서 품목값, **사용자 정의** 방식에서 QR data 조합, **나트륨** 방식에서 설정된 URL 조합을 사용합니다.
- 사용자 정의 **QR data 자체** 또는 **나트륨 조합 설정 자체**가 비어 있으면, 품목의 해당 2D 바코드 값을 사용합니다. QR 데이터 보기와 출력내용 미리보기에 대체 사용 경고를 표시하고 진단 로그에도 기록합니다. 저장된 생성 방식·조합 설정과 품목 데이터는 변경하지 않습니다.
- 이미 설정된 QR data 조합의 결과가 빈 경우나 비어 있지 않은 잘못된 나트륨 설정은 품목값으로 대체하지 않습니다. 조합 설정과 품목값이 모두 없을 때도 오류로 표시하고 발행을 차단합니다. 유효한 조합·URL 및 별도로 설정한 QR text는 유지합니다.
- 삽입 시 연결과 속성에서 연결 변경 모두 같은 품목별 해석을 사용합니다. 공용라벨은 템플릿이므로 실제 데이터는 품목 선택 후 확인합니다.
- 현재 포함된 네이티브 인코더는 Micro QR 생성을 지원하지 않습니다. Micro QR의 데이터 해석은 적용되지만 이미지 생성·발행은 오류로 차단하며, 다른 바코드 형식으로 임의 변경하지 않습니다. QR·Data Matrix 이미지 생성과는 별개의 기존 제한입니다.
- 회귀 테스트: `flutter test --no-pub test\item_code_data_resolver_test.dart` 및 `flutter test --no-pub test\label_sheet_toolbar_test.dart --name "linked 2D"`. 실제 2D PNG 생성과 Windows 인쇄 이미지 변환까지 확인하려면 빌드된 `flutter_zxing.dll` 폴더를 현재 PowerShell의 `PATH`에 추가하고 후자 명령에 `--dart-define=BARCODE_2D_NATIVE=true`를 추가합니다. 실제 프린터 발행은 수행하지 않습니다.

## 바코드 삽입·속성 크기
- 1D 바코드 삽입 창에서 **세로**를 변경하면 **바코드 높이**도 같은 값으로 맞춰집니다. 비율 유지 상태에서 가로 변경으로 세로가 바뀌는 경우에도 동일하게 적용됩니다. 따라서 비율 유지 해제 후 가로20mm/세로10mm와 가로20mm/세로20mm로 삽입하면 막대 높이가 다르게 표시됩니다.
- 이후 **바코드 높이**를 직접 입력하면 그 값을 사용합니다. 문자 표시를 켠 경우 전체 세로 안에 문자 영역을 확보하므로 막대의 실제 높이는 남은 영역으로 제한됩니다. QR 등의 모듈 크기 설정과 기존에 저장된 바코드는 변경하지 않습니다.
- 바코드를 복제한 뒤 속성에서 회전만 변경해도 기존 폭·높이와 막대 높이는 유지됩니다. 속성의 **바 높이**는 라벨의 mm/px 단위로 표시하며, 적용·저장·품목 미리보기와 출력 명령 준비에서도 같은 단위를 사용합니다. RTF에서 가져온 바코드의 기존 픽셀 단위 정보도 유지합니다.
- 바코드 속성의 폭·높이 아래 **비율 유지**를 선택할 수 있습니다(기본 선택). 체크하면 현재 개체 비율을 기준으로 마지막으로 입력한 폭 또는 높이에 맞춰 다른 치수를 **적용** 시 조정하고, 해제하면 폭·높이를 각각 적용합니다. 1D/QR 모두 지원합니다. 삽입 창에서 선택한 상태를 개체 속성에 전달하며, 속성에서 변경한 상태는 **적용** 후 개체별로 라벨에 저장합니다. 다른 개체 선택·복제·실행취소/재실행·라벨 저장 후 다시 열기에도 유지됩니다. 이전 저장본에 상태 정보가 없으면 기존처럼 기본 선택입니다. 일반 이미지의 비율 유지 옵션은 기존 화면 편집 동작을 유지합니다.
- 1D 바코드 속성도 삽입 창과 동일하게 **높이** 변경 시 **바 높이**를 같은 값으로 맞춥니다. 비율 유지에 따른 폭 변경도 적용될 높이로 맞추며, 이후 **바 높이**를 직접 입력하면 그 값이 우선합니다. 복제본의 높이10→15 변경 시 원본은 유지하고 복제본의 실제 막대 높이도 변경됩니다. 비율 해제 상태의 폭만 변경하거나 회전만 변경할 때, QR/Matrix의 크기를 변경할 때에는 바 높이를 덮어쓰지 않습니다.
- 속성의 **비율 유지**, **사람이 읽는 텍스트 표시**는 체크 상태만 바꾸어도 **적용**됩니다. 라벨 저장 후 다시 열어도 유지되며, 텍스트 표시를 끄면 하단 글자를 제외한 바코드를 생성합니다. 템플릿 형식 유지는 항상 적용되어 별도 선택기를 표시하지 않습니다.
- **텍스트 글꼴**은 삽입 창과 같은 글꼴 목록을 사용하는 검색·선택 콤보박스입니다. 직접 입력도 가능하며, 목록에 없는 기존 저장 글꼴은 그대로 표시·보존합니다. 입력을 비우면 기본 글꼴을 사용합니다. 글꼴 변경 후 **적용 → 라벨 저장**으로 반영합니다.
- 회귀 테스트: `flutter test test\label_sheet_barcode_height_test.dart`. 기본 실행은 네이티브 인코더만 테스트 패턴으로 대체하고 실제 크기 계산·PNG 합성을 사용합니다. Windows 빌드 후 실제 인코더까지 검증하려면 빌드된 `flutter_zxing.dll` 폴더를 현재 PowerShell의 `PATH`에 추가하고 `flutter test --dart-define=BARCODE_HEIGHT_NATIVE=true test\label_sheet_barcode_height_test.dart`를 실행합니다.

## 라벨출력 미리보기의 밀기 조정
- **프린터 설정**의 **왼쪽 밀기**와 **위쪽 밀기**를 적용하면 라벨출력 미리보기의 셀·이미지·바코드·선·도형 위치가 함께 갱신됩니다. 양수·음수, 두 축 동시 조정 및 0으로 복원을 지원하며, 실제 출력과 같은 여백+밀기 위치 계산을 사용합니다.
- 눈금자와 라벨 경계는 고정하고 내용만 현재 확대 배율에 맞춰 이동합니다. 라벨 밖으로 이동한 부분은 미리보기에서 잘립니다. 품목별 여백/밀기 설정과 발행 목록에서 직접 수정한 값의 기존 우선순위는 유지합니다.
- 이 조정은 라벨출력 화면 표시용입니다. 일반 품목 미리보기·공용라벨 원본은 바꾸지 않으며, 출력용 원본 캡처에는 조정값을 넣지 않아 실제 발행에서 한 번만 적용됩니다.
- 회귀 테스트: `flutter test test\label_print_preview_push_test.dart`. 실제 설정 창 적용, 양축 ±5mm·조합·0 복원, 확대/잘림, 개체별 픽셀 위치, 눈금자·원본 캡처 유지, 품목/목록 설정 우선순위와 Windows 출력 이미지 준비까지 확인합니다. 실제 인쇄는 수행하지 않습니다.

## 라벨출력 자동줄간격
- **프린터 설정 → 자동줄간격**의 80%~300%를 적용하면 일반 문단의 글꼴·줄바꿈에 맞춰 출력용 행 높이와 다음 문단 위치를 다시 계산합니다. 글자 크기나 라벨 전체 이미지를 확대·축소하는 기능은 아닙니다.
- 레거시와 같이 표 내부는 선택한 배율 대신 **115% 줄간격**을 사용하고 기존 표 행 높이를 유지합니다. 표는 테두리·다중 셀·세로 병합 및 RTF 표 정보를 기준으로 구분합니다. RTF에서 새로 가져오는 테두리 없는 단일 셀 표도 표 정보를 보존합니다.
- **설정 안 함**은 저장된 줄간격과 행 높이를 사용합니다. 레거시와 같이 프린터 설정을 적용하면 **품목별 줄간격을 사용하지 않는 행**은 발행 목록에서 직접 수정했더라도 새 기본값으로 갱신됩니다. 품목별 줄간격을 사용하는 행은 현재 값을 유지하며, 품목 DB 설정은 변경하지 않습니다. 큰 줄간격으로 라벨 영역을 넘으면 출력에서 잘리므로 미리보기로 확인합니다.
- 미리보기와 Windows/G500·PDF/비트맵·EZPL 출력 준비에 같은 계산을 사용합니다. 공용라벨과 품목 원본 서식은 바꾸지 않으며, 반복 적용해도 누적되지 않습니다. RTF 문단에 연결된 이미지는 문단 이동을 따르고 일반 절대좌표 개체는 원래 위치를 유지합니다.
- 회귀 테스트: `flutter test test\label_print_line_spacing_test.dart`. 80%/300%의 실제 PNG와 네이티브 텍스트 위치 차이, 표 규칙, 혼합 글꼴·줄바꿈, 원본 복원 및 미리보기/출력 준비의 일치를 확인합니다. 실제 인쇄는 수행하지 않습니다.

## 라벨출력 발행매수
- Windows 프린터는 같은 품목 행에서 출력 내용이 같은 연속 라벨을 한 작업으로 묶고, 해당 매수를 드라이버에 전달합니다. 예를 들어 동일 라벨 3장은 `copies=3`인 작업 하나로 요청합니다.
- 자동증가 등으로 장마다 값이 달라지면 별도 작업으로 유지하며, 다른 품목이나 출력 크기를 섞지 않습니다. 드라이버의 매수 범위(최대 32,767매)를 넘으면 작업을 나눕니다.
- GoDEX는 드라이버가 생성한 다매수 PRN을 역상 보정 후 한 번 제출합니다. BIXOLON의 페이지 반복 처리, PDF 출력 및 발행내역의 라벨별 매수 집계는 유지합니다. 로그의 접수 매수는 스풀 접수 기준이며 실제 종이 배출을 보증하지 않습니다.

## Windows 프린터의 검정 배경과 흰 글자
- GoDEX 외 프린터(D420/BIXOLON, Zebra 등)도 검정 배경과 흰 글자를 원래 서식대로 출력합니다. 제목행을 흰색으로 지우고 글자를 검정으로 바꾸던 처리를 제거했습니다.
- 기존 단색 메모리 비트맵에 흰 글자를 합성한 뒤 드라이버로 전달합니다. GoDEX 전용 역상 합성/PRN 전송과 다른 프린터의 GDI 제출, 드라이버 설정·해상도·배율·매수는 유지합니다.
- 종이를 출력하지 않는 실제 GDI 픽셀 회귀는 [역상 무출력 검사](tools/inverse_rich_edit_probe/README.md)의 `printer_background_polarity`를 사용합니다. D420/203dpi·Zebra/300dpi 상당 크기, 재샘플링, 전체/부분 검정 배경의 흰 글자와 일반 검정 글자를 확인합니다. 드라이버별 실물 품질은 별도 확인이 필요합니다.

## 시작하기
1. Windows 10/11 환경에서 PowerShell 5.1 이상과 winget 사용 가능 여부를 확인합니다.
2. Windows ODBC Driver를 설치합니다.
3. https://jrsoftware.org/isdl.php/Inno-Setup-Downloads을 다운로드 받아 설치 합니다. (배포 작성)
4. Flutter SDK를 설치하고 Flutter doctor로 환경을 확인합니다.
5. flutter.ps1 pub get으로 의존성을 받습니다. 이때 Windows용 MSBuild가 없으면 winget으로 Visual Studio Build Tools 2022(C++ workload) 설치를 시도합니다.
6. Flutter run을 실행하여 애플리케이션을 구동합니다.
7. Visual Studio Code에 최적화 되어 있습니다. (프로젝트 개발)

### Windows Build Tools 자동 설치 지원 환경
- 지원: Windows 10/11, PowerShell 5.1 이상, winget 사용 가능 환경.
- 확인: PowerShell에서 `winget --version`이 버전을 출력해야 합니다.
- winget이 없는 PC에서는 자동 설치가 중단됩니다. Microsoft App Installer가 포함된 Windows 10/11 환경에서 다시 `flutter.ps1 pub get`을 실행하거나, Visual Studio Build Tools 2022의 Desktop development with C++ workload를 수동 설치한 뒤 다시 실행합니다.
