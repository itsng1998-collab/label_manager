# 라벨 시트 선·도형 객체 및 통합 객체 패널 구현 작업지시서

## 0. 최우선 원칙

- 이 문서는 현재 FortuneSheet 기반 라벨 시트에 직선, 사각형, 둥근 사각형과 타원 객체를 추가하고, 기존 이미지·바코드 레이어 패널을 단일 선택 속성 편집과 다중 선택 레이어 조정을 함께 제공하는 통합 객체 패널로 확장하는 구현 기준이다.
- 기존 `FortuneImage`, `FortuneSheet.images`, 저장된 `sheet.images` JSON의 의미와 호환성을 유지한다. 이미지·바코드를 새 배열로 마이그레이션하거나 기존 저장 파일을 일괄 변환하지 않는다.
- endpoint 기반 직선은 `FortuneLine`과 `FortuneSheet.lines`, bounds 기반 사각형·둥근 사각형·타원은 `FortuneShape`와 `FortuneSheet.shapes`로 분리 저장한다. 이미지로 rasterize해 저장하거나 `FortuneImage.extraFields`에 geometry를 억지로 넣지 않는다.
- 이미지·바코드·직선·폐쇄 도형의 선택, Z-Order, 레이어 목록과 공통 명령은 런타임 공통 객체 참조로 통합한다. 공통 참조는 저장 포맷이 아니며 각 typed model의 소유권을 없애지 않는다.
- 직선과 폐쇄 도형의 화면 렌더, PNG capture, PDF와 EZPL 출력은 같은 geometry/style 해석을 사용한다. 미리보기와 실물 출력에 서로 다른 테두리 패턴·두께·채우기·Z-Order를 만들지 않는다.
- 기존 이미지·바코드 생성 다이얼로그는 유지한다. 기존 객체의 일상적인 속성 편집만 오른쪽 객체 패널로 옮기고, 이미지 파일 선택은 panel button으로 실행하며 자르기처럼 별도 작업면이 필요한 기능은 기존 전용 다이얼로그를 유지한다.
- 현재 레이어 패널의 다중 선택, 키보드 명령, 복사·붙여넣기와 Z-Order 이동 동작을 퇴행시키지 않는다.
- 객체는 특정 cell range에 귀속되지 않으므로 모든 object mutation의 공통 권한은 workbook `allowEdit`만 사용한다. 현재 cell selection의 protection/locked 상태로 객체 명령 허용 여부를 바꾸지 않는다.
- workbook 변경만 dirty/undo 대상이다. 패널 열림 상태, 패널 폭, splitter drag와 내부 스크롤은 workbook에 저장하지 않고 dirty 또는 undo를 만들지 않는다.
- `labelSheetSaveFeatureVersions`, sanitizer allow-list, migration과 저장 회귀 테스트를 함께 변경한다. 저장 기능 키나 allow-list 중 하나만 수정하지 않는다.
- DB schema, SQL, DAO와 데이터 migration은 이번 작업 범위가 아니다.
- 배포 build, installer 생성과 원격 push는 별도 요청이 있을 때만 수행한다.

## 1. 구현 목적

1. 라벨 시트 툴바에 직선·사각형·둥근 사각형·타원과 스타일을 선택하는 통합 도형 삽입 콤보를 추가한다.
2. 시트에서 drag해 직선은 시작점/끝점, 폐쇄 도형은 bounds를 생성한다.
3. 직선 본체·두 끝점 편집과 폐쇄 도형 이동·8방향 resize·회전을 지원한다.
4. 이미지·바코드·직선·폐쇄 도형을 하나의 paint/hit-test/layer 순서로 관리한다.
5. 기존 부유 레이어 패널을 시트 오른쪽의 통합 객체 패널로 확장한다.
6. 객체 하나를 선택하면 해당 타입의 속성을 표시하고, 여러 객체를 선택하면 공통 레이어 조정 명령을 표시한다.
7. 시트와 패널 사이에 공용 `VerticalPaneSplitter`를 두어 사용자가 패널 폭을 조절할 수 있게 한다.
8. 직선과 폐쇄 도형이 저장·복원, 라벨 미리보기, PNG capture, PDF와 EZPL 출력에 같은 모습으로 포함되게 한다.

## 3. 현재 코드 기준과 재사용 경계

### 3.1 현재 객체 모델

- 이미지와 바코드는 모두 `FortuneSheet.images`의 `FortuneImage`다.
- 바코드는 `FortuneImage.extraFields['fortuneBarcode'] == true`로 구분한다.
- 이미지 연결 ID는 `fortuneImageObjectIdExtraKey`, 바코드 연결 ID는 `fortuneBarcodeObjectIdExtraKey`를 사용한다.
- 공통 레이어 값은 `fortuneSheetObjectZOrderExtraKey == 'zOrder'`다.
- 기존 `fortuneImagesInPaintOrder()`는 이미지 배열 안에서만 정렬한다.

### 3.2 현재 레이어 패널

- 현재 패널은 폭 220px, 최대 8행의 부유 패널이다.
- 이미지·바코드 행, 다중 선택, 행 drag reorder, 삭제·복제·앞/뒤 이동과 키보드 명령이 이미 있다.
- 행 더블클릭 또는 Enter는 기존 이미지/바코드 편집 다이얼로그를 연다.
- 새 패널은 이 기능을 제거하지 않고 typed object 목록으로 일반화한다.

### 3.3 공용 splitter

- `lib/widgets/vertical_pane_splitter.dart`의 `VerticalPaneSplitter`를 재사용한다.
- 공용라벨관리와 라벨출력에서 이미 사용하는 시각 스타일과 좌우 resize cursor를 유지한다.
- 이 기능에 필요한 더블클릭 기본 폭 초기화 callback을 기존 사용처에 영향을 주지 않는 optional property로 확장한다. 키보드 resize와 활성 색상은 접근성 검토에서 필요할 때 같은 방식으로 추가한다.

## 4. 직선·폐쇄 도형 저장 model과 JSON 포맷

### 4.1 `FortuneLine`

최소 model은 다음 값을 가진다.

- `String id`
- `double x1`
- `double y1`
- `double x2`
- `double y2`
- `FortuneStrokeStyle strokeStyle`
- `double strokeWidthMm`
- `String strokeColor`
- `double zOrder`
- codec round-trip에 필요한 raw value/hasRaw 또는 기존 model과 동등한 metadata 보존 구조
- 향후 호환을 위한 `Map<String, Object?> extraFields`

`x1/y1`과 `x2/y2`는 각각 독립된 시작점과 끝점의 시트 logical coordinate다. 이미지의 left/top anchor나 width/height 의미로 해석하지 않는다. `strokeWidthMm`만 출력 물리 두께를 명시적으로 소유하며 화면에서는 기존 FortuneSheet logical pixel↔mm 변환 helper로 변환한다.

`strokeColor`는 line/shape 전용 validator가 허용하는 `^#[0-9A-Fa-f]{6}$` wire만 사용한다. 공용 Fortune color parser가 추가로 허용하는 `#RGB`, 8자리 alpha hex, `rgb()`와 `rgba()`는 이번 범위에서 유효하지 않다. 유효한 값은 대문자 `#RRGGBB`로 canonicalize하며 기본값은 `#000000`이다.

### 4.2 공통 stroke enum과 wire 값

```text
FortuneStrokeStyle.solid   <-> "solid"
FortuneStrokeStyle.dashed  <-> "dashed"
FortuneStrokeStyle.dotted  <-> "dotted"
FortuneStrokeStyle.dashDot <-> "dashDot"
```

알 수 없는 stroke wire 값은 line/shape 객체 전체를 버리지 않고 `solid`로 읽는다. 다음 save에서 현재 지원 wire로 정규화한다.

### 4.3 `FortuneShape`

사각형·둥근 사각형·타원은 하나의 bounds 기반 model을 사용한다.

- `String id`
- `FortuneShapeKind kind`
- `double left`
- `double top`
- `double width`
- `double height`
- `double rotationDegrees`
- `FortuneStrokeStyle strokeStyle`
- `double strokeWidthMm`
- `String strokeColor`
- `String? fillColor`
- `double cornerRadiusMm`
- `double zOrder`
- codec round-trip에 필요한 raw value/hasRaw 또는 기존 model과 동등한 metadata 보존 구조
- 향후 호환을 위한 `Map<String, Object?> extraFields`

wire 값은 다음과 같다.

```text
FortuneShapeKind.rectangle        <-> "rectangle"
FortuneShapeKind.roundedRectangle <-> "roundedRectangle"
FortuneShapeKind.ellipse          <-> "ellipse"
```

- `left/top/width/height`는 이미지와 같은 시트 logical coordinate다.
- `width`와 `height`는 저장 시 항상 양수로 정규화한다.
- `rotationDegrees`는 시계 방향 degree이며 기본값 `0.0`, 저장 정규화 범위는 `0 <= value < 360`이다.
- `fillColor == null`은 채우기 없음이다. stroke와 같은 전용 validator의 단색 `#RRGGBB` wire만 지원하고 유효한 값은 대문자로 canonicalize하며 기본값은 null이다.
- `cornerRadiusMm`는 `roundedRectangle`에서만 사용하고 기본값은 `2.0`, 유효 범위는 `0.0~50.0 mm`다. 실제 렌더에서는 현재 bounds의 짧은 변 절반을 넘지 않게 clamp한다.
- rectangle/ellipse의 canonical `cornerRadiusMm`는 항상 `0.0`이다. 해당 kind에 들어온 다른 값은 사용하지 않고 normalize 후 재저장 시 `0.0`으로 쓴다. roundedRectangle 값만 의미 있게 round-trip한다.
- 알 수 없는 shape kind는 다른 타입으로 추정하지 않고 해당 shape entry만 무시한다.

### 4.4 JSON 예시

```json

      "x1": 20.0,
      "y1": 30.0,
      "x2": 180.0,

      "strokeStyle": "dashed",
      "strokeWidthMm": 0.5,
      "strokeColor": "#000000",
      "zOrder": 3.0
    }
  ],
  "fortuneShapes": [
    {
      "id": "roundRect_1",
      "kind": "roundedRectangle",
      "left": 30.0,
      "top": 50.0,
      "width": 120.0,
      "height": 60.0,
      "rotationDegrees": 0.0,
      "strokeStyle": "solid",
      "strokeWidthMm": 0.5,
      "strokeColor": "#000000",
      "fillColor": null,

    }

```

### 4.5 codec 규칙

- `FortuneSheet`에 immutable `List<FortuneLine> lines`와 raw lines metadata를 추가한다.
- 기존 public model 호출 호환을 위해 `FortuneSheet` 생성자의 `lines`/`shapes` 인자는 optional이고 생략 시 각각 빈 immutable list다. `copyWith()`에서 typed list와 대응 raw value/`hasRaw*` 인자를 모두 생략하면 기존 typed list와 raw metadata를 deep clone해 보존한다. typed list를 명시적으로 교체하고 대응 raw metadata를 함께 제공하지 않으면 stale raw value와 `hasRaw*` 상태를 폐기한다. 기존 `FortuneSheet(id:, name:)` 호출부에 신규 required 인자를 요구하지 않는다.
- 사용자가 확정한 대로 sheet JSON의 canonical key는 `lines`다. `lines`와 `fortuneShapes`는 신규 typed model/raw metadata가 각각 단독 소유하며 `_unhandledSheetFields()`의 handled key에 추가해 `extraFields`와 이중 소유하거나 stale unknown raw가 encoder에서 typed 결과를 덮어쓰지 않게 한다. 기존 unknown `lines`/`fortuneShapes` 값도 typed decoder 규칙으로만 판정하고 invalid entry가 있으면 아래 raw-list 전체 폐기·canonical encode 규칙을 적용한다.
- 필수 필드는 `id`, `x1`, `y1`, `x2`, `y2`다.
- line/shape의 `id` wire는 JSON string이고 `trim()` 결과가 non-empty여야 한다. 숫자·bool 등 다른 JSON 타입을 문자열로 암묵 변환하지 않으며 빈/공백 ID entry는 무시한다. canonical ID는 trim된 문자열을 사용하고 trim 또는 중복 재발급이 발생하면 raw list를 재사용하지 않는다.
- 필수 필드가 없거나 좌표가 유한한 숫자가 아니면 해당 line entry만 무시한다.
- `strokeStyle` 기본값은 `solid`다.
- `strokeWidthMm` 기본값은 `0.5`, 유효 범위는 `0.1 <= value <= 10.0`이다. decode 값이 없거나 유한하지 않거나 범위 밖이면 clamp하지 않고 `0.5`를 사용한다.
- `strokeColor` 기본값은 `#000000`이다. decode 문자열이 line/shape 전용 `^#[0-9A-Fa-f]{6}$`와 일치하지 않으면 공용 Fortune color parser의 처리 가능 여부와 무관하게 `#000000`을 사용한다.
- `zOrder`가 없거나 숫자가 아니거나 유한하지 않으면 `0.0`이다. 숫자와 문자열 형태의 `NaN`, `Infinity`, `-Infinity`를 모두 비유한 값으로 처리하고 다음 save에서 canonical `0.0`을 쓴다.
- 빈 `lines`는 기존 파일과 같은 결과를 만들며 기존 `images` decoding에 영향을 주지 않는다.
- 지원하지 않는 line extra field는 Fortune model 내부 round-trip에서는 보존할 수 있지만, LabelSheet 저장 sanitizer에서는 allow-list 밖 값을 제거한다.
- `FortuneSheet`에 immutable `List<FortuneShape> shapes`와 raw fortuneShapes metadata를 추가한다.
- Dart model 이름은 `FortuneSheet.shapes`를 유지하되 신규 typed shape JSON의 canonical key는 사용자가 확정한 `fortuneShapes`다.
- shape 필수 필드는 `id`, `kind`, `left`, `top`, `width`, `height`다.
- 필수 필드가 없거나 geometry가 유한한 숫자가 아니거나 width/height가 0 이하이면 해당 shape entry만 무시한다.
- stroke style/width/color 기본값과 validation은 line과 같다.
- `fillColor`가 null이면 채우기 없음이며, 전용 `#RRGGBB` wire가 아닌 문자열은 공용 parser의 처리 가능 여부와 무관하게 null로 읽는다.
- `rotationDegrees`, `cornerRadiusMm`가 없거나 유한하지 않으면 각 기본값을 사용한다.
- 빈 `fortuneShapes`는 기존 파일과 같은 결과를 만들며 images/lines decoding에 영향을 주지 않는다.
- 지원하지 않는 shape extra field의 round-trip/sanitizer 경계는 line과 같다.
- 기존 sheet-level `shapes` map/list는 FortuneSheet raw shape overlay wire이므로 신규 typed shape로 decode하거나 migrate하지 않고 `extraFields['shapes']`에 원형 보존한다. 기존 painter·capture 동작도 유지하며 `fortuneShapes`와 동시에 존재해도 어느 한쪽을 덮어쓰지 않는다. legacy raw overlay는 이번 통합 object 선택·편집·공통 zOrder 대상이 아니며 기존 overlay 렌더 순서를 유지한다.
- active sheet 안에서 typed key의 같은 kind별 내부 `id`는 유일해야 한다. codec/외부 workbook normalize는 재발급 전에 kind별 모든 원본 ID를 예약하고 공통 source sequence의 첫 `(kind, id)` entry를 유지한다. 후속 중복 entry에는 전체 원본 ID 집합과 이미 발급한 ID를 모두 피해 `{원본 id}__2`, `__3`, ... 형식의 첫 사용 가능한 ID를 결정적으로 발급하며 기존 연결 이미지·바코드 ID metadata는 바꾸지 않는다. 예를 들어 `a, a, a__2`는 `a, a__3, a__2`가 된다.

### 4.6 LabelSheet save format

다음을 한 변경 단위로 반영한다.

1. `_labelSheetSaveFeatureKeys`의 맨 끝에 `sheet.lines`, 그 다음 `sheet.fortuneShapes`를 추가한다. 기존 feature의 version 번호가 바뀌지 않도록 중간에 삽입하지 않는다.
2. `labelSheetSaveFeatureVersions` 자동 version 증가 확인
3. `_supportedSheetKeys`에 `lines`, `fortuneShapes`를 추가하고 기존 raw overlay `shapes`도 호환 key로 허용한다. 단 `shapes`는 typed list sanitizer에 연결하지 않고 전용 raw overlay pass-through로 처리한다. JSON-safe leaf는 `null`, `bool`, `String`, finite `num`만 허용하고 map은 `String` key, list/map descendant는 같은 규칙을 재귀 적용한다. cycle, 비문자열 map key, 비유한 숫자나 그 밖의 객체가 하나라도 있으면 사용자가 확정한 대로 부분 가지치기·문자열 변환 없이 해당 sheet의 legacy `shapes` 값 전체만 제외하고 나머지 sheet/workbook 저장은 계속한다.
4. `_supportedLineKeys` 추가
5. `_supportedShapeKeys` 추가
6. `_sanitizeSheetJson()`에서 `lines`, `fortuneShapes` list sanitizer와 legacy `shapes` raw overlay pass-through 연결
7. `labelSheetMigrateWorkbookSaveJson()`에서 payload에 존재하는 `lines`/`fortuneShapes`는 manifest version/feature 누락과 무관하게 보존하고, payload key 자체가 없는 이전 문서만 codec의 빈 model로 해석
8. `labelSheetNormalizeWorkbookForCurrentSaveFormat()`의 encode→migrate→sanitize→decode 경계에서 lines/fortuneShapes 보존
9. `_currentLabelFileHasContent()`에서 lines/fortuneShapes를 라벨 내용으로 인정해 선·도형만 있는 `.lms`도 export할 수 있게 한다.
10. `_sheetForPrintAreaSave()`는 확장 전 원래 print-area logical `Rect`를 별도로 유지한다. 공용 geometry helper로 line과 fill 없는 shape는 실제 stroked path, fill이 있는 폐쇄 shape는 회전된 fill path 영역과 stroked outline 중 하나가 원래 rect와 교차하거나 경계에 접촉하는 exact typed key를 먼저 확정한다. patterned line과 fill 없는 patterned shape의 최종 exact key 판정에서 실제 stroked path는 raster pixel이나 anti-alias 결과가 아니라 공용 pattern helper가 canonical phase로 생성한 dash segment와 원형 dot의 기하학적 painted footprint다. 원래 rect가 gap만 교차하면 제외하고 mark 외곽에 접촉하면 포함한다. 채움 shape는 outline의 gap만 교차하더라도 회전된 fill 영역이 교차하면 포함한다. 회전 bounds와 연속 stroke envelope/padding은 후보 탐색, viewport/capture 조기 culling과 확정 객체의 row/column 범위 확장에만 보수적으로 사용하며 gap만 viewport에 걸렸다는 이유로 객체를 조기 cull하지 않는다. 최종 line/shape 목록은 확장 bounds로 다시 판정하지 않고 확정 key 집합을 사용한다. 저장 객체의 원래 sheet logical 좌표는 바꾸지 않으며 crop-local origin 변환은 capture 단계에서만 수행한다. 이 painted-mark 판정은 print-area exact key 선별에만 적용하고 §8.1의 전체 centerline hit-test에는 적용하지 않는다.
11. sanitizer가 line과 shape의 필수 geometry, kind, stroke, fill, radius, rotation과 zOrder만 남기는 테스트 추가
12. `.lms` 초기 로드와 라벨 파일에서 불러오기는 `labelSheetDecodeWorkbookSaveBytes()` 내부의 migrate→sanitize→decode만 한 번 사용하고 다시 normalize하지 않는다. `.xlsx` parser는 범용 raw `FortuneWorkbook` 반환 계약을 유지하며 `LabelSheetWorkbench` 적용 경계에서만 `labelSheetNormalizeWorkbookForCurrentSaveFormat()`을 호출한다. `.xlsx` import는 line/shape drawing이나 legacy raw `shapes`를 typed shape로 추론하지 않고 빈 `lines`/`fortuneShapes` model을 가진 현재 포맷 workbook으로 normalize한다.

allow-list는 다음 key로 고정한다.

- line: `id`, `x1`, `y1`, `x2`, `y2`, `strokeStyle`, `strokeWidthMm`, `strokeColor`, `zOrder`
- shape: `id`, `kind`, `left`, `top`, `width`, `height`, `rotationDegrees`, `strokeStyle`, `strokeWidthMm`, `strokeColor`, `fillColor`, `cornerRadiusMm`, `zOrder`

- feature version은 `_labelSheetSaveFeatureKeys`의 index/순서에서 파생되는 기존 방식을 유지한다. `sheet.lines`와 `sheet.fortuneShapes`를 끝에 순서대로 append해 두 개의 연속된 신규 version을 만들고 기존 key의 version은 바꾸지 않는다.
- feature map은 migration 이력/capability 판정에만 사용한다. 이전 version이나 feature 누락만으로 payload의 `lines`/`fortuneShapes`를 지우지 않으며 해당 payload key 자체가 없는 sheet만 decode model에서 빈 list로 해석한다.
- LabelSheet sanitizer는 JSON-safe 구조, supported key/type와 allow-list 필터만 담당한다. geometry fallback, ID trim/중복 재발급, 색상·회전 canonicalization과 raw-list 재사용 판정은 FortuneSheet decode/encode codec이 소유한다. `labelSheetNormalizeWorkbookForCurrentSaveFormat()`은 별도 canonicalizer가 아니라 실제 encode→migrate→sanitize→decode 진입점이다.
- legacy raw `shapes` sanitizer는 성공 시 원래 JSON-safe 구조를 그대로 복사하고 invalid descendant가 있으면 overlay 전체를 omit한다. 일부 map entry/list item만 제거하거나 `null`로 바꾼 결과를 raw 보존으로 취급하지 않는다.
- legacy raw `shapes`는 migration의 일반 deep clone이나 `Map<String, Object?>.from` cast보다 먼저 원본 `Object?` 상태에서 분리해 strict clone한다. strict clone은 `({bool valid, Object? value})`처럼 유효 여부와 `null` 값을 구분하고, map key의 실제 `String` 타입과 finite num을 변환 전에 검사하며 현재 재귀 경로의 object identity set으로 cycle을 판정한다. 성공한 값만 일반 sheet payload에 다시 넣고 실패한 key는 omit하므로, 공용 clone의 key 문자열화·cast 예외·cycle 재귀가 먼저 발생하면 안 된다.
- absent `lines`/`fortuneShapes`와 빈 list는 decode model에서 같은 empty list다. 기존 images wire 규칙과 같이 canonical encoder는 빈 typed list key를 생략하고, raw empty key를 그대로 재사용해야 하는 경우에만 원래 raw key/value를 보존한다. save/import 테스트는 `"lines": []`/`"fortuneShapes": []` key 존재가 아니라 decoded empty model과 반복 encode 안정성을 검증한다.
- codec fallback 또는 canonical normalize가 적용된 entry는 비정상 raw wire를 그대로 재사용하지 않는다. raw list 전체를 재사용하려면 raw entry 수가 canonical model entry 수와 같고 각 entry의 모든 canonical field가 fallback/normalize 없이 유효한 wire여야 한다. 여기에는 필수 field와 ID, geometry의 유한한 JSON number·양수 bounds, zOrder, stroke style, `strokeWidthMm` 범위, `strokeColor`/`fillColor`, shape kind, rotation과 kind별 `cornerRadiusMm`이 포함된다. 중복 ID 재발급, 비숫자/비유한 값 fallback, invalid color/style/range fallback 또는 decoder에서 제외된 entry가 하나라도 있으면 빈 canonical model을 포함해 해당 raw list 전체를 폐기하고 canonical encode한다.
- 저장할 때마다 zOrder를 임의 재정렬하지 않는다. zOrder 연속값 정규화는 사용자가 layer reorder/앞뒤 이동 command를 실행해 실제 front-to-back exact-key 순서가 달라진 transaction 안에서만 수행한다.

기존 `sheet.images`, `image` legacy alias 선택과 `rawImagesKey` 동작은 변경하지 않는다. 단 image/barcode ID 또는 zOrder canonicalization이 필요한 raw images list는 재사용하지 않고 canonical encode하며, images-only 무변경 round-trip은 모든 canonical field가 이미 유효한 raw wire에 한정한다.
일반 workbook XLSX exporter와 line/shape custom XML schema를 새로 만드는 것은 이번 범위가 아니다. `.xlsx` import는 외부 drawing을 line/shape로 추론하지 않으며 이번 완료 조건은 `.lms` round-trip으로 한정한다.

## 5. 공통 객체 참조와 Z-Order

### 5.1 런타임 공통 타입

저장 model과 별도로 다음과 동등한 typed key/view를 둔다.

```text
FortuneSheetObjectKind.image
FortuneSheetObjectKind.barcode
FortuneSheetObjectKind.line
FortuneSheetObjectKind.rectangle
FortuneSheetObjectKind.roundedRectangle
FortuneSheetObjectKind.ellipse

FortuneSheetObjectKey(kind, id)
FortuneSheetObjectRef(key, zOrder, sourceIndex)
```

- image와 barcode는 같은 `FortuneImage` 저장 model을 참조하지만 kind는 metadata로 구분한다.
- line은 `FortuneLine`을 참조한다.
- rectangle/roundedRectangle/ellipse는 같은 `FortuneShape` 저장 model을 참조하지만 kind는 typed key에서 구분한다.
- 선택 상태는 bare `String id`가 아니라 typed key를 사용한다.
- 서로 다른 타입의 같은 문자열 ID가 있어도 선택 충돌이 없어야 한다.
- 공통 resolver와 조회·replace·delete·reorder를 포함한 모든 mutation은 bare ID가 아니라 `FortuneSheetObjectKey(kind, id)`를 받는다. 공유 `images`/`shapes` 배열에서는 저장 model metadata에서 kind를 다시 계산해 key 전체가 일치할 때만 대상을 확정하고, bare-ID map이나 `removeWhere(id == ...)`로 mutation하지 않는다. command transaction 안에서는 검증된 source index를 사용할 수 있지만 commit 전에 같은 exact key인지 다시 확인한다.
- 새 ID는 기존 prefix를 유지하고 직선 `line_*`, 사각형 `rect_*`, 둥근 사각형 `roundRect_*`, 타원 `ellipse_*` prefix를 사용한다.

### 5.2 공통 정렬

공통 paint order는 다음 순서로 안정 정렬한다.

1. `zOrder` 오름차순
2. 같은 zOrder이면 source sequence 오름차순

source sequence는 legacy 호환을 위해 현재 저장 model의 배열 index로 계산한다.

```text
image[i] = i
line[i]  = images.length + i
shape[i] = images.length + lines.length + i
```

배열 내부 순서는 zOrder 변경 때문에 재배열하지 않는다. 공통 accessor와 canonical save는 image/barcode의 `extraFields.zOrder`와 line/shape의 zOrder 모두에서 비숫자·비유한 값을 `0.0`으로 처리하고 최대값 계산은 유한값만 사용한다. 기존 image/barcode raw 재사용 여부도 같은 canonical 판정에 포함한다. 새 객체는 images/lines/shapes 전체의 유한한 최대 zOrder + 1을 받으므로 정상 편집 후 tie에 의존하지 않는다. 객체가 하나도 없거나 유효한 zOrder가 없으면 `1.0`을 사용한다.

레이어 순서 변경 후에는 이미지·바코드·직선·폐쇄 도형을 뒤에서 앞으로 순회해 `1.0, 2.0, ...` 연속 zOrder로 정규화한다. 저장 배열 자체를 Z-Order 목적으로 재배열하지 않고 각 typed model의 원래 배열 소유권을 유지한다.

### 5.3 기존 helper 호환

- 새 `fortuneSheetObjectsInPaintOrder()` 또는 동등 공용 helper가 image/barcode/line/rectangle/roundedRectangle/ellipse를 모두 반환한다.
- 기존 image 전용 호출부가 실제로 image만 필요하면 `fortuneImagesInPaintOrder()`를 유지한다.
- paint, hit-test, layer panel, copy/paste와 출력처럼 모든 객체 순서가 필요한 경로는 새 공통 helper를 사용한다.
- 이미지/바코드 새 삽입과 복제의 `_nextImageZOrder()`는 직선과 shapes까지 보는 `_nextObjectZOrder()`로 교체한다.
- 신규 삽입·복제·copy paste의 내부 ID allocator는 active sheet의 모든 typed key와 같은 command transaction에서 예약한 ID를 함께 확인하고 충돌이 없어질 때까지 발급한다. cut paste의 sheet별 ID 정책은 §13.2를 따른다.
- prefix 기반 신규 allocator는 kind별 기존 ID와 transaction 예약 집합을 함께 보고 `line_1`, `line_2`, ...처럼 가장 작은 사용 가능한 양의 정수 suffix를 선택한다. codec 중복 normalize의 전체 원본 ID 예약과 같은 충돌 회피 helper를 재사용한다.

## 6. 직선·폐쇄 도형 렌더와 출력

### 6.1 공용 geometry/style helper

화면 painter, capture와 출력이 다음 공용 계산을 사용한다.

- logical 시작점/끝점
- 폐쇄 도형의 logical bounds, 회전된 path와 resize handle 위치
- mm 두께의 logical pixel 변환
- style별 dash segment 생성
- 선분 bounds
- rectangle/rounded rectangle/ellipse path와 fill/stroke 순서
- point-to-segment 거리
- 회전 역변환을 적용한 shape 내부/테두리 hit-test
- endpoint handle 위치
- Shift angle snap
- Shift 정사각형/원 bounds 계산

`strokeWidthMm`의 공용 logical 두께는 `wL = strokeWidthMm * fortuneSheetLogicalPixelsPerInch / 25.4`다. 최종 화면 logical 두께는 `wL * effectiveZoom`이다. canvas에 zoom transform을 적용하는 painter는 `Paint.strokeWidth = wL`, geometry를 screen logical 좌표로 미리 변환하는 painter는 `Paint.strokeWidth = wL * effectiveZoom`을 사용하며 두 방식을 결합하지 않는다. zoom 없는 capture logical canvas는 `wL`을 `Paint.strokeWidth`로 사용한다. capture canvas가 `pixelRatio`로 scale되므로 raster 결과는 `wL * pixelRatio`이고, printer raster의 `pixelRatio = DPI / fortuneSheetLogicalPixelsPerInch`이면 `strokeWidthMm * DPI / 25.4` dots가 된다. native printer도 같은 mm→dot 결과를 한 번 계산한 뒤 해당 command의 dot 정수화 정책을 적용한다. zoom과 `pixelRatio`/DPR은 각각 정확히 한 번만 적용하며 canvas 또는 Flutter rasterization이 DPR을 소유하는 screen/capture 경로에서 `Paint.strokeWidth`에 DPR을 다시 곱하지 않는다. dash/gap/dot 크기는 각 경로에서 이렇게 변환된 같은 `w`로 계산한다. crop origin 변환은 위치만 평행 이동하고 두께와 pattern 길이를 바꾸지 않는다.

화면용 선택 강조, endpoint/resize/rotation handle과 hit tolerance는 editor overlay이며 capture와 출력에 포함하지 않는다.

생성·이동·resize·회전 drag 중 geometry는 canonical workbook을 pointer move마다 바꾸지 않고 canvas의 transient gesture draft로 표시한다. draft는 시작 시 workbook identity/history generation과 owner sheet ID를 캡처한다. active sheet 변경, undo/redo 또는 외부 workbook 교체 전에 draft를 폐기하고, pointer up에서도 owner가 현재 workbook/sheet와 모두 일치할 때만 commit한다. 유효한 pointer up은 최종 geometry를 workbook에 한 번 commit하고 `onChange`/`onOp`와 undo snapshot을 각각 1회만 만든다. clean workbook이면 이 첫 commit에서 dirty를 true로 한 번 전환하고, 이미 dirty이면 추가 dirty callback을 만들지 않는다. Escape, pointer cancel, owner 변경 또는 최소 크기 미달은 draft를 폐기하고 workbook notification을 만들지 않는다. 생성 gesture에서 pointer cancel과 최소 크기 미달은 같은 owner의 재시도를 위해 insertion mode를 유지하지만, active sheet 변경·undo/redo·외부 workbook 교체처럼 owner가 무효화되면 draft와 insertion mode를 함께 종료한다. 기존 이미지·바코드 move/resize/rotation도 같은 공용 geometry gesture API로 전환해 동일한 notification 경계를 적용한다.

### 6.2 선 스타일 패턴

패턴은 stroke width를 기준으로 계산한다.

- `solid`: 연속선
- `dashed`: dash `4w`, gap `2w`
- `dotted`: 보이는 지름 `1w`인 원형 dot, 보이는 edge 사이 gap `2w`
- `dashDot`: butt-cap dash `4w`, 보이는 edge 사이 gap `2w`, 보이는 지름 `1w`인 원형 dot, 보이는 edge 사이 gap `2w`

여기서 `w`는 현재 출력 좌표계로 변환된 stroke width다. 원형 dot은 centerline 길이 0의 round-cap mark로 그려 실제 보이는 지름이 `w`가 되게 하며 dotted와 dashDot의 dot에 같은 helper를 사용한다. dash segment는 butt cap을 사용한다. gap은 인접한 dash/dot의 보이는 edge 사이 거리이고, 길이가 패턴보다 짧아도 시작점에서 첫 segment 또는 dot을 그린다.

open line의 pattern offset `0`은 저장된 canonical `x1/y1`에 고정한다. pattern은 canonical logical 좌표의 `wL`을 기준으로 `(x1, y1)`에서 `(x2, y2)` 방향의 전체 centerline에 생성한 것과 같은 phase를 사용하고, geometry/output transform 뒤 viewport/capture/print crop으로 clip한다. crop 교차점이나 crop-local origin에서 pattern을 다시 시작하지 않는다. 구현은 crop 밖의 모든 mark를 실제로 열거할 필요가 없으며 canonical `x1/y1`부터 visible/clip interval 시작점까지의 centerline 거리를 pattern period로 modulo해 첫 visible mark를 구한 뒤 필요한 구간만 생성할 수 있다. `x1/y1`과 `x2/y2`를 교환하면 start/end 방향이 바뀐 것이므로 새 canonical `x1/y1`에서 phase를 시작한다. 화면, 일반 capture, PDF bitmap과 EZPL bitmap fallback은 이 공용 pattern helper와 phase를 사용한다.

### 6.3 폐쇄 도형 path와 채우기

- rectangle은 정규화된 bounds의 직사각형 path를 사용한다.
- roundedRectangle은 bounds와 `cornerRadiusMm`를 변환한 radius로 round-rect path를 만든다. radius는 짧은 변의 절반을 넘지 않는다.
- ellipse는 bounds에 내접하는 타원 path를 사용한다.
- `fillColor != null`이면 fill을 먼저 그리고 stroke를 그린다.
- `fillColor == null`이면 내부를 칠하지 않는다.
- rotation은 bounds center를 기준으로 path 전체에 적용한다.
- stroke pattern은 line과 같은 공용 `FortuneStrokeStyle` segment/path effect를 사용한다.
- closed pattern phase는 회전 전 local path의 고정 시작점에 둔다. rectangle은 왼쪽 위, roundedRectangle은 위쪽 직선의 왼쪽 tangent, ellipse는 위쪽 중앙에서 시계 방향으로 진행한다. 첫 mark의 보이는 시작 edge를 path offset `0`에 두고 rotation은 path와 pattern을 함께 변환하며 phase를 다시 시작하지 않는다. seam 직전에는 첫 mark와의 보이는 edge 기준 gap `2w`를 위한 `[perimeter - 2w, perimeter)` exclusion 구간을 둔다. terminal butt-cap dash가 이 구간에 들어가면 양의 길이가 남는 범위에서 `perimeter - 2w`까지만 자르고, 지름 `1w` 원형 dot 전체가 exclusion 구간 전에 들어가지 않으면 부분 원을 그리지 않고 해당 terminal dot을 생략한다. 잔여 길이는 전체 gap에 재분배하지 않는다.

### 6.4 화면 렌더

- line과 shape는 셀 위 객체 layer에서 image/barcode와 공통 zOrder 순서로 그린다.
- 같은 zOrder tie는 5.2의 source sequence를 사용한다.
- zoom과 devicePixelRatio가 바뀌어도 물리 두께 의미를 유지한다.
- viewport 밖 line/shape는 회전을 반영한 bounds와 stroke padding으로 culling한다.
- capture object inclusion과 print-area 후보 culling은 endpoint 포함 여부가 아니라 연속 stroke envelope를 포함한 실제 line segment/path와 crop rect의 교차를 사용한다. 양 endpoint가 crop 반대편 밖에 있거나 중심선은 밖이지만 stroke가 닿는 line, 회전 전 bounds는 밖이지만 회전 path가 닿는 shape를 제거하지 않는다. print-area의 최종 exact-key 확정만 §4.6에 따라 patterned stroke의 canonical painted mark footprint를 사용해 gap-only 교차를 제외한다.
- 선택 강조는 원본 stroke/fill을 덮지 않고 바깥쪽 highlight로 표시한다.

### 6.5 capture와 PDF

- `captureRangeAsPng()`, screenshot, print capture에 line과 shapes를 포함한다.
- crop/origin 변환 뒤에도 화면과 같은 좌표·스타일·zOrder를 사용한다.
- panel, splitter, 선택 highlight와 endpoint/resize/rotation handle은 포함하지 않는다.
- PDF 경로는 capture bitmap을 쓰는 경우 해당 결과를 그대로 사용한다. 별도 line/shape layout을 중복 작성하지 않는다.

### 6.6 EZPL

- solid이고 수평/수직인 검정 line은 기존 EZPL rectangle/border command로 정확히 표현할 수 있을 때만 native command를 사용할 수 있다.
- 회전 0도, 채우기 없음, solid 검정 stroke인 rectangle은 EZPL `R` command로 화면과 같은 결과가 보장될 때만 native command를 사용할 수 있다.
- 채워진 rectangle, roundedRectangle, ellipse는 bitmap fallback을 사용한다.
- dashed/dotted/dashDot, 임의 각도, 색상 line 또는 native overlay가 공통 zOrder를 깨는 경우 bitmap fallback을 사용한다.
- native 최적화보다 화면/PDF와 같은 clip·zOrder 결과를 우선한다.
- `LabelSheetPrintLayout`에 콘텐츠 하단 경계 `clipBottomMm = metrics.labelHeightMm`을 명시한다. `pageHeightMm = labelHeightMm + extraAreaMm`은 매체 높이와 EZPL `^Q`에만 사용하고 raster/native 후보의 하단 교차·clip에는 사용하지 않는다.
- raster와 native barcode/line/rectangle/cell-border 후보는 모두 `LabelSheetPrintLayout`의 `contentLeftMm`, `contentTopMm`, `clipRightMm`, `clipBottomMm`을 사용하는 하나의 logical→printer-dot transform을 공유한다. `leftPushMm`/`topPushMm`을 margin과 함께 적용하고 교차 bounds와 native command 좌표도 이 최종 printer 좌표계에서 계산한다. right margin과 label-height clip을 native command로 정확히 보장할 수 없는 후보는 bitmap fallback한다.
- app의 resolved `LabelSheetPrintLayout`은 FortuneSheet package-owned immutable `FortunePrintTransform` 또는 동등한 app-neutral DTO를 정확히 한 번 만든다. DTO는 canonical logical source bounds/크기, DPI 또는 mm→dot scale, printer content origin, `clipRightMm`, `clipBottomMm`, orientation과 native 허용 여부를 소유하며 app의 `LabelSheetPrint*` 타입이나 encoder 타입을 참조하지 않는다. `clipBottomMm`은 `labelHeightMm`이고 extra area를 포함하지 않으며 vertical orientation은 native 허용 false다. plan, filtered capture와 app-owned native encoder는 이 동일 DTO 인스턴스를 공유하고 각자 margin/push/clip/회전 transform을 다시 계산하지 않는다.
- 사용자가 확정한 대로 `orientation == vertical`에서는 barcode/line/rectangle/cell-border를 포함한 모든 native 후보를 승인하지 않고 bitmap fallback한다. raster의 기존 90도 회전 결과를 그대로 사용하며 세로 native 회전 좌표식은 이번 범위에 추가하지 않는다.
- Hybrid EZPL output coordinator가 controller와 canonical sheet/range snapshot에서 행·열 metrics 기반 source width/height를 먼저 확정하고, 그 값과 options로 resolved metrics/layout을 만든다. FortuneSheet package는 이 snapshot/transform 안에서 unique한 stable candidate token이 exact object/edge key를 소유하고 공통 paint order·실제 교차 footprint를 함께 가진 app-neutral native 후보를 계산한다. app은 filtered capture 전에 각 후보를 EZPL command 규칙으로 preflight해 정수 parameter와 그 parameter가 만들 최종 painted footprint를 가진 app-owned immutable native descriptor를 만들고, 통과한 descriptor마다 package-owned app-neutral approval record `(candidateToken, predictedPaintedFootprint)`로 projection한다. package 최종 plan API는 app descriptor나 command parameter를 참조하지 않고 candidate 목록의 token→exact key binding과 approval record만 받아 공통 zOrder/fallback 판정을 적용하며 승인 candidate token과 exact key 집합을 가진 immutable render plan을 만든다. unknown 또는 중복 candidate token approval은 해당 token을 미승인 처리해 bitmap에 유지한다. coordinator는 그 plan으로 filtered print capture를 요청하고, plan의 승인 token으로 원래 app descriptor를 필터링해 app-owned encoder에 전달한다. preflight 실패 또는 최종 plan 미승인 후보는 bitmap에 유지되며 filtered capture 뒤에 새 native 실패/fallback 판정을 하지 않는다. plan, descriptor, capture와 encoder는 모두 같은 immutable canonical snapshot과 resolved layout/transform을 공유한다. EZPL 호출부는 coordinator보다 먼저 일반 `captureRangeAsPng()`을 실행하거나 이미 flatten된 전체 PNG를 plan 입력으로 넘기지 않는다. 최종 plan은 승인된 exact `FortuneSheetObjectKey` 집합과 승인된 canonical cell-border edge key 집합을 소유하고, 동일한 plan을 FortuneSheet filtered print capture와 native command 생성에 전달한다. filtered capture는 승인 집합만 공용 painter에서 생략하고 workbook/sheet/revision/undo를 바꾸지 않으며, 승인되지 않은 객체와 border는 bitmap에 유지한다. 이미 flatten된 PNG의 객체 bounds나 paint mask를 흰색으로 지우거나 임시 workbook mutation·전체 border 제외로 plan을 구현하지 않는다. 따라서 native barcode의 bar 사이·quiet zone과 비채움 rectangle 내부에는 아래쪽 raster 객체가 그대로 남는다.
- cell-border edge key는 물리 edge 기준으로 canonicalize한다. vertical edge는 `(row, boundaryColumn)`, horizontal edge는 `(boundaryRow, column)`을 사용해 cell `(row, column)`의 left/right를 각각 vertical `(row, column)`/`(row, column + 1)`, top/bottom을 horizontal `(row, column)`/`(row + 1, column)`로 매핑한다. 따라서 인접 cell의 right/left 또는 bottom/top이 같은 물리 edge를 나타내면 같은 key이며 plan·filtered capture·native command가 모두 이 key를 사용한다.
- cell border는 object zOrder 구성원이 아니라 화면에서 항상 object layer 아래에 있는 cell base layer다. native cell-border command는 이 고정 순서를 보존하거나 상부 객체와 겹치지 않을 때만 사용하고, 그렇지 않으면 border를 capture bitmap에 유지한다.
- 신규 line/shape와 기존 native barcode는 같은 object 합성 순서 판정에 포함한다. fallback bitmap에서 native 영역을 지우거나 raster 뒤에 native command를 추가하면 겹치는 객체의 공통 zOrder가 바뀌는 경우 해당 barcode/line/shape native 최적화를 사용하지 않고 capture bitmap에 남긴다.
- bitmap fallback은 공용 capture의 line/shapes를 다시 별도 overlay하지 않는다.
- selection handle, ID label과 editor highlight는 EZPL에 포함하지 않는다.
- native 후보도 label clip 안의 logical 좌표와 mm 두께를 printer dots로 변환한 값이 모두 유효하고 stroke가 최소 1 dot이어야 한다. 비교 기준인 목표 physical painted footprint는 model bounds나 centerline bounds를 임의로 재해석하지 않고 공용 geometry/painter가 만드는 stroke cap을 포함한 최종 외곽을 동일 transform으로 printer-dot 좌표에 옮긴 값이다. EZPL `R`처럼 좌상단/우하단 painted edge를 표현하는 line/rectangle/cell-border command는 이 최종 signed 비정수 printer-dot edge를 각각 Dart `round()`로 정수화하고, command가 extent를 요구하면 정수화된 반대 edge의 차이로 파생해 source extent를 별도로 반올림하지 않는다. 음수 half를 포함해 Dart `round()` 의미를 그대로 사용한다. preflight는 command 제약, clip과 최소 stroke를 적용한 정수 parameter가 실제로 만들 predicted painted edge와 stroke를 목표 비정수 footprint에 각각 대조하고 정확히 0.5 dot은 허용하되 하나라도 0.5 dot보다 크게 달라지면 bitmap fallback한다. 양쪽 edge가 각각 허용 범위면 파생 extent 오차에 별도의 0.5 dot 제한을 다시 적용하지 않는다.
- barcode처럼 정수 module width, module count, quiet zone과 command 규칙이 bounds를 간접 결정하는 native command에는 edge 차이를 width parameter로 강제하지 않는다. command가 실제 소유하는 parameter를 정수화한 뒤 그 값과 command 규칙으로 결정론적으로 계산한 최종 painted bounds/height를 목표 physical bounds와 edge별로 대조하고 0.5 dot 초과 시 bitmap fallback한다. 목표 bounds에 맞추기 위해 module 또는 quiet-zone 규칙을 변형하지 않는다.

## 7. 통합 도형 툴바와 생성

### 7.1 배치

라벨 시트 전용 툴바의 객체 삽입 영역을 다음 순서로 구성한다.

```text
[가로 정렬] [세로 정렬] [줄 바꿈] [회전] | [도형▼] [이미지] [바코드]
```

`fortuneToolbarShapePopupKey` 또는 동등 command를 `fortuneToolbarImageCommand` 바로 앞에 추가한다. 직선과 폐쇄 도형을 각각 별도 toolbar button으로 늘어놓지 않고 `[도형▼]` 하나로 통합한다. 도형 도구를 셀 `border` popup과 합치지 않는다.

### 7.2 콤보 버튼

- 기존 Fortune toolbar combo icon 폭과 arrow hit area를 재사용한다.
- 본체 클릭은 마지막으로 선택한 geometry kind와 insertion preset으로 생성 모드에 진입한다.
- 화살표 클릭은 geometry kind와 style popup을 연다.
- 아이콘은 현재 preset의 직선/사각형/둥근 사각형/타원 kind를 표시한다. stroke가 너무 두꺼워도 icon layout을 바꾸지 않도록 preview 두께를 clamp한다.
- tooltip은 `도형 삽입: {도형}, {테두리 종류}, {두께} mm` 형식이다.
- toolbar overflow와 More popup에서도 같은 command가 동작해야 한다.

### 7.3 popup

기존 border style submenu의 선 미리보기, inline width editor와 color picker 시각 문법을 재사용한다.

확정 크기:

- 폭 240px
- 도형 선택 행 높이 44px
- 행 높이 28px
- 두께 입력 42px
- 오른쪽 `mm` suffix

popup 배치:

```text
┌─ 도형 ───────────────────┐
│ [직선] [사각형] [둥근 사각형] [타원] │
├──────────────────────────┤
│ 테두리 종류  [실선 ▼]       │
│ 테두리 두께  [0.5] mm        │
│ 테두리 색상  [■]             │
│ 채우기 색상  [없음 ▼]        │  shape만
│ 모서리 반경  [2.0] mm        │  둥근 사각형만
│                    [삽입]     │
└──────────────────────────┘
```

- 첫 행은 4개 icon-only segmented control이며 각 아이콘에 tooltip을 제공한다.
- geometry kind를 선택하면 popup을 유지하고 아래 속성 영역만 해당 kind로 전환한다.
- 테두리 종류 dropdown 순서는 실선, 파선, 점선, 일점쇄선이다.
- 채우기 색상은 rectangle/roundedRectangle/ellipse에서만 표시하며 기본값은 `없음`이다.
- 모서리 반경은 roundedRectangle에서만 표시한다.
- 직선을 선택하면 채우기와 모서리 반경 행을 숨기고 popup 높이를 줄인다.
- 각 geometry kind는 workbench session의 stroke style/width/color preset을 별도로 기억한다. 폐쇄 도형은 fill preset, roundedRectangle은 radius preset도 기억한다.
- workbench session은 현재 `LabelSheetWorkbench`/FortuneSheet controller 인스턴스의 수명이며 preset은 메모리에만 둔다. workbook JSON이나 `SharedPreferences`에 저장하지 않는다.
- 최초 값은 solid, `0.5 mm`, 검정 stroke, 채우기 없음, radius `2.0 mm`다.
- 저장 model에서는 kind/style/width/color/fill/radius를 독립 필드로 저장하며 조합 enum을 만들지 않는다.

- geometry icon 클릭: kind/preset 선택만 변경하고 popup 유지
- `[삽입]` 클릭: focused width/radius editor를 command handler에서 먼저 동기적으로 finalize한다. 유효하면 popup을 닫고 갱신된 kind/preset snapshot으로 생성 모드에 진입하며, 유효하지 않으면 validation과 popup을 열린 상태로 유지하고 삽입을 시작하지 않는다.
- toolbar 본체 클릭: popup을 열지 않고 현재 preset으로 생성 모드 진입
- 테두리 종류/색상/채우기 선택: popup 유지, preset 갱신
- 숫자 입력 클릭: popup 유지, width 또는 radius 편집
- Enter 또는 focus loss: width commit
- Escape: 입력 원복 또는 popup 닫기
- 유효 범위 `0.1~10.0 mm`, 증감 단위 `0.1 mm`
- radius 유효 범위 `0.0~50.0 mm`, 증감 단위 `0.1 mm`
- 잘못된 입력은 preset을 변경하지 않고 기존 inline validation 표시를 사용한다.
- stroke/fill color는 기존 color picker를 재사용한다. fill picker에는 `없음` swatch를 명시적으로 제공한다.

toolbar popup은 삽입 preset만 편집한다. 이미 선택된 객체의 속성 변경은 오른쪽 속성 패널이 담당하며 popup 조작으로 기존 객체를 뜻하지 않게 변경하지 않는다.

### 7.4 생성 interaction

1. popup에서 geometry kind/preset을 정한 뒤 도형 도구 본체를 선택한다.
2. cursor를 crosshair로 바꾼다.
3. grid/object viewport 안 pointer down 위치를 시작점으로 잡는다.
4. drag 중 line은 시작점/끝점, shape는 정규화된 bounds로 preview를 그린다.
5. pointer up에서 최소 생성 크기를 만족하면 현재 kind 객체 한 개를 commit한다.
6. 생성된 객체를 단일 선택하고 도형 생성 모드를 끝낸다.

- line 최소 생성 길이는 화면 기준 3px이다.
- shape는 화면 기준 width와 height가 각각 3px 이상이어야 한다.
- click만 하고 유효 길이가 없으면 객체를 만들지 않는다.
- Escape는 draft와 생성 모드를 취소한다. 사용자가 확정한 대로 오른쪽 클릭은 draft와 생성 모드를 먼저 취소한 뒤 같은 위치의 기존 object/cell hit-test로 context menu를 연다. 다른 toolbar command는 draft와 생성 모드를 취소한 뒤 원래 command를 실행한다. 취소된 pointer sequence의 후속 pointer up은 commit하지 않는다.
- Shift drag는 시작점 기준 가장 가까운 `0°/45°/90°` 계열 각도로 snap한다.
- rectangle/roundedRectangle에서 Shift drag는 정사각형, ellipse에서 Shift drag는 원을 만든다.
- 왼쪽/위쪽 방향 drag도 허용하고 pointer up에서 positive width/height bounds로 정규화한다.
- 삽입 모드의 primary pointer는 grid/object viewport에서 기존 object handle/body와 cell hit-test보다 먼저 처리한다. pointer down 시 기존 object/cell selection은 유지하지만 move/resize/cell selection을 시작하지 않는다.
- 생성 중 auto-scroll은 실제 공용 `_autoScrollOffsetForDrag()` 또는 동등 helper를 재사용한다. 각 pointer move에서 반환된 next scroll offset을 적용하고 그 offset을 `scrollOverride`로 사용해 pointer의 sheet logical 좌표를 다시 계산하여 transient geometry가 scroll delta를 포함하게 한다. 현재 drag 패턴과 같이 pointer move event가 있을 때만 한 step scroll하며 pointer 정지 중 timer 기반 연속 scroll은 이번 범위에 추가하지 않는다.
- 사용자가 확정한 대로 viewport 안에서 시작한 생성 gesture의 pointer up은 viewport 밖이어도 실제 `PointerUpEvent.localPosition`을 마지막 pointer move까지 적용된 현재 scroll offset으로 sheet logical 좌표화해 최종 geometry를 다시 계산한다. pointer up 자체는 auto-scroll step을 추가하지 않는다. 왼쪽 밖 release의 음수 X와 오른쪽·아래쪽 밖 release의 right/bottom 초과는 허용하고, 위쪽 밖 release는 기존 생성 geometry 정책대로 line endpoint 또는 shape top이 `0`보다 작지 않도록 보정한 뒤 최소 크기를 판정한다. Shift line 생성은 `release logical 좌표 계산 → 45도 snap → snap된 ray가 위쪽 경계를 넘으면 같은 방향의 y=0 교점까지 단축 → 최소 길이 판정` 순서를 사용해 endpoint Y만 clamp하여 snap 방향을 깨지 않는다. 마지막 preview 위치를 대신 commit하거나 viewport 경계 clamp·gesture 취소로 바꾸지 않는다.
- pointer up 한 번에 canonical workbook commit과 undo snapshot을 각각 1개 만든다. clean 상태이면 dirty를 true로 한 번 전환하고 이미 dirty이면 추가 dirty callback을 만들지 않는다.
- 생성 모드는 객체 하나를 성공적으로 commit하면 종료하는 one-shot 방식이다. 같은 kind를 다시 만들려면 toolbar 본체 또는 popup `[삽입]`을 다시 실행하며 마지막 preset은 유지한다.
- 최소 크기 미달과 pointer cancel은 현재 draft만 폐기하고 crosshair/insertion mode를 유지해 같은 owner에서 toolbar 재선택 없이 다음 primary drag를 허용한다. active sheet 변경·undo/redo·외부 workbook 교체는 draft와 insertion mode를 함께 종료하고 cursor를 일반 상태로 복원하며, 이전 pointer sequence의 후속 move/up은 no-op이다. 성공 commit, Escape, 오른쪽 클릭과 다른 toolbar command의 기존 종료 규칙은 유지한다.

## 8. 직선·폐쇄 도형 선택과 geometry 편집

### 8.1 hit-test

line hit-test는 point-to-segment 거리로 판정한다.

```text
hitTolerance = max(5 screen px, displayStrokeWidth / 2 + 3 screen px)
```

- zoom과 무관하게 최소 화면 클릭 범위 5px을 보장한다.
- endpoint handle이 line body보다 먼저 hit된다.
- pointer hit-test는 삽입 모드가 아닐 때 `단일 active 객체에 현재 표시된 endpoint/resize/rotation handle → 공통 paint order 역순의 object body → cell/grid` 순서로 판정한다. active 객체 handle은 더 높은 zOrder 객체 body와 겹쳐도 먼저 hit되며, handle을 벗어난 위치의 body끼리는 가장 높은 zOrder부터 판정한다. 다중 선택에서는 개별 handle을 표시하지 않으므로 이 handle 우선 branch도 없다.
- 선택되지 않은 line도 얇은 실제 stroke만으로 클릭을 요구하지 않는다.
- shape hit-test는 회전을 역변환한 local point를 사용한다.
- fill이 있는 rectangle/roundedRectangle/ellipse는 내부를 body hit로 인정한다.
- fill이 없는 shape는 point를 center 기준으로 역회전한 뒤 local rectangle/round-rect/ellipse 경계까지의 절대 거리가 `max(5 screen px, displayStrokeWidth / 2 + 3 screen px)` 이내인지 판정한다. 경계 안쪽과 바깥쪽에 같은 tolerance를 적용하고 내부 전체를 hit로 잡지 않는다. 빈 내부를 클릭하면 뒤쪽 객체 또는 cell selection이 가능해야 한다.
- resize/rotation handle이 shape body보다 먼저 hit된다.

### 8.2 단일 선택 표시

```text
●━━━━━━━━━━━━━━━━●
start              end
```

- 시작점과 끝점에 화면 기준 8x8px handle을 표시한다.
- zoom에 따라 handle 자체 크기를 확대·축소하지 않는다.
- line은 두 점이 방향과 길이를 이미 표현하므로 별도 회전 handle을 두지 않는다.
- bounding rectangle의 8개 resize handle을 line에 적용하지 않는다.

폐쇄 도형 단일 선택은 회전된 bounds에 다음 handle을 표시한다.

- 모서리 4개 resize handle
- 변 중앙 4개 resize handle
- 위쪽 중앙 밖 rotation handle 1개
- handle은 line endpoint와 같이 화면 기준 8x8px이며 zoom에 따라 크기를 바꾸지 않는다.
- rotation handle 중심은 회전 전 bounds의 위쪽 중앙에서 바깥 법선 방향으로 화면 기준 20px 떨어진 점이며, bounds 회전과 함께 center 주위를 회전한다. bounds와 handle 사이에는 선택용 연결선을 표시한다.

### 8.3 본체 이동

line body drag는 두 점에 같은 delta를 적용한다.

```text
x1 += dx, y1 += dy
x2 += dx, y2 += dy
```

- 길이와 각도를 유지한다.
- drag 시작 시 변경 전 `_WorkbookHistorySnapshot` 또는 동등 snapshot을 gesture draft 내부에 로컬로 한 번 캡처하되 undo stack에는 아직 push하지 않는다. owner가 유효하고 geometry가 실제 변경된 pointer up commit 직전에 이 snapshot만 stack에 push하며 cancel·owner 불일치·최소 크기 미달에서는 폐기한다.
- keyboard arrow는 기존 객체 미세 이동 단위를 사용한다.
- Shift+arrow는 기존 객체 큰 이동 단위를 사용한다.
- 기존 이미지 parity에 맞춰 move는 X 음수를 허용하고 전체 geometry의 최소 Y가 `0`보다 작아지지 않게 delta Y만 clamp한다. line은 두 endpoint에 같은 보정 delta를 적용한다.

### 8.4 끝점 이동

- start handle drag는 `x1/y1`만 변경한다.
- end handle drag는 `x2/y2`만 변경한다.
- Shift drag는 반대 endpoint 기준 45도 단위로 snap한다.
- endpoint drag도 최종 Y를 `0` 이상으로 제한한다. Shift snap ray가 상단 경계를 넘으면 snap 방향을 바꾸거나 Y만 따로 clamp하지 않고 같은 45도 방향을 유지한 채 ray 길이를 `y=0` 교점까지 줄인다.
- endpoint가 서로 교차하거나 방향이 뒤집혀도 허용한다.
- drag 완료 결과 길이가 0이면 원래 geometry로 복원한다.
- line 생성의 화면 기준 3px 최소값은 신규 객체에만 적용한다. 생성 후 endpoint drag와 panel start/end commit은 공용 logical-distance validator로 길이 0만 거부·원복하고 0보다 큰 짧은 기존 선은 편집·저장할 수 있게 한다.
- 끝점 drag 전체는 undo 1건이다.

### 8.5 폐쇄 도형 이동·resize·회전

- shape body drag는 left/top에 같은 delta를 적용하고 width/height/rotation을 유지한다.
- shape body move는 음수 X를 허용하고 저장 bounds의 top만 `0` 이상으로 clamp한다. 회전된 시각 bounds는 추가 clamp하지 않으며 canvas drag, keyboard move와 panel X/Y commit이 같은 규칙을 사용한다.
- resize는 반대편 anchor를 고정하고 선택 handle 방향에 맞춰 bounds를 변경한다.
- 회전된 shape resize는 pointer를 drag 시작 시점의 bounds center 기준으로 `-rotationDegrees` 역회전해 local 축에서 계산한다. 반대 local anchor를 회전한 월드 좌표는 drag 전체에서 고정하고, 변경된 local bounds의 center를 다시 회전해 새 `left/top`을 역산한다. edge가 반대 anchor를 넘으면 local bounds와 active handle의 가로/세로 side를 함께 반전한다.
- local resize 후보가 저장 `top < 0`을 만들면 계산된 bounds를 사후 평행 이동하지 않는다. 사용자가 확정한 대로 opposite world anchor 고정을 우선하고, 현재 active local 축·Shift aspect ratio 제약 안에서 `top == 0`이 되는 최대 허용 pointer projection까지 extent를 제한한다. 따라서 상단 경계 이후의 pointer 이동은 크기 증가를 멈추고 anchor와 회전각을 유지한다.
- 모서리 resize에서 Shift를 누르면 현재 aspect ratio를 유지한다. 정사각형/원으로 강제하는 것은 생성 중 Shift에만 적용한다.
- edge가 반대 anchor를 넘어가면 bounds와 active handle 방향을 정규화한다.
- resize 결과의 화면 width/height가 3px 미만이면 pointer up에서 원래 geometry로 복원한다.
- rotation handle drag는 bounds center 기준 angle을 변경한다.
- rotation 중 Shift는 15도 단위로 snap한다.
- roundedRectangle radius는 resize 후에도 mm 값을 유지하되 렌더 effective radius는 짧은 변 절반으로 clamp한다.
- 기존 확정 geometry 정책에 맞춰 shape resize는 `left` 음수를 허용하고 저장 `top`만 `0` 이상으로 clamp하며 right/bottom 초과는 허용한다. 회전된 시각 bounds는 추가 clamp하지 않는다. 기존 image/barcode resize도 같은 X/Y 정책으로 보정해 canvas와 panel parity를 맞춘다.
- move/resize/rotate 각각 pointer drag 전체가 undo 1건이다.

이 문서의 handle, hit tolerance와 최소 생성/resize 크기에 쓰는 모든 "화면 px"는 Flutter logical pixel이다. `logicalExtent * effectiveZoom`으로 판정하고 `devicePixelRatio`는 화면 interaction threshold에 곱하지 않으며 capture raster 해상도에만 적용한다.

### 8.6 선택 규칙

- 일반 클릭: 단일 객체 선택
- 삽입 모드가 아닐 때 Ctrl/Meta+primary pointer가 object body 또는 표시된 handle에 적중하면 해당 pointer sequence 전체를 객체 선택 toggle이 소유한다. 기존 canvas pointer selection parity대로 pointer down에서 exact key toggle을 정확히 한 번 확정하고 controller/listenable에 selection snapshot을 한 번 통지한다. 후속 pointer 이동이 drag threshold를 넘거나 pointer cancel이 도착해도 toggle을 반복·원복하지 않고 body move나 endpoint/resize/rotation draft를 시작하지 않으며 geometry, workbook, undo/redo, dirty, revision과 `onChange`/`onOp` canonical callback을 바꾸지 않는다. 삽입 모드에서는 §7.4의 primary pointer 선점이 modifier보다 먼저여서 Ctrl/Meta가 눌려도 selection을 toggle하지 않고 기존 selection을 유지한 채 insertion sequence를 시작한다.
- Shift 클릭: 레이어 목록의 active anchor 기준 범위 선택은 panel에서만 적용한다.
- 빈 grid 클릭: 객체 선택 해제 후 기존 cell selection 동작
- 다중 선택 상태에서는 개별 endpoint/resize/rotation handle을 표시하지 않는다.
- 이번 범위에서 다중 geometry resize/rotation은 하지 않는다.
- 다중 선택의 삭제·복제·copy/cut/paste와 layer 이동은 지원한다.
- panel 또는 modifier로 만든 다중 selected set의 구성원 body를 canvas에서 modifier 없이 primary down하면 그 exact key 하나로 selection을 축소하고 active로 지정한 뒤 해당 객체만 단일 body move한다. group move는 이번 범위에 추가하지 않으며 pointer 이동 없는 click은 selection만 바꾸고 geometry transaction을 만들지 않는다. Shift 단독 body drag도 canvas 범위 선택이 아니라 같은 단일 선택·move이고, Shift geometry 제약은 endpoint/resize/rotation drag가 시작된 뒤에만 각 기존 snap/aspect 규칙으로 사용한다.
- 기존 `Tab`/`Shift+Tab` 겹친 이미지 순환은 canvas focus에서만 공통 object selection으로 일반화한다. probe는 마지막 pointer 위치가 아니라 active 객체의 geometry 중심을 사용한다. line은 endpoint 중점, image/barcode와 shape는 bounds 중심이며, probe에서 공통 body hit-test되는 객체를 공통 paint order로 순환한다. fill 없는 shape처럼 자기 중심이 body hit가 아니어도 현재 active exact key는 후보에 명시적으로 포함한다. `Tab`은 기존 이미지 순환 방향, `Shift+Tab`은 반대 방향을 유지하고 pointer 위치 변화에 의존하지 않는다. 후보가 둘 미만이면 기존 cell Tab navigation으로 넘긴다. panel list/property editor focus에서는 §13.3의 traversal이 소유하고 object cycle을 실행하지 않는다. 순환은 selection/UI만 바꾸므로 selection이 실제 변경되면 controller/listenable을 한 번 통지하되 workbook/undo/dirty/revision과 `onChange`/`onOp` canonical callback을 만들지 않는다.

## 9. 통합 객체 패널

### 9.1 구조

기존 부유 이미지 레이어 패널을 다음 dock형 객체 패널로 승격한다.

```text
┌─ 객체 ─────────────────┐
│ [삭제][복제][맨앞][앞][뒤][맨뒤] │
│ 바코드  #EAN13          │
│ 이미지  #LOGO           │
│ 타원    ellipse_1       │
│ 둥근 사각형 roundRect_1 │
│ 사각형  rect_1          │
│ 선      line_1          │
├────────────────────────┤
│ 선택 상태별 내용         │
└────────────────────────┘
```

- 상단은 모든 object의 front-to-back 레이어 목록이다.
- 하단은 선택 상태별 속성 또는 레이어 조정 영역이다.
- card 중첩 없이 한 패널 안에서 header/list/divider/content로 구성한다.
- 레이어 목록과 속성 영역은 각각 필요한 경우 독립 scroll한다.
- 목록 행은 object type, 연결 ID 또는 object ID를 표시한다.
- 기존 `_imageLayerPanelOpen` 기반 220px 부유 패널은 넓은 화면에서 중복 표시하지 않고 dock panel 상태로 대체한다. 기존 draw/hit-test 함수는 narrow overlay adapter로 재사용하거나 제거하며 dock panel과 동시에 두 레이어 패널을 만들지 않는다.

### 9.2 목록 순서와 선택 동기화

- 목록은 가장 앞 객체가 위에 오도록 공통 paint order를 reverse해 표시한다.
- canvas 객체 선택은 panel row 선택과 즉시 동기화한다.
- panel row 선택은 canvas selection과 handle을 즉시 갱신한다.
- 단일 선택 active key와 selected key set을 분리한다.
- active sheet 변경 시 객체 선택은 해제한다. `FortuneSheetObjectKey(kind, id)`에 sheet ID를 추가하거나 workbook 전체 ID 유일성을 가정하지 않으므로, 다른 sheet의 같은 kind/id 객체로 선택을 넘기지 않는다.
- 같은 active sheet의 undo/redo와 외부 workbook 교체 뒤 selected key set을 현재 active sheet object key와 교집합으로 정리한다. active key가 더 이상 존재하지 않으면 남은 selected key 중 front-to-back 첫 key를 active로 정하고, 남은 선택이 없으면 null로 둔다.
- object selection 자체는 undo history에 넣지 않는다. workbook 복원 뒤 존재하는 기존 선택만 유지하고 정리된 active/selected snapshot을 controller/listenable로 한 번 통지한다.
- property draft는 생성 시점의 `sheetId`, typed object key와 workbook/object revision을 함께 보관한다. workbook revision은 성공한 canonical workbook mutation, undo/redo 복원과 실제 외부 workbook 교체마다 정확히 한 번 증가하고 selection, panel, splitter와 scroll 변경에서는 유지한다. object revision은 exact typed key의 model 교체·삭제·ID 변경 때 증가한다. package는 별도로 sheet ID별 canonical revision과 workbook 전역의 단조 증가 history-lineage generation을 소유한다. per-sheet revision은 해당 sheet의 cell/object canonical mutation transaction마다 정확히 한 번 증가시키고 다른 sheet 편집·단순 sheet 전환·selection·panel·splitter·scroll 변경에서는 유지한다. undo/redo와 실제 외부 workbook replacement는 canonical before/after가 달라진 sheet revision을 각각 한 번 증가시키고 history-lineage generation도 한 번 증가시켜 전체 cut token을 무효화하므로 sheet revision 값이 우연히 같아도 유효성을 복원하지 않는다. draft commit/focus-loss는 캡처한 sheet/key/revision이 모두 일치할 때만 허용한다. 불일치하면 미commit draft를 폐기하고 현재 typed property snapshot으로 controller를 다시 구성하며, splitter resize처럼 canonical snapshot이 바뀌지 않는 layout 변경에서는 draft를 유지한다.
- revision은 FortuneSheet package가 소유한 command/commit API와 host의 실제 외부 workbook replacement 경계만 추적한다. transaction은 public command/batch 진입 전후의 canonical snapshot 비교가 끝나는 경계이며, 내부 `_replace*` helper별로 증가시키지 않는다. canonical no-op은 증가하지 않고 한 command가 여러 내부 교체 또는 같은 sheet의 cell/object를 함께 바꿔도 해당 sheet revision은 한 번만 증가한다. package가 `onChange`로 방출한 동일 canonical revision/workbook을 부모가 새 인스턴스로 되돌려 주는 controlled-widget echo는 acknowledgment이며 외부 replacement가 아니므로 workbook/per-sheet revision과 history lineage를 바꾸거나 transient/cut 상태를 초기화하지 않는다. 현재 package canonical snapshot과 다른 host 입력만 실제 외부 replacement다. 기존 mutable collection API를 이번 범위에서 breaking change로 바꾸지 않으며 `images`/`lines`/`shapes` collection을 직접 변경하는 것은 지원되는 mutation 경로가 아니다. panel, canvas, dialog와 controller의 object 변경은 모두 package-owned command를 거쳐 revision을 우회하지 않는다.
- 성공한 canonical transaction의 내부 확정 순서는 `canonical model commit → undo/redo stack·workbook/object/per-sheet revision·history lineage 확정 → selection/property draft/transient state 정리 → package read-only state snapshot 확정`으로 고정한다. 실제 `FortuneOp`가 있는 package command와 undo/redo는 그 뒤 `onChange → onOp → controller/listenable 단일 통지` 순서를 사용한다. `onChange` 진입 시 controller getter는 이미 새 revision과 정리된 selection/undo 상태를 반환하고, 기존 호환성을 위해 `onChange`가 항상 `onOp`보다 먼저다. 사용자가 확정한 대로 실제 외부 workbook replacement는 synthetic `FortuneOp`를 만들지 않고 같은 내부 상태 확정 뒤 `onChange → controller/listenable 단일 통지`만 사용하며 `onOp`는 0회다. canonical no-op과 stale async 결과는 어느 callback/listener도 통지하지 않는다.
- Shift 범위 선택, Ctrl/Meta toggle, Ctrl+A, keyboard navigation을 기존 panel 동작과 같게 유지한다.
- 선택된 여러 행의 drag reorder는 선택 묶음의 내부 상대 순서를 유지한다.
- 사용자가 확정한 대로 drag target은 `(target exact key, before|after)`로 캡처하고 행의 위쪽 절반은 `before`, 아래쪽 절반은 `after` drop indicator를 표시한다. target이 selected set 구성원이면 before/after 어느 쪽도 선택 묶음 내부 순서를 바꾸지 않는 no-op indicator로 취급하고 commit하지 않는다. 그 밖에는 선택 묶음을 원래 front-to-back 목록에서 제거한 뒤 target exact key를 다시 찾아 해당 side에 삽입하므로 원본 숫자 index를 그대로 재사용하지 않는다. target이 삭제되거나 owner/revision이 달라지면 reorder를 commit하지 않는다. preview와 pointer-up은 같은 projected exact-key 배열 helper를 사용해 indicator와 commit 결과가 어긋나지 않게 한다.
- 선택 묶음을 제거하고 target exact key의 지정 side에 삽입해 계산한 front-to-back `FortuneSheetObjectKey(kind, id)` 배열을 원래 배열과 비교한다. 배열이 같으면 기존 zOrder의 연속성·중복 여부와 무관하게 값을 정규화하지 않고 workbook/undo/redo/dirty/revision과 `onChange`/`onOp`/controller-listenable을 모두 유지하는 no-op이다. 배열이 실제로 달라진 drop만 유효한 reorder transaction이며 선택 묶음의 내부 상대 순서를 유지한 채 전체 공통 zOrder를 연속값으로 다시 매기고 undo와 canonical callback을 각각 한 번 만든다.

shape 위치/크기/회전 field는 canvas handle과 같은 geometry commit API를 사용한다. 타원과 사각형에는 corner radius field를 표시하지 않는다.

- geometry model의 X/Y, endpoint와 width/height는 항상 logical coordinate로 유지한다.
- panel의 X/Y, endpoint, width/height와 read-only line length는 기존 이미지 dialog와 같이 physical-size가 있는 시트에서는 `mm`, 없으면 `px`로 표시하고 모든 field에 현재 단위 suffix를 표시한다.
- panel commit은 공용 logical pixel↔mm helper로 표시값을 logical coordinate로 변환하며, 단위 전환 때문에 별도 raw geometry metadata를 추가하지 않는다.
- field를 열 때 반올림한 mm/px 초기 표시 문자열을 사용자가 변경하지 않은 채 Enter 또는 focus loss가 발생하면 표시 문자열을 logical coordinate로 역변환하지 않고 원래 canonical geometry를 유지한다. 이 무편집 경로와 역변환 결과가 기존 canonical 값과 같은 경로는 commit·undo·dirty·revision·callback/listenable이 없는 no-op이다.
- 모든 geometry text field는 parse와 단위 변환 뒤 X/Y, line start/end X/Y, width/height, rotation과 corner radius가 모두 finite인지 공용 geometry commit 경계에서 먼저 검증한다. 입력 자체가 유한해도 단위 변환 결과가 비유한 값이면 거부하고, finite 검증을 통과한 값에만 아래의 기존 range·clamp·정규화 정책을 적용한다.

- X/Y field는 move와 같은 정책으로 음수 X를 허용하고 Y만 `0` 이상으로 제한한다. width/height field도 resize와 같이 `left` 음수를 허용하고 `top`만 `0` 이상으로 clamp하며 right/bottom 초과는 허용한다. rotation field는 회전 bounds를 clamp하지 않는다.
- width/height는 양수만 허용하며 현재 zoom에서 3px 미만이 되는 값은 commit하지 않는다.
- rotation 입력은 유한한 degree만 허용하고 commit 시 `0 <= value < 360`으로 정규화한다.
- corner radius 입력은 `0.0~50.0 mm`를 허용하며 저장값은 유지하고 화면 effective radius만 현재 짧은 변 절반으로 clamp한다.

`zOrder` 숫자를 직접 입력하는 field는 두지 않는다. 목록 drag와 layer command만 사용한다.

### 9.6 기존 active object toolbar와 context menu

- 기존 canvas active image toolbar를 active object toolbar로 일반화하고 이미지·바코드·직선·폐쇄 도형 단일 선택에서 삭제·복제·레이어 이동을 동일하게 제공한다.
- `이미지 편집`/`바코드 편집` command는 기존 객체에 대해 별도 dialog를 열지 않고 객체 패널을 열고 해당 속성 영역에 focus한다.
- active object context menu 첫 항목은 타입에 따라 `선 편집`, `사각형 편집`, `둥근 사각형 편집`, `타원 편집`으로 표시하고 객체 패널의 해당 속성 영역에 focus한다.
- 편집 다음에 구분선을 두고 `복제`, `삭제`, 다시 구분선 뒤 `맨 앞으로`, `앞으로`, `뒤로`, `맨 뒤로` 순서로 배치한다.
- secondary click 대상이 현재 selected set에 포함되면 다중 선택을 유지하고 해당 exact typed key만 active로 바꾼다. context menu의 복제·삭제·layer command는 유지된 selected set 전체에 적용한다. 선택 밖 객체를 secondary click하면 그 객체 하나로 선택을 교체한다.
- `allowEdit == false`에서도 같은 secondary click selection 규칙으로 기존 object context menu를 연다. 편집·복제·삭제와 layer command는 기존 순서 그대로 disabled 표시하고 각 command 진입점의 `allowEdit` guard도 유지한다. object copy 항목을 context menu에 새로 추가하지 않으며 읽기 전용 object copy는 기존 Ctrl/Meta+C와 controller command로 허용한다.
- 빈 canvas secondary click은 object selected set과 active key를 유지한 채 기존 cell context menu를 열며 menu command는 cell에만 적용한다. 이후 object keyboard command는 유지된 실제 focus와 active key 규칙을 따른다. 빈 canvas primary click의 기존 object selection 해제 규칙은 바꾸지 않는다.
- 빈 canvas context menu에는 직선/도형 삽입 항목을 새로 추가하지 않는다. 신규 삽입의 단일 진입점은 §7의 `[도형▼]` toolbar이며 기존 cell context menu를 확장하지 않는다.
- 레이어 row double-click 또는 Enter는 단일 선택이면 첫 편집 가능한 속성에 focus한다.
- 다중 선택이면 layer action 영역에 focus한다.

## 10. 이미지·바코드 속성 패널 이전

### 10.1 생성과 편집 분리

- toolbar의 이미지/바코드 삽입은 기존 생성 dialog를 유지한다.
- 이미지·바코드 삽입 command의 enablement와 확인 시 권한 검사는 다른 object mutation과 같이 workbook `allowEdit`만 사용한다. 선택 cell/merge anchor는 생성 위치 계산에만 사용하며 해당 cell의 protection/locked 상태로 삽입을 차단하지 않는다.
- toolbar command 시점의 workbook identity/history generation, active sheet ID와 선택 cell의 merge anchor를 생성 dialog owner로 캡처한다. dialog 조작 중 cell selection이 바뀌어도 삽입 위치를 바꾸지 않으며 active sheet 변경, undo/redo 또는 외부 workbook 교체가 발생하면 미commit dialog를 닫고 입력을 폐기한다. 확인 시 owner가 일치할 때만 캡처한 anchor의 왼쪽 위에 생성한다.
- 생성 dialog의 최초 source는 현행 동작을 유지한다. 구조화 `imageObjectOptions`/`barcodeObjectOptions`가 있으면 `연결 안 함`을 선택한다. option 없는 image host는 새 자동 image ID, option 없는 barcode host는 기존 `barcodeObjectIds`의 첫 effective ID가 있으면 해당 ID, 없으면 기존 자동 barcode ID를 선택한다.
- 이미지 dialog는 기존 연결 이미지/고정 이미지 source 선택을 유지한다. 모든 source는 finite 양수 폭/높이가 필요하다. `imageObjectOptions`가 있으면 연결 source는 non-empty value를 가진 현재 option, `연결 안 함` 고정 source는 성공한 파일 선택이 추가로 필요하다. option이 없는 범용 host는 `imageObjectIds`를 포함한 effective ID 목록에서 dialog가 선택한 non-empty legacy ID를 연결 metadata에 기록하고 목록이 비었을 때만 기존 자동 ID를 발급한다. 파일 없는 모든 연결 source의 `src`는 ID가 legacy/자동인지와 무관하게 기존 1px placeholder를 사용한다. 파일 선택 성공 시 원본 aspect ratio를 유지한 기존 초기 크기를 채우며 file picker 취소는 dialog와 현재 입력을 유지한다.
- 이미지 file picker 호출도 증가하는 picker token과 dialog owner를 캡처한다. 반환 시 `mounted`, dialog open, 최신 picker token, workbook identity/history generation과 owner sheet ID를 다시 확인하고 모두 일치할 때만 파일명·decoded image·크기 draft를 반영한다. dialog 취소, active sheet 변경, undo/redo 또는 외부 workbook 교체 뒤 도착한 picker 성공 결과는 decoded resource를 정리하고 아무 상태도 바꾸지 않는다.
- 바코드 dialog는 유효한 format, finite 폭/높이 `>= 0`, finite `moduleScale > 0`과 `barHeight > 0`이 필요하다. 폭 또는 높이 `0`은 기존 renderer 결과 크기를 사용하는 auto-size 의미로 유지하고 음수·비유한 값과 구분한다. `barcodeObjectOptions`의 연결 source는 non-empty value를 가진 현재 option이어야 한다. effective format은 option의 non-empty `formatId`가 있으면 등록 목록 포함 여부와 무관하게 해당 custom ID를 허용하고, `formatLabel`이 비어 있으면 ID를 label로 사용한다. option format ID가 비어 있으면 dialog의 현재 등록 format을 사용한다. renderer data는 effective format이 QR/Data Matrix 계열이면 `ITEM`, 그 외에는 `123456789012` placeholder를 사용한다. `연결 안 함`과 option이 없는 host는 공백이 아닌 직접 data가 필요하며, option이 없는 host는 `barcodeObjectIds`를 포함한 effective ID 목록의 현재 non-empty legacy ID를 연결 metadata에 기록하고 목록이 비었을 때만 자동 `#BARCODE*` ID를 사용한다.
- 바코드 `[확인]`은 입력 snapshot, 증가하는 request token과 dialog owner를 캡처해 renderer를 한 번만 호출한다. 진행 중에는 모든 입력·확인·닫기·취소와 Escape를 비활성화해 중복 submit과 완료 전 dialog 종료를 막는다. active sheet 변경, undo/redo, 외부 workbook 교체는 pending dialog를 닫고 request token을 무효화한다. renderer 완료 직후 생성 transaction 전에 `mounted`, 최신 request token, dialog open, workbook identity/history generation, owner sheet ID와 `allowEdit`를 다시 확인한다. owner/token/dialog가 달라 이미 취소된 늦은 결과는 아무 상태도 바꾸지 않고 폐기한다. 같은 request/dialog지만 `allowEdit`가 false가 된 경우에는 dialog를 닫고 pending 입력을 폐기한 뒤 결과를 조용히 버려 disabled dialog를 남기지 않는다. renderer가 null을 반환하거나 Future가 예외를 던지면 둘 다 같은 생성 실패로 처리해 dialog와 입력을 유지하고 `바코드를 생성하지 못했습니다.` inline 오류를 표시한 뒤 control을 다시 활성화한다.
- 생성 성공은 새 내부 typed ID와 전체 object 기준 최상단 zOrder를 할당하고 기존 다중 선택을 해제해 새 typed key만 active 단일 선택으로 만드는 하나의 command다. 구조화된 연결 option은 검증된 option value, option 없는 host는 dialog의 selected effective legacy/자동 ID를 연결 metadata에 기록하고 `연결 안 함` source만 연결 metadata를 기록하지 않는다. 최종 객체의 rotation을 적용한 visual paint bounds가 viewport 안에 전부 보이지 않으면 zoom을 바꾸지 않고 bounds를 포함하는 최소 거리만 scroll한다. selection highlight, handle과 바코드 ID label overlay는 reveal bounds에서 제외하며, visual bounds가 viewport보다 큰 축은 회전된 bounds의 left/top edge를 viewport의 해당 축 시작에 맞춰 최대 영역을 보인다. undo, `onChange`, `onOp`는 각각 1건이고 clean workbook의 dirty 전환은 1회다.
- 생성 후 dock/overlay panel을 강제로 열지 않는다. panel이 이미 열려 있으면 새 객체 속성으로 전환하고, 닫혀 있으면 `userWantsDockOpen`과 좁은 화면의 overlay closed 상태를 유지한다. 새 active 객체의 toolbar/context menu로 후속 편집에 진입하며, 좁은 화면의 상시 객체/레이어 icon과 넓은 화면의 panel 상태와 무관하게 표시되는 기존 객체/레이어 toolbar toggle로 panel을 다시 열 수 있어야 한다.
- dialog 취소와 이미지 file picker 취소, validation 실패 및 barcode renderer 실패는 workbook, selection, panel open 상태, undo, dirty, `onChange`, `onOp`를 바꾸지 않는다.
- 기존 객체의 일반 편집은 panel로 이전한다.
- 이미지 파일 교체는 panel의 파일 선택 button을 사용한다.
- panel 이미지 파일 교체도 호출 시 `sheetId`, image exact typed key, workbook identity/history generation, per-sheet/object revision과 증가하는 picker token을 캡처한다. picker 대기 중 selection 변경은 허용하되 성공 결과는 원래 exact key에만 귀속한다. 반환 직전 owner/revision/token과 `allowEdit`를 다시 확인하고 원 객체 삭제·교체·ID 변경, undo/redo·외부 workbook 교체 또는 더 최신 picker 호출 뒤의 결과는 decoded resource를 정리하고 workbook/draft/selection을 바꾸지 않는다. 현재 active image로 대상을 바꾸거나 같은 ID의 새 객체에 적용하지 않는다.
- 이미지 crop처럼 별도 canvas가 필요한 기능은 panel button에서 기존 전용 dialog를 열 수 있다.

### 10.2 중복 구현 금지

기존 dialog와 새 panel이 다음 로직을 각각 구현하지 않는다.

- object connection ID validation
- width/height/rotation parsing
- aspect ratio 계산
- barcode format 선택과 renderer request 생성
- barcode body metadata 계산
- image/barcode replacement commit
- 생성 dialog owner 검증, anchor logical 위치 계산과 생성 성공 selection/reveal transaction
- image picker와 barcode renderer의 request token/owner 검증
- barcode 생성과 기존 객체 panel 적용이 공유하는 render request coordinator

이 로직을 FortuneSheet package 내부의 공용 draft/validation/commit API로 추출하고 생성 dialog와 panel이 같은 API를 사용한다.

### 10.3 commit 규칙

- 숫자 field: Enter 또는 focus loss에서 validation 후 commit
- 숫자 field의 초기 표시 문자열과 사용자 편집 여부를 draft가 보존한다. 반올림된 초기 문자열을 수정하지 않은 Enter/focus loss는 validation용 역변환이나 canonical write를 하지 않는 no-op이며, 사용자가 실제 변경한 문자열만 parse·단위 변환·finite 검증 뒤 commit한다.
- 일반 Tab·다른 field 클릭·canvas 클릭에 따른 focus loss에서 변경 문자열이 invalid이면 workbook을 바꾸거나 focus를 강제로 되찾지 않고 해당 exact key draft의 입력 문자열과 inline 오류를 유지한다. 명시적 command가 요청된 경우에만 아래 동기 finalize 규칙에 따라 invalid draft를 원복·폐기한 뒤 command를 계속한다.
- spinner/drag: 조작 중 preview, 종료 시 undo 1건
- style/color/select field: 선택 시 즉시 commit, undo 1건
- position/size/rotation/radius text field: Enter 또는 focus loss의 유효한 commit 1회당 undo 1건
- barcode text/format과 렌더 결과를 바꾸는 묶음: panel의 `[적용]`에서 한 번 render/commit
- barcode panel `[적용]`은 생성 dialog와 같은 render request coordinator를 사용한다. 요청 시 `sheetId`, exact typed key, workbook/object revision과 request token을 캡처하고 renderer 완료 직전 모두 일치할 때만 원래 exact key에 commit한다. pending 중 selection 변경은 요청을 취소하지 않지만 객체 삭제·교체·ID 변경, undo/redo와 외부 workbook 교체는 token/revision 불일치로 늦은 결과를 폐기한다. null/예외 실패는 workbook을 바꾸지 않고 해당 object draft의 inline 오류로 복구하며 성공 commit은 render/replace, undo, `onChange`, `onOp` 각각 1건이다.
- barcode panel `[적용]` pending 중에는 같은 exact key와 다른 key 모두 새 `[적용]`을 시작할 수 없다. UI submit과 public/controller render command를 함께 차단하고 현재 request token 하나만 pending을 소유하며, 완료 뒤 사용자가 다시 실행한 요청만 새 token으로 시작한다.
- barcode pending request/draft/inline error는 `(sheetId, exact barcode key)`에 귀속하고 controller의 `activePropertyDraft`는 현재 active selection key에 대한 projection으로만 노출한다. 사용자가 확정한 대로 A가 pending인 동안 object selection, read-only property 조회와 copy만 허용한다. delete/duplicate/cut/paste, layer reorder·앞뒤 이동, canvas·keyboard·panel geometry 변경, 모든 property commit·새 property draft와 그 밖의 canonical workbook mutation은 UI enablement와 public/controller command 진입점 양쪽에서 차단한다. 차단된 command는 queue하거나 pending 종료 뒤 자동 재실행하지 않으며 workbook, selection, internal/system clipboard payload·marker, undo/redo, dirty, revision과 `onChange`/`onOp`/controller-listenable을 바꾸지 않는다. copy는 canonical workbook을 바꾸지 않으므로 기존 latest-wins clipboard write coordinator로 실행할 수 있다. A 상태를 B form에 표시하거나 B draft로 대체하지 않고, A가 현재 selection이 아니면 A의 inline error를 panel에 표시하지 않는다. pending 실패 뒤 A를 다시 선택하면 key에 보존된 error/draft를 표시하며 성공 또는 명시적 draft 폐기 시 해당 key 상태를 제거한다.
- 잘못된 중간 입력: workbook 변경 없음
- panel의 일반 selection 변경·삭제·복제·layer 이동 등 다른 command handler는 focus callback에 의존하지 않고 active field를 먼저 동기적으로 finalize한다. 유효 draft는 canonical commit을 완료한 뒤 요청 command를 실행하고, 사용자가 확정한 대로 invalid draft는 원복·폐기한 뒤 workbook 변경 없이 해당 draft만 버리고 요청 command는 계속 실행한다. 일반 object selection 변경도 이 순서에 따라 old exact key의 valid draft commit 또는 invalid draft 폐기를 끝낸 뒤 새 selection과 active key를 적용한다. valid draft commit은 독립 canonical transaction의 `onChange`→`onOp`→controller/listenable 1회 뒤 selection-only controller/listenable 1회를 추가해 listener 총 2회이고, invalid/no-draft에서 실제 selection만 바뀌면 canonical callback 없이 controller/listenable 1회다. 단 barcode panel renderer pending guard는 draft finalize보다 먼저 실행하며, 이 pending 중 허용된 selection 변경만 원래 `(sheetId, exact typed key)`의 draft/request/inline error를 commit·폐기하지 않고 selection UI와 controller/listenable을 1회 바꾸는 예외다. 허용된 copy는 draft를 finalize하지 않고 현재 canonical selected object snapshot으로 기존 latest-wins clipboard write를 실행한다. 그 밖의 차단 command는 유효·invalid draft 모두 commit·폐기·원복하지 않는 완전한 no-op이다.
- `.lms` save/export, print/PDF/capture, undo/redo, active sheet 전환, label/XLSX/image import와 이미지·바코드·도형 삽입 toolbar command도 canonical workbook을 읽거나 교체하기 전에 같은 동기 finalize API를 호출한다. 유효 draft는 commit된 최신 workbook snapshot으로 요청 command를 계속하고 invalid draft는 원복·폐기한 뒤 기존 canonical snapshot으로 command를 계속한다. focus-loss callback 순서에 의존하지 않는다.
- 동기 finalize가 valid/invalid draft를 commit 또는 폐기하면 해당 draft identity의 callback 자격도 함께 종료한다. 그 뒤 같은 draft에서 지연 도착한 Enter·focus-loss callback은 draft나 inline 오류를 다시 만들지 않고 workbook/undo/dirty/revision과 callback/listenable을 모두 유지하는 no-op이다. 이를 위해 별도 전역 generation을 추가할 필요는 없으며 기존 owner exact key·revision·request/draft token 중 현재 구조에 맞는 identity를 사용한다.
- 사용자가 확정한 대로 barcode panel `[적용]` renderer가 pending이면 save/export/print/capture, undo/redo, sheet 전환, import와 모든 삽입 command 및 property draft를 취소하는 Escape branch를 완료까지 비활성화한다. pending command를 queue하거나 자동 재실행하지 않으며 render 성공·실패·stale 폐기로 pending이 끝난 뒤 사용자가 다시 실행한다. selection 변경은 허용하고 request·draft·inline 오류 상태는 원래 exact typed key에 귀속한다. 일반 동기 property draft는 이 비활성화 대상이 아니다.
- object selection 변경: 위 finalize 뒤 유효한 committed 값만 유지하고 invalid draft는 폐기
- 이미지 파일 선택 취소: 기존 image 유지

## 11. 시트/패널 splitter와 반응형 동작

### 11.1 dock layout

`LabelSheetWorkbench`의 편집 화면을 다음 Row로 구성한다.

```text
Expanded(FortuneSheet) | VerticalPaneSplitter | SizedBox(ObjectPanel)
```

확정값:

- splitter width: 8px
- panel 기본 폭: 300px
- panel 최소 폭: 260px
- panel 최대 폭: 420px
- sheet 최소 폭: 480px
- dock 최소 전체 폭: 760px

panel이 오른쪽에 있으므로 drag 계산은 다음과 같다.

```text
nextPanelWidth = currentPanelWidth - delta.dx
```

`nextPanelWidth`는 현재 workbench의 실제 local constraint로 clamp한다. 공용라벨관리 바깥 splitter가 있더라도 전체 window 폭이 아니라 workbench에 배정된 폭을 사용한다.

### 11.2 좁은 화면

- local width가 760px 미만이면 dock panel을 자동 접는다.
- 접힌 상태에서는 object 선택 여부와 무관하게 항상 보이는 32px 이하의 객체/레이어 icon button으로 overlay panel을 열 수 있다. 기존 active-image toolbar의 toggle command도 같은 open command를 호출한다.
- 사용자가 확정한 대로 narrow overlay가 열린 동안 active object toolbar는 paint와 hit-test에서 모두 숨긴다. overlay rect 안의 pointer/scroll은 overlay가 소유하고 canvas object/cell hit-test로 전달하지 않는다. overlay가 닫히면 active object toolbar를 다시 표시하며, dock mode에서는 legacy floating layer panel의 paint와 hit-test를 모두 비활성화해 panel chrome을 중복 생성하지 않는다.
- overlay panel은 시트를 영구 축소하지 않고 현재 220px보다 넓은 최대 300px 범위에서 viewport 안에 맞춘다.
- `userWantsDockOpen`, 현재 local width로 dock 가능한지 나타내는 `dockEligible`, 좁은 화면의 `overlayOpen` 상태를 분리한다. 자동 접기가 사용자의 open/closed 의도를 덮어쓰지 않는다.
- panel controller, active property draft, selection과 field controller는 dock/overlay presentation widget보다 상위에서 소유해 760px 경계 전환으로 dispose·재생성하지 않는다. 사용자가 확정한 대로 wide→narrow에서 overlay open command를 발생시키거나 focus를 옮기지 않고, narrow→wide에서도 dock open command/callback을 발생시키거나 field focus를 이전하지 않는다. 경계 전환 자체는 draft를 finalize·commit·폐기하거나 `userWantsDockOpen`/`overlayOpen`을 변경하지 않으며 실제 FocusNode 소유권을 유지한다. 단 narrow 진입 전 보존된 `userWantsDockOpen == true`이면 wide layout 복귀 시 dock이 다시 표시되고 false이면 숨김을 유지하는 것은 새 open command가 아니라 기존 사용자 의도의 presentation 복원이다.
- 다시 760px 이상이 되면 마지막 dock panel 폭을 복원하되 dock 표시 여부는 `userWantsDockOpen`을 유지한다. 사용자가 넓은 화면에서 닫은 panel을 width 왕복만으로 다시 열지 않는다.
- 좁은 화면에서 속성 form이 화면 밖으로 나가지 않도록 panel 내부를 scroll한다.

### 11.3 panel open/close와 폭 저장

- 넓은 화면의 최초 기본 상태는 open이다.
- header에 접기 icon을 제공한다.
- 기존 객체/레이어 toolbar toggle은 dock open/closed와 무관하게 표시하고, 닫힌 dock에서 실행하면 `userWantsDockOpen = true`로 바꾸면서 마지막 폭으로 다시 연다.
- 접기와 다시 열기는 마지막 폭을 보존한다.
- splitter double-click은 기본 300px로 복원한다.
- panel 폭은 `SharedPreferences`의 LabelSheet UI 전용 key에 저장하고 다음 workbench에서 복원한다. 저장값도 현재 local constraint로 다시 clamp하며 workbook save JSON에 넣지 않는다.
- panel open/closed 상태는 현재 workbench session에서만 유지하고 라벨 파일에 저장하지 않는다.
- narrow overlay open/closed는 dock 사용자 의도와 별개이며 overlay를 닫아도 `userWantsDockOpen`을 바꾸지 않는다.

### 11.4 resize 안정성

splitter drag가 다음 상태를 초기화하면 안 된다.

- workbook
- active sheet
- cell selection
- selected object keys
- zoom
- sheet scroll
- undo/redo stack
- panel property draft

FortuneSheet child key를 panel width에 연결하지 않는다. 부모 constraint만 바꾸고 기존 state를 유지한다.

- drag 시작 시 열린 toolbar popup과 object tooltip을 닫는다.
- drag 중 grid viewport와 scrollbar를 현재 width로 layout한다.
- `onGridRectChanged`는 post-frame에 새 global rect를 통지한다.
- panel resize는 dirty와 undo를 만들지 않는다.

## 12. controller와 package API

### 12.1 상태 노출

FortuneSheet package가 다음과 동등한 read-only 상태를 controller/listenable로 노출한다.

- 현재 active object key
- selected object key set
- front-to-back object refs
- 선택된 단일 object의 typed property snapshot
- panel command enablement
- barcode property render pending 중 selection·조회·copy만 true이고 canonical mutation command는 false인 enablement
- geometry kind별 insertion preset과 도형 insertion mode
- active object property draft 유무와 barcode property render pending 여부
- sheet ID별 package-owned canonical revision과 workbook 전역 history-lineage generation

`FortuneSheetController`는 동시에 하나의 mounted `FortuneSheet` canvas에만 attach되는 exclusive owner다. 이미 다른 mounted canvas에 attach된 controller의 두 번째 attach는 이전 owner를 조용히 덮어쓰거나 자동 이전하지 않고 즉시 명시적 `StateError`로 거부한다. canvas의 controller 교체는 new controller의 attach 가능 여부를 동기적으로 먼저 검증하고, 불가능하면 old controller와 양쪽 기존 owner를 그대로 유지한 채 `StateError`를 던진다. 가능할 때만 old detach가 완료된 뒤 new attach하며 canvas state는 widget 설정값과 별도로 실제 attach에 성공한 controller를 추적해 dispose와 후속 교체에 사용한다. detach 뒤 재attach하는 rollback은 사용하지 않고 old canvas의 뒤늦은 detach가 새 owner를 해제하지 않는다.

controller는 host가 package 내부 state를 직접 읽지 않도록 immutable read-only `snapshot`과 안정적인 public `Listenable` 진입점을 제공한다. controller 자체가 `ChangeNotifier`인지 별도 notifier에 위임하는지는 구현 세부사항이다. detached snapshot은 `isAttached == false`, active key·단일 property snapshot·property draft는 `null`, selected key set·object refs는 empty, command enablement·barcode pending은 `false`를 반환해 stale live state를 노출하지 않는다. dispose되지 않은 detached controller는 다른 canvas에 다시 attach할 수 있다. host가 controller의 listener 등록/해제와 최종 dispose를 소유하고 canvas는 attach/detach만 수행하며 controller를 dispose하지 않는다. 정상 attach/detach는 각각 확정된 snapshot을 listener에 한 번 통지하며 canonical `onChange`/`onOp`는 발생시키지 않는다.

`LabelSheetWorkbench`가 private canvas state를 직접 읽거나 package 내부 field에 의존하지 않는다.

### 12.2 command API

다음과 동등한 command를 public controller 또는 package-owned panel controller로 제공한다.

- select/toggle/range/selectAll object
- delete/duplicate/copy/cut/paste selected objects
- bringToFront/bringForward/sendBackward/sendToBack
- reorder selected object block
- update selected image properties
- update selected barcode properties
- update selected line properties
- update selected shape properties
- begin/cancel shape insertion
- focus selected object property editor
- `finalizeActiveObjectPropertyDraft()` 또는 동등한 동기 command. no draft/valid commit/invalid discard를 처리하며 async render pending은 별도 enablement 상태로 노출한다.
- FortuneSheet package는 canonical sheet/range/layout snapshot에서 exact key를 내부 binding으로 소유하는 unique stable candidate token의 app-neutral native 후보를 만드는 API, app descriptor를 package-owned `(candidateToken, predictedPaintedFootprint)` approval record로 projection한 목록을 받아 immutable Hybrid 최종 plan을 만드는 API와, 그 plan을 받아 승인된 key만 생략하는 filtered print capture API를 소유한다. package API는 app descriptor/command parameter를 참조하지 않고 일반 `captureRangeAsPng()`의 화면/PDF 동작을 바꾸거나 workbook을 mutation하지 않으며 app의 `LabelSheetPrint*` 타입이나 EZPL encoder를 import하지 않는다.
- app의 `LabelSheetWorkbench`/output controller가 package 후보 생성→app-owned EZPL preflight descriptor 확정→package 최종 plan→같은 plan의 filtered capture→승인 descriptor native command encode 순서를 조정한다. 기존 PDF/preview capture entry point와 분리하고 package 의존 방향을 역전시키지 않는다.
- app-facing `LabelSheetOutputCaptureController.captureHybridEzpl(...)` 또는 동등 API. 입력은 source 크기가 아직 없을 수 있는 `LabelSheetPrintPageMetrics`, `LabelSheetPrintOptions`와 `lineSpacingPercent`를 포함한다. unit이 active인 동안 property draft finalize→canonical sheet/range snapshot→range의 행·열 metrics로 source width/height와 resolved metrics/layout 확정→native 후보/preflight descriptor→최종 plan→filtered capture→승인 descriptor native command를 한 번에 수행하고 EZPL bytes, 오류 검사에 사용할 동일 immutable canonical sheet/range snapshot과 그 resolved metrics/page spec을 반환한다. private `FortuneSheetController`를 app host에 노출하지 않는다.

다중 라벨 발행은 backend를 확정한 뒤 unit별 active 상태에서 PDF backend만 기존 `capture()` 결과를 저장하고, EZPL backend는 `captureHybridEzpl()` 결과를 즉시 저장한다. EZPL unit을 일반 PNG로 먼저 capture하거나 모든 unit 렌더가 끝난 뒤 마지막 live controller와 과거 snapshot을 조합하지 않는다. item-code 오류 검사는 각 반환 결과의 canonical sheet snapshot에서 기존과 동일하게 수행하고, grouping 단계는 이미 생성된 unit별 PDF page 또는 EZPL bytes를 인접 group payload에 연결만 한다.

UI widget이 workbook list를 직접 수정하지 않고 controller command가 undo, dirty, selection과 zOrder를 한 경계에서 처리한다.

### 12.3 object mutation 권한

- `canEditObjects == workbook.settings.allowEdit`를 package 공용 상태/guard로 사용한다.
- `allowEdit`가 true에서 false로 바뀌는 settings-only host update는 canonical workbook replacement가 아니라 permission/presentation update이며 barcode renderer pending과 그 Escape 차단보다 우선하는 package 시스템 정리 경계다. 새 settings의 `allowEdit == false`는 수용하되 canonical sheet/object/cell content, workbook identity, undo/redo, dirty, workbook/object/per-sheet revision과 history-lineage generation을 유지하고 `onChange`/`onOp`를 호출하지 않는다. 일반 property draft와 inline error를 canonical commit 없이 폐기하고 해당 draft의 Enter/focus-loss callback identity를 종료한다. pending cut, paste, image picker와 barcode renderer 등 mutation async token·owner 자격을 무효화하되 read-only에서도 허용되는 pending copy marker write는 기존 latest-wins coordinator에서 계속 완료한다. 생성·편집 dialog와 style/color/insertion popup을 즉시 닫고 표준 close focus 복원 규칙을 적용하며, 늦은 mutation callback/async 성공·실패는 resource만 정리하는 완전한 no-op이다. 이미 열린 object context menu는 닫지 않고 기존 mutation 항목을 즉시 disabled 상태로 재구성하며 stale enabled action도 command guard에서 차단한다. object selection, active key와 panel open 상태는 유지하고 panel은 canonical property만 표시하는 read-only 상태로 전환한다. 정리가 끝난 최종 read-only snapshot을 controller/listenable로 정확히 1회 통지한다. 이후 `allowEdit`가 true로 돌아와도 폐기한 draft/error, dialog/popup 또는 mutation async request를 복원하지 않는다.
- 생성, property commit, move/resize/rotation, delete, duplicate, cut/paste, layer reorder와 앞/뒤 이동을 포함한 모든 mutation entry point가 같은 guard를 통과한다.
- object selection, panel open/close와 copy clipboard payload 생성처럼 workbook을 바꾸지 않는 동작은 `allowEdit == false`에서도 허용한다. cut과 paste는 workbook을 바꾸므로 비활성화한다.
- object copy는 system/internal clipboard와 UI selection state만 갱신하며 selection range metadata를 포함한 `FortuneWorkbook`/`FortuneSheet`를 교체하지 않는다.
- 현재 cell selection의 `_canEditRange()`를 object command 권한에 사용하지 않는다. 읽기 전용 cell을 선택했는지에 따라 같은 객체 command enablement가 바뀌면 안 된다.

### 12.4 panel widget 소유권

- typed object model, selection state, property validation과 command는 FortuneSheet package가 소유한다.
- 공용 object panel widget도 가능한 한 FortuneSheet package에 두어 다른 FortuneSheet host에서 재사용할 수 있게 한다.
- app의 `LabelSheetWorkbench`는 dock/overlay 배치, splitter, responsive threshold와 UI preference만 소유한다.
- 이미지 import file picker와 Label Manager object option 입력은 기존 callback/API를 통해 package panel에 주입한다.

## 13. undo, dirty, clipboard와 focus

### 13.1 undo/dirty 단위

다음은 workbook change 1건이다.

- line 생성 1개
- line 본체 drag 1회
- endpoint drag 1회
- shape 생성 1개
- shape 본체 drag 1회
- shape resize 1회
- shape rotation 1회
- property field commit 1회
- 다중 layer command 1회
- 선택 묶음 reorder drag 1회
- 다중 cut 1회
- 다중 delete/duplicate/paste 1회

pointer move나 text input의 각 key마다 undo snapshot을 만들지 않는다.

다음은 workbook change가 아니다.

- 선택 변경
- panel open/close
- panel width 변경
- panel/list scroll
- property field focus
- toolbar popup open/close

### 13.2 clipboard

- image/barcode-only 기존 clipboard 동작을 유지한다.
- line/shape-only와 mixed selection을 내부 clipboard payload로 지원한다.
- payload는 source sheet ID, cut transaction/revision token, typed object kind와 각 model JSON을 구분한다.
- 내부 object payload는 호출 시점 package-owned canonical typed object snapshot을 deep clone해 소유한다. 직렬화가 필요한 경우에만 payload version과 kind를 가진 package typed-object codec을 사용하고, LabelSheet save sanitizer·sheet raw-list wire·raw metadata 재사용 결과를 payload codec으로 사용하지 않는다. save sanitizer는 실제 LabelSheet 저장 경계에서만 적용하며 system clipboard에는 payload 본문이 아니라 아래 opaque ownership marker만 기록한다.
- object copy/cut은 payload version이 포함된 opaque clipboard marker를 `Clipboard.kTextPlain`에 기록한다. paste 직전에 현재 system clipboard text가 payload와 함께 저장한 marker와 정확히 일치할 때만 내부 object payload를 사용한다. 다르면 object paste는 workbook·selection·payload를 바꾸지 않고 no-op한 뒤 기존 cell/text paste 경로에 제어를 넘긴다. 이 marker는 clipboard 소유권 판정 전용이며 아래 구조화 연결 ID 판정 금지 marker와 무관하다.
- Ctrl/Meta+V는 system clipboard를 정확히 한 번 읽는 async paste coordinator가 소유한다. marker가 일치하면 object paste만 실행하고, 불일치하면 같은 clipboard data를 기존 cell/text paste API에 전달해 정확히 한 번 실행한다. key event를 먼저 소비한 뒤 별도 handler로 되돌려 보내거나 object/cell paste를 동시에 시작하지 않는다.
- paste key event를 소비할 때 target workbook identity/history generation, active sheet ID와 기존 cell/text fallback에 필요한 selection snapshot을 캡처한다. 사용자가 확정한 대로 clipboard read 완료 뒤 target owner 또는 selection이 달라졌으면 object paste와 fallback cell/text paste를 모두 실행하지 않는다. marker 판정과 선택된 한 paste 경로는 캡처한 target snapshot이 여전히 현재 값과 일치할 때만 이를 사용하며 완료 시점의 새 active sheet/selection을 추종하지 않는다.
- object copy는 clipboard marker 기록이 성공한 뒤 내부 payload를 활성화한다. object cut은 호출 시 source workbook identity/history generation, sheet ID, per-sheet revision, exact typed key 집합과 각 canonical source model을 캡처하고 marker 기록 성공을 기다린다. 성공 후 삭제 직전에 같은 owner/revision, 모든 exact key가 같은 canonical model을 가리키는지와 `allowEdit`를 다시 확인한 경우에만 source 삭제, undo/dirty/change transaction과 내부 payload 활성화를 수행한다. 대기 중 selection/panel 상태만 바뀌고 source model이 같으면 계속하며, source mutation·삭제·교체·ID 변경, undo/redo·외부 workbook 교체 또는 권한 변경이면 marker가 기록됐더라도 삭제와 내부 payload 활성화 없이 종료한다. clipboard 기록 실패·예외에서도 workbook, selection, 내부 payload, undo, dirty와 callback을 바꾸지 않는다.
- object copy/cut marker write는 호출 순서 기준 latest-wins인 하나의 coordinator가 소유한다. 새 copy/cut이 시작되면 이전 pending 요청은 stale이고, 성공 여부와 무관하게 호출 순서상 최신 요청만 commit 자격을 가진다. 이전 요청의 늦은 성공·실패는 source 삭제, selection, 내부 payload, undo/dirty/revision과 callback/listenable을 바꾸지 않는다. 최신 요청이 성공하면 모든 pending write가 정리된 최종 system clipboard marker와 활성 내부 payload는 그 최신 요청 하나에 대응해야 하며, stale OS write가 나중에 완료돼 marker만 과거 요청으로 되돌아가지 않도록 write 직렬화 또는 최신 marker 재확정까지 coordinator가 책임진다. 사용자가 확정한 대로 최신 요청이 실패하면 이전 stale 요청을 다시 활성화하거나 그 cut source를 삭제하지 않고 요청 시작 전의 안정된 활성 payload와 대응 system marker 쌍을 OS clipboard까지 복원하며 workbook도 유지한다.
- copy paste는 새 typed ID를 만들고 모든 pasted object를 현재 최대 zOrder 뒤에 원래 상대 순서로 추가한다. 해당 kind의 host `imageObjectOptions`/`barcodeObjectOptions`가 비어 있지 않은 구조화 mode에서는 현재 option 목록에서 빠진 stale 연결 ID도 기존 데이터 바인딩으로 보존한다. 해당 kind의 options가 비어 있는 host에서만 legacy/자동 editable 연결 ID를 active sheet의 기존 값과 transaction 예약값을 피해 새로 발급한다. 별도 저장 marker를 추가하거나 ID prefix로 구조화 여부를 추론하지 않는다.
- duplicate는 clipboard를 읽거나 변경하지 않는 독립 command다. 선택 객체를 즉시 한 번 복제해 새 typed ID와 최상단 zOrder를 주고, 현재 kind host가 구조화 mode이면 stale 값을 포함한 연결 ID를 보존하며 options가 비어 있는 host의 editable 연결 ID만 새로 발급한다. 전체 command는 undo 1건이다.
- copy paste와 duplicate는 기존 이미지 동작과 같은 logical `(+12, +12)` offset을 사용한다. line은 두 endpoint, shape/image/barcode는 left/top에 같은 delta를 적용하고 Y 상단 clamp를 적용한다.
- cut paste는 사용자가 확정한 대로 geometry offset 없이 원래 위치를 유지하고 image/barcode 연결 ID도 보존한다. source sheet와 target sheet가 같으면 cut token이 유효하고 source typed key가 현재 부재할 때만 원본 typed ID를 유지한다. 다른 sheet이면 target의 typed key와 같은 transaction 예약 ID를 검사하며, 충돌이 없으면 원본 ID를 유지하고 충돌하면 target 기존 객체를 보존한 채 pasted 객체에 첫 충돌 없는 새 typed ID를 발급한다. 단순 ID 일치만으로 현재 target 객체를 제거하지 않는다.
- cut token은 source sheet ID, cut commit 직후 package-owned per-sheet canonical revision과 undo/redo·외부 workbook 교체 때 바뀌는 history-lineage generation으로 구성한다. cut 삭제 transaction이 source sheet revision을 한 번 증가시킨 뒤 그 값을 캡처한다. 단순 sheet 전환과 다른 sheet의 후속 편집은 token을 바꾸거나 payload를 무효화하지 않는다. source sheet의 후속 cell/object canonical mutation 또는 history-lineage generation 변경으로 token이 달라지면 내부 cut payload를 무효화한다. 성공한 cut paste는 payload를 즉시 소비하고, 권한·형식·target 충돌 검증 등으로 workbook을 바꾸지 못한 paste는 payload를 유지한다.
- mixed selection도 객체별 ID/연결 ID/offset 규칙을 적용한다. 성공한 paste 전체는 undo 1건이다.
- 성공한 duplicate/paste는 새 객체 전체만 selected set으로 만들고 그중 frontmost를 active key로 지정한다. copy와 실패한 paste는 기존 선택을 유지하며 undo/redo 뒤에는 §9.2의 typed-key 교집합 정리를 적용한다.

### 13.3 focus와 keyboard

- panel이 열린 동안 Tab은 layer list와 현재 속성 form 안에서 예측 가능한 순서로 이동한다.
- canvas shortcut과 text field shortcut이 충돌하지 않는다.
- editable field 또는 그 하위 editor가 focus된 동안 Ctrl/Meta+A/C/X/V/D, Ctrl/Meta+Up/Down/Home/End, 일반 Up/Down/Home/End와 Delete/Backspace를 object command로 전달하지 않는다. editable이 지원하는 키는 text selection/edit/clipboard/navigation이 소유하고, 지원하지 않는 키도 panel이 열렸다는 이유만으로 duplicate/reorder/delete 같은 object command로 재해석하지 않는다.
- `allowEdit == false`의 property text control은 disabled control로 교체하지 않고 read-only/selectable 상태로 유지해 pointer text selection과 Ctrl/Meta+A/C를 text editor가 소유한다. 값 변경, cut과 paste는 차단하고 canvas 또는 panel list focus의 Ctrl/Meta+C는 canonical selected object copy를 계속 실행한다.
- panel list focus에서 Delete, Ctrl+D, Ctrl+C/X/V, Ctrl+Up/Down/Home/End는 기존 layer shortcut을 유지한다.
- panel list focus의 일반 Arrow Up/Down은 row navigation, canvas focus와 active object가 있으면 Arrow/Shift+Arrow는 geometry 이동, canvas focus에 active object가 없으면 기존 cell navigation을 수행한다. editable field focus에서는 arrow를 caret/input이 소유한다.
- dock/overlay panel의 open 여부가 아니라 실제 `FocusNode`를 기준으로 keyboard command 소유권을 결정한다. layer shortcut은 layer list focus, geometry shortcut은 canvas focus일 때만 실행한다.
- canvas primary pointer-down은 canvas focus, layer row/action pointer-down은 layer list focus, property field pointer-down은 실제 하위 editor focus를 소유한다. 넓은 화면 dock을 단순히 열거나 닫는 command는 기존 focus를 옮기지 않는다.
- 사용자가 좁은 화면 object overlay를 명시적으로 열면 layer list에 focus한다. 단순 close는 아직 mounted·attached인 open trigger 또는 직전 유효 focus로 복원하고 복원 대상이 없으면 canvas focus로 fallback한다. popup이 내부 editor 등으로 focus를 실제 이동한 경우에도 단순 close는 같은 규칙으로 복원하되, focus를 가져가지 않은 toolbar popup close는 기존 focus를 바꾸지 않는다. 편집 command는 close 복원 대신 대상 property field로 focus한다.
- Escape 우선순위는 property draft 취소 → popup/overlay 닫기 → shape insertion 취소 → canvas focus 복귀 순서다. 한 번의 Escape는 가장 높은 적용 가능 branch에서 시각적으로 최상위인 transient 하나만 처리하고 즉시 handled로 종료하며 다음 Escape가 같은 branch의 상위 container 또는 다음 branch를 처리한다. 예를 들어 dropdown/submenu가 toolbar popup이나 object overlay 위에 열렸으면 dropdown/submenu만 먼저 닫는다. popup/overlay branch에는 toolbar popup과 하위 submenu, object/cell/editor context menu, color/dropdown popup과 좁은 화면 object overlay를 포함하고 context menu close는 selection을 바꾸지 않는다. 단 barcode panel renderer pending 중에는 request와 원래 exact typed-key draft/error 상태를 유지하기 위해 property draft 취소 branch를 건너뛰고 허용되는 다음 branch를 처리한다.

- `Completer` 기반 A cut→B copy와 A copy→B cut을 각각 A→B/B→A 완료 순서로 실행해 호출 순서상 최신 B만 최종 system marker·내부 payload를 소유함. stale A는 어느 완료 순서에서도 source를 삭제하거나 selection/undo/dirty/revision/callback을 바꾸지 않음. 요청 전 payload/marker가 일치하는 `P/M(P)` 상태에서 B write 실패 뒤 stale A OS write가 성공하는 순서도 모든 Future 정리 후 internal payload `P`와 system marker `M(P)`를 복원하고 A/B cut source와 workbook을 바꾸지 않음

- 구조화 image/barcode duplicate·copy paste 뒤 직렬화 model에 구조화 여부를 판별하는 신규 extraFields marker가 없고 ID prefix를 판정에 사용하지 않으며, system clipboard marker는 model JSON에 저장되지 않음

- same-sheet cut paste의 원본 ID 유지, cross-sheet 비충돌 유지와 충돌 시 target 보존·pasted ID 재발급
- cut→undo/redo·외부 workbook 교체·source sheet 후속 canonical mutation 뒤 stale cut payload 무효화, 단순 sheet 전환과 다른 sheet 편집 뒤 유지, 성공 paste 뒤 소비와 실패 paste 뒤 유지

- undo/redo·외부 workbook replacement 뒤 history-lineage generation이 바뀌어 sheet revision 값이 우연히 같거나 복원돼도 stale cut payload가 다시 유효해지지 않음
- cut 직후 package `onChange` 결과를 부모가 새 workbook 인스턴스로 echo해도 acknowledgment로 판별해 token·selection/transient state를 유지하고 same/cross-sheet paste가 동작하며, canonical snapshot이 다른 실제 외부 replacement만 token을 무효화함
- duplicate/paste 성공 뒤 새 객체만 선택·frontmost active, copy/실패 paste의 기존 선택 유지
- object mutation은 `allowEdit == false`에서 모두 차단되고 panel selection/copy는 허용됨
- `allowEdit == false` object copy 전후 workbook JSON 불변과 undo/dirty/`onChange`/`onOp` 0회
- valid/invalid 일반 property draft와 barcode pending 각각에서 object selection을 바꿀 때 valid draft는 첫 `onChange`와 listener가 committed canonical 값·old selection·draft 없음을 보고, 이어지는 selection listener가 같은 canonical 값·new selection을 보아 총 2회임. invalid/no-draft와 pending 예외는 canonical callback 없이 new selection listener 1회이며 observer가 old draft와 new selection이 섞인 snapshot을 보지 않음. 동일 selection 재요청은 통지 0회이고 panel row/canvas/keyboard/secondary-click 대표 진입점이 같은 coordinator를 사용함
- settings-only `allowEdit` true→false에서 새 permission은 수용하되 canonical sheet/object/cell JSON, workbook identity·history lineage, undo/redo·dirty·revision과 `onChange`/`onOp`는 불변임. valid/invalid 일반 draft와 inline error를 commit 없이 폐기하고 callback identity를 종료하며 selection·active key·panel open 상태를 유지한 read-only snapshot을 listener 1회로 노출함. 생성·편집 dialog와 style/color/insertion popup은 표준 focus 복원과 함께 즉시 닫히고 열린 object context menu는 menu focus scope와 Escape 소유권을 유지한 채 mutation 항목이 disabled로 재구성됨. pending cut/paste/image picker/barcode renderer는 무효화되며 늦은 blur/Enter/mutation async 결과는 완전한 no-op이고 pending copy는 latest-wins marker/payload 일치를 유지하며 완료함. 이후 settings-only false→true는 폐기 상태를 복원하지 않고 selection·revision·history를 유지한 채 mutation enablement snapshot만 controller/listenable 1회로 갱신하며 canonical callback은 0회임
- 보호/locked cell selection이 object mutation enablement를 바꾸지 않고 `allowEdit == true`이면 동일하게 동작함

- 기존 image/barcode edit dialog command가 panel edit로 전환
- option 목록에 없는 non-empty image/barcode 연결 ID를 panel open과 연결 ID/source 미변경 commit에서 보존함. barcode는 명시적 `연결 안 함`에서 metadata를 제거하고 linked image는 아래 새 파일 필수 조건을 따름
- linked image의 `연결 안 함`은 새 파일 선택 성공 때만 commit되고 파일이 없으면 validation과 기존 linked image/metadata를 유지함
- stale ID linked image의 파일 교체가 연결 ID와 `left/top/width/height/rotation` 및 기타 metadata를 유지한 채 `src`·`originWidth`·`originHeight`만 바꾸고, 고정 image의 파일 교체는 연결 metadata를 새로 만들지 않음
- panel image picker pending 중 selection을 다른 image로 바꿔도 성공 결과는 호출 시점 exact image에만 적용되고, 원 객체 삭제·교체·ID 변경·권한 해제·undo/redo·외부 교체와 A 뒤 B picker 역순 완료에서는 stale resource 정리와 workbook/draft/selection no-op
- 기존 회전 바코드의 panel open이 rotation metadata의 동등한 canonical 값을 표시하고 무변경 `[적용]`은 같은 시각 회전을 render request/replacement에 보존하며, `-90`/`360`/`450`은 `270`/`0`/`90`으로 정규화되고 비숫자·`NaN`·무한대는 `0` fallback, 변경 적용은 유한값 검증 뒤 저장·capture에 반영됨
- barcode panel `[적용]` pending 중 selection 변경 뒤 원래 exact key/revision commit, 객체 삭제·교체·ID 변경·undo/redo·외부 교체 뒤 늦은 결과 폐기와 null/예외 inline 실패
- barcode A pending 중 B 선택은 허용하고 active property snapshot은 B를 표시하지만 B property control·새 draft 시작은 disabled이며 A keyed draft/request/error는 유지됨. A 실패 중 B가 active이면 error를 B form에 표시하지 않고 A 재선택 시 표시하며 성공/명시적 폐기 뒤 A keyed 상태를 제거함
- barcode A pending 중 B를 선택한 뒤 controller의 B property update/begin-draft command를 직접 호출해도 workbook/draft/undo/dirty와 `onChange`/`onOp`/listenable이 모두 불변이어서 UI enablement 우회 mutation이 차단됨
- barcode panel 적용 pending 중 같은/다른 exact key의 UI submit과 controller render command가 모두 no-op이고 기존 request token·draft·blocking을 유지하며, 완료 뒤 사용자가 다시 실행한 요청만 새 token으로 시작함
- 신규 image/barcode 생성 dialog는 유지
- image/barcode 생성 후 이미 열린 panel만 새 속성으로 전환하고 dock/overlay closed 사용자 의도를 유지함
- 넓은 화면에서 닫힌 panel에도 객체/레이어 toolbar toggle이 표시되고 마지막 폭으로 다시 열며, 좁은 화면에서는 상시 icon으로 overlay를 엶

### 15.7 capture/출력 테스트

- capture PNG에 line/shapes 포함, 모든 editor handle/panel 제외
- crop origin이 있는 capture의 endpoint 위치
- 양 endpoint가 crop 반대편 밖인 교차 line과 중심선은 밖이지만 stroke만 crop에 닿는 line의 보존/pixel 결과
- crop origin과 회전이 있는 shape 위치
- 회전 전 bounds는 crop 밖이지만 회전 path가 crop과 교차하는 shape의 보존/pixel 결과
- image/barcode/line/shape zOrder pixel 결과
- PDF capture와 화면 style 일치
- solid axis-aligned EZPL native 조건
- unfilled solid black rectangle EZPL native 조건
- native coordinate/stroke의 최소 1 dot과 0.5 dot 오차 제한. 양수·음수 half를 포함한 signed left/top/right/bottom edge를 각각 Dart `round()`하고 R 계열 extent는 정수화된 반대 edge 차이로 파생하며, edge별 정확히 0.5 dot은 허용하고 command 제약·clip·최소 stroke 뒤 하나라도 초과하면 fallback함
- module 기반 native barcode는 정수화한 command parameter와 module count/quiet zone 규칙으로 최종 painted bounds를 계산해 목표 edge/height와 비교하고, edge 차이를 module width로 강제하거나 module/quiet-zone 규칙을 변형하지 않음
- nonzero signed left/top push와 right margin 및 `clipBottomMm == labelHeightMm` 하단 경계에서 raster/native barcode·line·rectangle·border의 공용 transform 좌표 일치, right/height native clip 불가 후보의 bitmap fallback
- `extraAreaMm > 0`이어도 label-height 아래 매체 영역에 raster/native 콘텐츠가 없고 `pageHeightMm`은 `^Q` 매체 높이에만 반영됨
- 세로 방향에서는 barcode/line/rectangle/cell-border native command가 생성되지 않고 회전된 공용 bitmap만 출력됨
- native 가능 barcode의 앞·뒤에 line/shape가 있을 때 공통 object zOrder를 보존하고, 순서가 바뀌는 native barcode 최적화는 bitmap fallback
- native 후보 line/rectangle의 앞·뒤에 raster image/barcode/shape가 있을 때 공통 object zOrder를 보존하고, 여러 native geometry 사이의 상대 순서도 paint order와 일치
- `raster → native 후보 → 상부 raster`로 교차하는 세 객체에서 후보를 bitmap fallback하고 native 승인 전에는 fallback PNG 영역을 제거하지 않음
- app preflight descriptor 생성에 성공한 후보가 package 최종 zOrder 판정에서 탈락하면 filtered bitmap에 객체 전체가 유지되고 해당 candidate token의 descriptor는 encoder에 전달되지 않음
- approval record의 unknown 또는 중복 candidate token은 최종 plan에서 미승인되어 어떤 exact key도 bitmap에서 생략하지 않고 descriptor도 encoder에 전달하지 않으며, package 후보의 token→exact key binding은 app이 덮어쓰지 못함
- 승인된 native barcode의 bar 사이·quiet zone과 비채움 rectangle 내부에서 아래 raster pixel을 보존하고 flatten된 PNG의 bounds/mask를 흰색으로 지우지 않음
- 하나의 immutable Hybrid render plan이 filtered print capture와 native command 생성에 동일하게 전달되고 exact object key/cell-border edge 승인 집합만 bitmap에서 생략됨
- native preflight에서 edge/stroke가 정확히 0.5 dot이면 descriptor와 최종 plan에 승인되고, command 제약·clip·최소 stroke 또는 barcode module/quiet-zone predicted bounds 중 하나라도 0.5 dot을 초과하면 최종 plan에서 제외되어 filtered bitmap에 객체 전체가 유지되고 native command는 0개임
- plan 확정 뒤 async filtered capture 완료 전 live workbook mutation·undo·active sheet 변경이 발생해도 filtered bitmap/native bytes와 반환 sheet/range는 plan이 소유한 최초 canonical snapshot 기준이며 완료 시점 live canvas를 다시 읽지 않고 새 workbook/revision/undo에 영향이 없음
- image/barcode/line/shape에 같은 문자열 ID를 준 fixture에서 한 exact typed key만 승인하면 해당 객체만 filtered capture에서 빠지고 native command에 포함되며 다른 kind의 같은 ID 객체는 bitmap에 유지됨
- EZPL host가 선행 일반 capture 없이 Hybrid coordinator 하나를 호출하고 coordinator 내부 순서가 canonical snapshot→source 크기/resolved layout 확정→package native 후보→app preflight descriptor→package 최종 plan→filtered capture→승인 descriptor native command 생성임
- 인접 cell의 right/left 및 bottom/top alias가 같은 canonical physical edge key로 합쳐지고 한 edge 승인 시 filtered capture와 native command에서 정확히 한 번만 제외·출력됨
- 숫자 좌표가 같은 vertical `(row, boundaryColumn)`과 horizontal `(boundaryRow, column)` edge를 동시에 두어 방향을 포함한 서로 다른 key로 독립 승인·제외·출력함
- filtered print capture 전후 workbook JSON·revision·undo/dirty/callback 불변, 일반 capture/PDF 결과 불변과 임시 workbook mutation·전체 border 제외·사후 흰색 pixel 삭제 미사용
- 다중 발행 PDF backend는 unit별 기존 `capture()`만 호출하고 Hybrid API를 호출하지 않으며, EZPL backend는 각 unit이 active일 때 `captureHybridEzpl()`만 호출해 일반 PNG 선행 capture 없이 unit별 bytes와 동일 canonical sheet/range snapshot을 저장함
- 서로 다른 데이터의 연속 EZPL unit에서 각 반환 snapshot의 item-code 오류를 해당 unit 이름/copy index로 검사하고, grouping은 저장된 unit별 bytes를 순서대로 연결하며 마지막 live controller로 이전 unit을 다시 capture하지 않음
- Hybrid facade가 입력 source 크기 null이고 canonical range 크기가 label 크기와 다른 경우에도 range의 행·열 metrics로 source width/height와 resolved metrics/layout을 plan 전에 확정하며 plan/filtered capture/native encoder가 같은 transform을 사용해 group page spec과 layout 검사를 구성함. FortuneSheet package import graph에는 app `LabelSheetPrint*` 타입과 EZPL encoder가 없음
- app resolved layout이 logical source bounds, DPI/mm→dot scale, content origin, right/bottom clip, orientation/native 허용을 가진 package-neutral immutable transform DTO를 한 번 만들고 plan/filtered capture/native encoder에 동일 instance를 전달함. `clipBottomMm == labelHeightMm`, extra area 제외와 vertical native false를 검증하며 package DTO/import graph에는 app `LabelSheetPrint*`/encoder 타입이 없음
- cell base-layer border가 상부 객체와 겹칠 때 native border를 사용하지 않고 bitmap의 고정 순서를 보존
- dashed/diagonal/color line bitmap fallback
- filled rectangle/roundedRectangle/ellipse bitmap fallback
- fallback 후 line/shape 중복 overlay 없음
- 출력 clip 밖 선 제거

## 16. 구현 순서

1. 공통 stroke style, `FortuneLine`, `FortuneShape`, shape kind, optional-empty `FortuneSheet.lines/shapes`와 codec을 추가한다. 무관한 `copyWith`의 typed/raw 보존과 typed list 교체 시 stale raw 폐기, `lines`/`fortuneShapes`의 typed 단독 소유, ID wire validation과 images raw 재사용 경계를 포함한 model/codec 테스트를 통과시킨다.
2. LabelSheet의 `sheet.lines`, `sheet.fortuneShapes` feature key, sanitizer, migration/normalize, label content 판정과 save 테스트를 추가하고 legacy raw overlay `shapes`와 분리한다. legacy `shapes`는 일반 clone/cast 전 raw `Object?` strict clone으로 JSON-safe 구조만 원형 복사하고 invalid descendant가 있으면 overlay 전체만 omit한다. 원래 print-area rect에서 exact geometry key를 확정한 뒤 padded bounds로 범위만 확장하는 print-area save를 연결한다.
3. typed object key/ref, exact-key resolver/mutation, 중복 ID normalize/allocator와 finite zOrder 정렬·정규화 helper를 추가한다.
4. line/shape 공용 geometry/stroke helper와 화면/capture painter를 추가한다.
5. toolbar shape combo, geometry kind별 stroke/fill/radius preset과 transient gesture draft 기반 line/shape drag 생성을 추가한다.
6. line hit-test, 단일 선택, 본체 이동, endpoint handle과 keyboard 이동을 추가한다.
7. shape hit-test, 본체 이동, local-axis 8방향 resize와 opposite world anchor 고정, rotation handle과 keyboard 이동을 추가한다.
8. 기존 image layer selection state를 typed object selection으로 일반화하고 기존 image/barcode geometry drag도 transient gesture commit 경계로 전환한 뒤 기존 회귀 테스트를 통과시킨다.
9. 공통 object layer list와 단일/다중 선택 상태를 immutable snapshot/public listenable이 있는 exclusive-attach package controller로 노출한다. controller 교체는 new attach 가능 여부를 먼저 검증하고 실제 owner를 추적하며, 실제 op transaction의 `onChange`→`onOp`→listenable과 외부 replacement의 `onChange`→listenable 통지 순서를 각각 연결한다.
10. dock형 object panel을 만들고 exact target key+before/after drag reorder를 포함한 기존 layer action을 연결한다.
11. line/shape property form과 타입별 context menu를 연결한다.
12. 기존 image/barcode 편집 validation/commit, linked image 해제의 새 파일 필수 조건, panel image picker의 exact-key owner/token 검증과 exact-key barcode pending draft/error·rotation/latest-request render/metadata 보존을 공용 API로 추출하고 panel form을 연결한다. 생성 dialog는 같은 API를 사용하도록 유지한다.
13. `LabelSheetWorkbench`에 splitter, panel width clamp, 접기와 narrow overlay fallback을 연결한다. panel controller/draft를 presentation보다 상위에 유지하고 경계 전환의 자동 open/focus 이동을 막으며 narrow overlay가 열린 동안 active object toolbar를 paint/hit-test하지 않는다.
14. clipboard 단일 async paste coordinator의 호출 시점 target owner snapshot, 호출 순서 latest-wins인 copy/cut marker write coordinator와 marker 기록 성공 뒤 source owner/model을 재검증하는 cut transaction, canonical typed deep-clone mixed payload, reorder, package-owned per-sheet revision과 모든 object zOrder insertion 경로를 마무리한다.
15. 일반 capture/PDF 동작을 유지한 채 Hybrid EZPL coordinator의 package-neutral immutable transform DTO/native 후보·최종 render plan, canonical physical cell-border edge key와 exact object/edge filtered print capture API를 추가한다. app resolved layout에서 transform DTO를 한 번 만들고 `LabelSheetOutputCaptureController`의 app-facing Hybrid unit API를 연결한다. 다중 발행 EZPL host의 선행 일반 capture를 제거한 뒤 coordinator 단일 진입점에서 package 후보→app EZPL preflight descriptor→package 최종 plan→최초 canonical snapshot 기준 filtered capture→승인 descriptor native command 생성 순서와 실패 후보의 bitmap 유지, zOrder/fallback을 검증한다.
16. 관련 focused test, 기존 회귀 test, `flutter analyze`, diagnostics와 `git diff --check`를 실행한다.
17. 테스트 생성물과 임시 파일을 정리한 뒤 요청 범위 파일만 stage/commit한다.

각 단계는 첫 작은 변경 직후 해당 focused test를 실행한다. model/codec이 검증되기 전에 panel UI부터 만들거나, 공통 ordering이 검증되기 전에 기존 image layer 코드를 대량 교체하지 않는다.

## 17. 완료 조건

다음을 모두 만족해야 완료다.

- 기존 images-only 라벨 파일이 이전과 같은 이미지·바코드로 열린다.
- `FortuneSheet`의 lines/shapes 생성자 인자는 optional-empty라 기존 호출이 source-compatible하고, 무관한 `copyWith`는 typed list와 raw metadata를 보존하며 typed list 교체는 함께 제공하지 않은 stale raw metadata를 폐기한다.
- line 4종과 두께·색상·좌표·zOrder가 저장 후 동일하게 복원된다.
- `lines`/`fortuneShapes`는 typed model/raw metadata가 단독 소유하고 `extraFields`와 이중 소유하지 않는다. line/shape ID는 trim 후 non-empty JSON string만 허용하고 다른 타입·빈 ID entry는 제외한다.
- 같은 sheet/kind의 중복 내부 ID는 첫 entry를 유지하고 후속 entry에 결정적인 충돌 없는 ID를 발급하며 연결 ID metadata는 유지된다.
- 중복 ID normalize는 kind별 모든 원본 ID를 선예약해 뒤의 정상 원본 ID를 선점하지 않고, 신규 allocator는 kind prefix별 가장 작은 빈 양의 suffix를 사용한다.
- 비유한 zOrder는 `0.0`으로 canonicalize되고 공통 정렬과 다음 객체 zOrder는 유한값만 사용한다.
- 기존 image/barcode의 비숫자·비유한 extraFields zOrder도 `0.0`으로 canonicalize되고 비정상 raw를 재사용하지 않는다.
- ID/zOrder canonicalization, geometry·stroke/fill/radius fallback 또는 invalid entry 제외가 발생한 raw list는 재사용하지 않고 모든 canonical field의 유효한 wire로 저장된다. line/shape 색상은 6자리 hex만 대문자 `#RRGGBB`로 canonicalize하고 다른 공용 parser 문법과 alpha는 허용하지 않는다.
- absent/빈 lines/fortuneShapes는 같은 empty model이며 canonical encoder는 raw empty key 보존 조건이 아니면 빈 typed list key를 생략한다. legacy raw overlay `shapes`는 typed shape로 해석하지 않고 FortuneSheet codec에서 원형 보존한다.
- legacy raw `shapes`는 JSON-safe leaf와 String-key map/list일 때만 원형 보존하고 invalid descendant가 하나라도 있으면 부분 변형 없이 해당 overlay 전체만 제외해 나머지 workbook 저장을 계속한다.
- legacy raw `shapes` strict clone은 일반 migration clone/cast 전에 원본 key 타입·finite value·cycle을 검사하고 유효 `null`과 invalid를 별도 결과로 구분한다.
- manifest feature 누락은 payload에 존재하는 lines/fortuneShapes를 제거하지 않고 payload key 자체의 부재만 empty model로 해석한다. FortuneSheet codec은 canonicalization을, LabelSheet sanitizer는 구조/allow-list 필터를 소유한다.

- 동시에 시작된 object copy/cut marker write는 성공 여부와 무관하게 호출 순서상 최신 요청만 commit 자격을 가지며 stale 완료가 source나 내부 상태를 바꾸지 않는다. 최신 요청 성공 시 모든 write 정리 뒤 system marker와 활성 payload는 그 요청에 일치하고, 최신 요청 실패 시 요청 전 안정된 payload와 대응 marker 쌍을 OS clipboard까지 복원해 stale 요청을 되살리지 않는다.
- async cut은 marker 기록 성공 후 호출 시점 source owner/revision/exact canonical models와 권한이 모두 유지될 때만 삭제와 payload 활성화를 commit하고, selection/panel 변경 외의 source 변경에서는 완전한 no-op이다.
- same-sheet cut paste는 원본 typed ID를 유지하며 cross-sheet 충돌은 target 객체를 보존하고 pasted 객체 ID를 재발급한다.
- cut paste는 원래 geometry와 image/barcode 연결 ID를 유지한다. copy paste와 clipboard 독립 duplicate는 `(+12,+12)` offset과 새 typed ID를 사용하되 구조화 option 연결 ID는 보존하고 option 없는 host의 editable 연결 ID만 재발급한다.
- stale cut payload는 source history 변경 시 무효화되고 성공한 cut paste 뒤 소비되며, 성공한 duplicate/paste는 새 객체만 선택하고 frontmost를 active로 둔다.
- capture/PDF/EZPL에 line/shapes가 포함되고 editor handle/panel이 출력되지 않는다.
- `sheet.lines`, `sheet.fortuneShapes` feature key, allow-list, migration과 테스트가 함께 갱신되고 기존 raw overlay `shapes` wire는 유지된다.
- `.lms` 초기 로드, 라벨 파일에서 불러오기와 `.xlsx` import가 모두 현재 save format migrate/normalize 경계를 거치며, XLSX drawing은 line/shape로 추론하지 않는다.
- `.lms`는 decoder 내부 migrate→sanitize→decode를 한 번만 사용하고 `.xlsx` raw parser는 LabelSheet 적용 경계에서만 normalize한다.
- 선·도형만 있는 `.lms`를 export할 수 있고 print-area 교차 geometry가 stroke와 회전을 포함한 bounds로 보존된다.
- print-area save는 geometry를 crop-local로 옮기지 않고 원래 sheet logical 좌표와 교차 객체를 보존하며 row/column 범위만 조정한다.
- print-area save는 원래 logical rect와 line/fill 없는 shape의 실제 stroked path 또는 채움 shape의 회전 fill 영역·outline이 교차·경계 접촉하는 exact object key를 먼저 확정한다. patterned stroke는 canonical phase의 기하학적 dash/dot painted footprint로 판정해 gap-only 교차를 제외하고, 연속 envelope/padded bounds는 후보 culling과 범위 확장에만 사용하며 확장 범위의 이웃 객체를 추가하지 않는다.
- endpoint/중심점이 crop 밖이어도 실제 stroke/path가 교차하는 line/shape는 print-area save와 capture에서 보존된다.
- EZPL native barcode/line/rectangle과 raster 객체가 겹쳐도 화면의 공통 object zOrder를 바꾸지 않고 native geometry끼리의 상대 순서도 유지하며, native cell border는 항상 상부 객체 아래인 base-layer 순서를 유지한다.
- EZPL raster와 모든 native 후보는 signed push·margin·right clip과 `clipBottomMm == labelHeightMm`을 포함한 같은 `LabelSheetPrintLayout` printer transform을 사용하고 extra area를 콘텐츠 영역으로 사용하지 않는다. 세로 방향은 모든 native 후보를 bitmap fallback한다.
- app resolved layout은 app 타입에 의존하지 않는 immutable print transform DTO를 한 번 생성하고 plan, filtered capture와 native encoder가 동일 인스턴스를 공유해 source bounds·scale·origin·clip·orientation을 중복 계산하지 않는다.
- Hybrid coordinator는 package app-neutral 후보→app command-specific preflight descriptor→package 최종 plan을 filtered capture 전에 완료하고, preflight/최종 plan 미승인 key는 bitmap에 유지한다. filtered capture 뒤에는 새 native 실패/fallback 판정을 하지 않고 승인 descriptor만 encode한다.
- Hybrid EZPL coordinator는 exact object key와 cell-border edge 승인 집합을 가진 하나의 immutable render plan을 filtered print capture와 native command 생성에 공유한다. capture는 workbook을 mutation하거나 flatten된 fallback PNG를 지우지 않고 승인 집합만 painter에서 생략해 하부 pixel을 보존한다.
- Hybrid plan 확정 뒤 live workbook이 바뀌어도 filtered capture와 native encoding은 plan이 소유한 최초 immutable canonical snapshot을 끝까지 사용하고 완료 시점 live canvas를 다시 읽지 않는다.
- 다중 발행의 PDF unit은 기존 일반 capture를 사용하고 EZPL unit은 active 시점의 app-facing `captureHybridEzpl()` 결과를 저장한다. 각 Hybrid 결과의 canonical sheet snapshot으로 오류를 검사하고 resolved metrics/page spec으로 grouping하며 unit별 bytes를 연결만 한다. FortuneSheet package는 plan/filtered capture까지만 소유하고 app 인쇄 타입/encoder에 의존하지 않는다.
- 관련 focused test와 기존 image/barcode/save/print 회귀 테스트가 통과한다.
- `flutter analyze` issues 0, 변경 파일 diagnostics 오류 0, `git diff --check` 통과다.
- 사용자 변경 `lib/core/app.dart`와 unrelated dirty 파일은 stage/commit하지 않는다.
