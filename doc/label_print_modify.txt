# 라벨출력 탭 구현 작업지시서

## 0. 최우선 원칙

- 이 문서는 `doc/label_print.txt`를 구체화한 구현 기준이다.
- 동작 기준은 레거시 `.tmp/LabelManager`의 라벨출력과 현재 Flutter 앱의 품목관리 미리보기·공용라벨 인쇄 구현이다.
- 보완·예외 처리를 과도하게 추가하지 않는다. 실제 화면, 출력, 자동증가와 발행 이력에 필요한 model, DAO, 공용 API만 작성한다.
- 현재 LabelSheet/FortuneSheet workbook을 유일한 렌더 원본으로 사용하고 별도 RTF·문자열 인쇄 엔진을 만들지 않는다.
- 현재 `pubspec.yaml`의 hosted `printing` package와 기존 `RawPrinterWin32`, PDF/EZPL builder를 공용 확장해 사용한다. 라벨출력의 1:1 물리 배치에 필요한 builder 수정만 허용하고 package local fork, Windows native plugin 개조, spooler job 추적 기능은 이번 작업에 추가하지 않는다.
- SQL은 parameterized query와 기존 `DbClient.transaction()` 경계를 사용한다. SQL Server 오류는 사용자에게 전달하고 활성 transaction은 가능한 경우 rollback한다.
- SQL Server table, column, index, trigger, procedure를 생성·변경·삭제하지 않고 data/schema migration도 구현하지 않는다.
- 출력 journal, checksum, process crash 복구, 관리자 DB 판정, 앱 재시작 후 출력 복원은 이번 범위에 포함하지 않는다.
- 같은 앱 instance의 중복 발행만 메모리 busy 상태로 차단한다. 여러 client/PC의 동시 자동증가 발행과 번호 예약은 지원하지 않는다.
- 이번 기능은 Windows desktop 전용이다. 다른 platform에는 라벨출력 탭과 발행 command를 노출하지 않는다.
- 배포 build, installer 생성과 원격 push는 별도 요청이 있을 때만 수행한다.

이 문서에서 `accepted`는 앱이 호출한 출력 API가 오류 없이 완료된 상태다. PDF는 `Printing.directPrintPdf()`가 `true`를 반환한 경우, RAW는 `RawPrinterWin32.sendRaw()`가 exception 없이 완료된 경우다. 이는 실제 용지 출력 완료나 이후 printer 오류까지 보장한다는 뜻이 아니다.

## 1. 구현 목적

- 메인 `라벨출력(F3)` placeholder를 실제 라벨 발행 화면으로 교체한다.
- 품목관리에서 `발행`이 체크된 품목을 출력 작업 목록으로 가져온다.
- 출력 작업 행을 선택하면 오른쪽에 해당 품목의 실제 출력 workbook을 자동 표시한다.
- 행별 발행매수와 레거시 출력 override를 적용해 여러 품목을 한 번에 발행한다.
- 공용라벨관리의 프린터 설정과 현재 PDF/EZPL 출력 엔진을 공용화한다.
- 실제 `accepted`된 unit만 자동증가 값과 기존 발행 이력 table에 반영한다.

## 2. 레거시 동작 기준

### 2.1 출력 작업 목록

품목관리의 발행 체크 행만 출력 목록으로 가져온다. 출력 작업 표는 다음 11개 항목을 가진다.

1. 발행매수
2. 라벨크기명
3. 품명
4. 출력 폭
5. 출력 높이
6. 왼쪽 여백
7. 오른쪽 여백
8. 위쪽 여백
9. 왼쪽 밀기
10. 위쪽 밀기
11. 줄간격

행 기본값은 `BM_ITEM_OF_MARKET`의 사용 설정을 우선한다. field별 item baseline/override 또는 label-size/printer preference fallback으로 초기화한 뒤 라벨출력 화면의 session edit가 해당 값의 최종 유효값이 된다. 이 session edit에는 품목관리의 미저장 draft를 포함하지 않으며 품목관리 원본에 저장하지 않는다.

- 발행매수는 `TYPE_PRINTCOUNT` column content가 있으면 그 값을, 없으면 `ItemOfMarket.printCount`를 item baseline으로 사용한다. copies용 printer preference는 두지 않는다.
- `useLabelSize == true`이면 item width/height의 `item override`, 아니면 현재 공용라벨 크기의 `label-size fallback`을 사용한다.
- `useMargin == true`이면 item의 left/right/top margin과 left/top push의 `item override`, 아니면 공용 프린터 설정의 같은 field에 대한 `preference fallback`을 사용한다.
- `useLinefeed == true`이면 item linefeed의 `item override`, 아니면 공용 프린터 설정의 자동 줄간격 `preference fallback`을 사용한다.

저장된 printer preference 전체가 없거나 저장 printer가 제거되어 설정이 정리된 경우에는 현재 공용 화면과 같이 printer 미선택, margin/push/extra area `0.0`, 줄간격 조정 없음, 방향 `horizontal`을 초기 설정 snapshot으로 사용한다. width/height는 현재 label-size fallback을 사용하며 printer를 자동 선택하지 않는다.

발행매수 `0`은 개별 행에서 허용한다. 전체 매수 합계가 `0`이면 발행하지 않는다. 음수와 정수가 아닌 값은 허용하지 않는다.

### 2.2 선택과 미리보기

- 출력 목록을 만든 뒤 첫 행을 선택한다.
- 선택 행이나 출력 설정이 바뀌면 별도 버튼 없이 미리보기를 갱신한다.
- 오른쪽 미리보기는 읽기 전용이며 품목관리 `출력내용 미리보기`와 같은 materializer를 사용한다.
- 이미 화면에 실제 출력 미리보기가 있으므로 별도 `미리보기` 버튼은 두지 않는다.

### 2.3 검색

- 검색 대상은 현재 발행 체크된 출력 작업 목록이다.
- 품명 또는 `TColumn.searchPrint == true`인 column content와의 exact match만 찾는다.
- 입력값과 대상값을 trim하고 대소문자를 무시해 비교한다. 부분 검색은 하지 않는다.
- 같은 값이 여러 개면 현재 선택 다음 결과를 찾고 마지막 뒤에는 처음으로 순환한다.
- 검색은 일치 행을 선택하고 미리보기만 갱신한다. 자동 발행하지 않는다.

### 2.4 발행

- copies가 1 이상인 row를 row 순서와 copy index 순서의 `LabelPrintUnit`으로 펼친다.
- copies가 0인 row는 materialize, 출력, 자동증가와 이력에서 제외한다.
- 현재 label-size의 `TColumn` 중 `autoInc == true`가 하나라도 있으면 copies가 1 이상인 모든 row를 copy index별 값으로 materialize한다. 실제 값 변경은 `autoInc == true`인 column에만 적용한다.
- resolved backend는 command 전체에서 같으며 최종 physical page spec이 같은 인접 unit만 한 print group으로 묶고 unit 순서를 바꾸지 않는다.
- group을 순서대로 출력하고 한 group이 실패하거나 사용자가 취소를 요청하면 다음 group을 보내지 않는다.
- 이미 `accepted`된 group의 unit만 자동증가와 이력 저장 대상으로 삼는다.

## 3. 현재 코드 재사용 경계

### 3.1 데이터

다음 기존 데이터와 DAO를 재사용한다.

- `ItemOfMarketDAO.selectByItemOfMarketAndLabelSizeId()`
- `TColumnDAO.selectByLabelSizeId()`
- `TColumnContentDAO.selectScopedByItemIds()`
- 현재 label size, customer, market, user session
- 현재 label-size session에 마지막으로 저장·조회된 `ItemOfMarket`과 `TColumnContent` baseline
- `LabelPrinterPreferences`
- `LabelSheetPrintOptions`, `LabelSheetPrintPageMetrics`
- `RawPrinterWin32`, `PrinterProfile`, 현재 PDF/EZPL builder

현재 label-size session에 이미 읽은 데이터가 있으면 출력 탭에서 같은 SELECT를 반복하지 않는다. 품목관리 편집 모드나 미저장 draft가 있으면 라벨출력 탭으로 전환하지 않으므로 command와 materializer는 마지막 저장·조회 baseline만 사용한다. label size 변경, 품목 저장, 공용라벨 저장 후에는 상위 session reload 결과로 목록과 미리보기를 갱신한다.

### 3.2 공용 API로 추출할 기능

기존 private 구현을 복사하지 말고 소유 모듈의 공용 API로 추출한다.

1. 품목 출력 workbook materialize
   - 현재 품목 미리보기의 keyword, text, barcode, image 치환을 공용 service로 이동한다.
   - 품목관리 미리보기와 라벨출력이 같은 함수와 입력 DTO를 사용한다.
2. 읽기 전용 출력 미리보기
   - 현재 품목 출력 미리보기 widget을 공용화한다.
   - 원본 workbook을 수정하지 않고 private copy를 렌더한다.
3. 프린터 설정
   - 현재 공용라벨 설정 dialog를 configurable한 공용 widget으로 추출하고 preference load/save, printer picker와 parsing/validation을 함께 재사용한다.
   - 공용라벨 mode는 기존 copies와 내부 발행 버튼을 유지하고, 라벨출력 mode는 이를 숨기며 화면 하단 command bar에서만 발행한다.
   - 라벨출력 설정에는 printer, left/right/top margin, left/top push, 자동 줄간격, 추가 영역과 방향을 표시한다.
   - 공용 preference에 없는 `rightMargin`, `leftPush`, `topPush`는 같은 문자열 저장 방식으로 추가하고 기존 key가 없으면 `0.0`을 사용한다.
4. 출력 dispatcher
   - 현재 공용라벨의 printer 확인과 EZPL RAW/PDF 분기를 공용 service로 추출한다. 지원하지 않는 profile 또는 명시적인 `FILE:`/`PORTPROMPT:` port를 발행 전에 PDF로 정하는 것만 capability fallback이며, port 조회 `null`은 file port가 아닌 것으로 본다. RAW build/send 실패 후 PDF를 다시 보내는 동작은 재사용하지 않는다.
   - dispatcher는 UI를 직접 표시하지 않고 성공 여부 또는 exception을 반환한다. PDF는 `directPrintPdf()` 반환값을 확인하고 group의 page format을 `format`으로 전달한다.
   - `RawPrinterWin32.sendRaw()`는 기존 API 형태를 유지하되 `EndDocPrinter` 반환값도 확인해 실패하면 exception을 던진다. job ID, `AbortPrinter`와 native plugin 변경은 추가하지 않는다.

## 4. 화면 구성

### 4.1 전체 레이아웃

- 상단의 기존 검색 영역을 `라벨출력` 탭에서도 표시한다.
- 본문은 왼쪽 출력 작업 표와 오른쪽 읽기 전용 미리보기로 구성한다.
- 좁은 화면에서는 두 영역이 겹치지 않도록 세로 배치 또는 탭 전환을 사용한다.
- 하단 command bar는 `[프린터 설정]  선택된 프린터명  [발행]` 순서다.
- 긴 프린터명은 말줄임과 tooltip을 사용한다.
- 발행 중에는 같은 위치를 `[발행 취소]`로 바꾸고 중복 발행을 막는다.
- Windows가 아닌 platform에서는 화면을 구성하지 않는다.

### 4.2 출력 작업 표

- 품목관리와 같은 `FortuneTable` 또는 공용 table style을 사용한다.
- 품목 추가·삭제·Excel·저장 footer는 표시하지 않는다.
- 발행매수와 숫자 출력 설정만 inline 편집한다. 라벨크기명과 품명은 읽기 전용이다.
- 줄간격 cell은 `null`을 `0`으로 표시한다. 빈 값 또는 `0` commit은 `session edited null`, 30~300 정수 commit은 해당 `session edited` percent로 저장한다. 1~29, 301 이상과 비정수는 validation 오류로 commit하지 않는다. 명시적인 `100`은 `null`과 구분해 유지한다.
- 품목관리 발행 체크가 바뀌면 item ID를 stable key로 목록을 동기화한다.
- 남아 있는 행의 session edit와 현재 선택은 유지한다.
- 체크 해제된 item의 row와 session edit는 즉시 폐기한다. 같은 item을 다시 체크하면 이전 edit를 복원하지 않고 현재 item baseline/override 또는 label-size/printer preference fallback으로 새 row를 초기화한다.
- printer 설정 적용 시 printer, `extraAreaMm`과 방향은 현재 label-print session의 command-wide 설정으로 갱신한다. 동시에 현재 출력 목록의 모든 row를 순회하고 margin/push/line spacing 중 출처가 `preference fallback`인 field만 새 preference로 갱신한다. copies, width/height와 같은 row 안의 `item override`, `label-size fallback` 또는 `session edited` field는 유지한다.

### 4.3 미리보기

- 선택 행이 없으면 `발행할 품목을 선택하세요.`를 표시한다.
- 저장된 공용라벨 workbook이 없거나 현재 workbook으로 변환되지 않은 라벨은 저장 필요 안내를 표시한다.
- 실제 출력과 같은 크기, margin/push, 방향, 추가 영역과 줄간격을 적용한다.
- 셀 편집, 저장, 삽입과 인쇄 toolbar는 노출하지 않는다.

### 4.4 프린터 설정

- 3.2의 configurable 공용 dialog를 라벨출력 mode로 사용한다. 별도 dialog와 field widget을 중복 작성하지 않는다.
- 매수는 출력 작업 행이 소유하므로 dialog에 매수와 내부 발행 버튼을 두지 않는다.
- 하단에는 `[취소] [적용]`만 둔다. printer를 선택하지 않았으면 `[적용]`을 비활성화하고 preference 저장, command-wide session 설정 변경과 row 갱신을 하지 않는다.
- printer를 선택한 뒤 `[적용]`하면 설정을 preference에 저장하고 현재 label-print session의 command-wide printer, `extraAreaMm`과 방향을 갱신한다. row에서는 margin/push/line spacing의 `preference fallback` field만 갱신할 뿐 출력하지 않는다. 현재 선택 행의 미리보기는 갱신한 command-wide 설정과 row 설정을 모두 사용해 즉시 다시 만들고 다른 행은 선택될 때 새 값으로 만든다.
- `[취소]`는 dialog에서 바꾼 값의 preference 저장, command-wide session 설정 변경과 row 갱신을 모두 하지 않는다.
- 화면 하단의 `[발행]`만 실제 출력 진입점이다.

## 5. 상태와 model

### 5.1 `LabelPrintRowDraft`

최소 필드:

- stable `itemId`
- 원본 `ItemOfMarket`
- `copies`
- `widthMm`, `heightMm`
- `leftMarginMm`, `rightMarginMm`, `topMarginMm`
- `leftPushMm`, `topPushMm`
- nullable `lineSpacingPercent`
- copies의 `item baseline`/`session edited` 출처
- width/height의 `item override`/`label-size fallback`/`session edited` 출처
- margin/push/line spacing의 `item override`/`preference fallback`/`session edited` 출처

입력 규칙:

- `copies`: 0 이상의 정수
- `widthMm`, `heightMm`: 양의 정수 mm
- margin: 0 이상의 실수 mm
- push: signed 실수 mm
- 줄간격: `null` 또는 30~300 정수 percent. 공용 preference를 load할 때 `none`과 레거시 fallback `0`은 `null`인 간격조정 없음으로 변환하고, save할 때 `null`은 `none`으로 직렬화한다. command와 공용 출력 option 내부에서는 간격조정 없음을 `null`로 유지하며 명시적인 100은 유효한 100% 조정값으로 보존한다.
- 물리 출력 직전에 `widthMm - rightMarginMm > 0`인지 확인한다. 방향 transform까지 적용한 source physical bounds와 label clip의 교집합이 비면 설정 오류를 표시하고 발행하지 않는다.

### 5.2 물리 출력 계산

- `extraAreaMm`은 0 이상의 실수이고 방향은 `horizontal` 또는 `vertical`만 허용한다. command 생성 전에 검증하고 두 값은 출력 설정 snapshot에 포함해 출력 중 preference나 UI에서 다시 읽지 않는다.
- 저장 workbook의 `gridClientWidthMm/gridClientHeightMm`를 source viewport로 사용한다. 없으면 라벨 저장을 요청하고 출력하지 않는다.
- source logical pixel과 mm의 기존 공용 변환을 사용한다.
- row 크기가 source 크기와 달라도 workbook content를 확대·축소하거나 text를 다시 배치하지 않는다.
- source를 row label 영역에 1:1로 배치한다. content 원점은 `(leftMarginMm + leftPushMm, topMarginMm + topPushMm)`이고 push는 음수를 허용한다. 오른쪽 content clip 경계는 `widthMm - rightMarginMm`이며 label 영역과 extra area에는 content가 넘어가지 않게 자른다.
- label clip은 page 좌상단을 `(0, 0)`으로 한 `[0, widthMm - rightMarginMm] x [0, heightMm]` 사각형이며 extra area는 포함하지 않는다. horizontal source bounds는 content 원점에서 `sourceWidthMm x sourceHeightMm`, vertical source bounds는 같은 원점에서 회전 결과인 `sourceHeightMm x sourceWidthMm`다. 두 bounds의 가로 또는 세로 겹침 길이가 0 이하이면 교집합이 빈 것으로 판정한다.
- 라벨출력 PDF builder는 source physical width/height로 image를 배치하고 row width/height에는 맞추지 않는다. 라벨출력 경로에서 `BoxFit.fill`을 사용하지 않는다. EZPL raster/bitmap fallback도 source physical 크기와 출력 DPI로 dot 크기를 계산하며 row label dot 크기로 `copyResize`하지 않는다. row 크기는 page와 clip에만 사용한다.
- horizontal page는 기존처럼 `W x (H + extraArea)`다. 사용자 확정에 따라 vertical도 같은 page 크기를 유지하고 content만 시계 방향 90도로 한 번 회전한다. page width/height를 교환하지 않는다.
- 방향 transform은 backend가 아니라 공용 physical layout이 소유한다. vertical의 시각적 시계 방향 90도는 page 좌상단 기준 source corner가 `TL→TR`, `TR→BR`, `BR→BL`, `BL→TL`로 이동하는 결과다. 회전 결과 bounds의 좌상단을 같은 content 원점에 배치하고 label 영역으로 자른다. preview, PDF와 EZPL은 backend 좌표계에 맞는 angle 부호로 이 결과를 만들며 backend builder에서 다시 회전하지 않는다.
- 위 방향과 extra area 동작은 기존 `LabelSheetPrintOptions`/`LabelSheetPrintPageMetrics`를 공용 확장해 preview, PDF와 EZPL에 동일하게 적용한다.
- 줄간격은 `FortuneOutputLayoutOptions` 같은 공용 출력 option으로 preview, PDF와 EZPL bitmap fallback에 동일하게 전달한다.
- DPI는 현재 `RawPrinterWin32.queryPrinterDpi()`와 `PrinterProfile` fallback을 사용한다. 별도 native DPI API를 추가하지 않는다.
- Godex EZPL은 현재 engine이 지원하는 plain-paper mode와 정밀 좌표/EZPL command/bitmap fallback 구조를 유지한다.

### 5.3 command/result

다음 immutable DTO 또는 동등 구조만 둔다.

- `LabelPrinterSnapshot`: 검증된 `Printer`, 표시용 name과 profile/port 확인으로 command 생성 전에 정한 단일 PDF 또는 EZPL RAW backend. `queryPrinterPortName() == null`은 현재 `isFilePortName(null) == false` 계약대로 명시적인 file port가 아닌 것으로 판정한다.
- `LabelPrintCommand`: `[발행]` 요청 시작 시 한 번 정한 `requestedAt`, label/customer/brand/market/user, printer, `extraAreaMm`과 방향을 포함한 설정, row, column/content와 saved workbook snapshot. brand는 command 생성 시점의 immutable `brandId`와 `brandName`을 가진다. `TColumn` snapshot은 `(columnOrder, columnId)` 오름차순으로 한 번 정렬하고 0부터 연속인 immutable `detailIndex`를 부여한다. 모든 snapshot은 출력 중 변경되지 않는다.
- `LabelPrintUnit`: item ID, row index, copy index와 materialize projection. 한 unit은 한 장이다.
- `LabelPhysicalPageSpec`: PDF 또는 EZPL backend의 최종 page 크기와 필요한 DPI/media 값
- `LabelPrintJobGroup`: command-wide resolved backend와 순서가 연속되고 page spec이 같은 unit 목록
- `LabelPrintDispatchResult`: group과 `accepted`/`failed`, 오류
- `LabelPrintPersistenceResult`: transient `notAttempted`/`succeeded`/`failed`/`outcomeUnknown`과 원본 오류. 별도 durable state나 복구 상태 machine은 아니다.
- `LabelPrintResult`: 요청/accepted 매수, group 결과, persistence 결과와 물리 dispatch 기준 `completed`/`partiallyAccepted`/`cancelled`/`failed`. 자동증가·이력 SQL 실패나 `DbCommitOutcomeUnknown`으로 accepted 매수와 물리 상태를 덮어쓰지 않는다.

process 복구용 manifest, generation, checksum과 별도 persistence state machine은 만들지 않는다.

### 5.4 session controller

- checked item ID와 출력 row 동기화
- item ID 기반 선택 유지
- row-local copies/출력 설정 편집
- 검색 cursor와 exact-match 선택
- 총 발행매수 계산
- 현재 앱 instance의 출력 busy와 cancellation request
- label-size session 교체 시 이전 row와 선택 폐기

## 6. workbook materialize

### 6.1 source of truth

- 현재 label-size session에 마지막으로 저장·조회된 공용라벨 workbook을 사용한다.
- 공용라벨 편집 화면의 저장 전 mutable workbook을 참조하지 않는다.
- materialize는 원본을 변경하지 않는 private copy를 반환한다.

### 6.2 치환 규칙

품목관리 `출력내용 미리보기`와 같은 공용 materializer를 사용한다.

- `#ITEMNAME`: 품명
- `#ELEMENT`: 마지막으로 저장·조회된 품목의 주원료/함량
- `# + TColumn.keyword`: 해당 item의 마지막 저장·조회 column value
- 일반/날짜/시간: 기존 format과 range 규칙
- 실제 출력의 일반 날짜·시간, 유통기한과 time-barcode 계산은 각 unit에서 `DateTime.now()`를 다시 호출하지 않고 command의 같은 `requestedAt`을 사용한다. autoInc가 없는 일반 row의 모든 copy는 동일한 시간 기준 projection을 사용한다.
- 바코드/QR/GS1: 기존 `ItemCodeDataResolver` 결과
- 연결 이미지: 현재 image resolver 결과. 값이나 파일이 없으면 materialized copy에서 해당 연결 image object만 생략하고 원본 workbook은 변경하지 않는다.
- 고정 이미지와 고정 바코드: 원본 workbook 값 유지
- resolver 오류: placeholder를 출력하지 않고 item/copy/column을 알린 뒤 첫 OS call 전에 전체 발행을 중단한다. 해당 unit만 건너뛰거나 앞 group부터 보내지 않는다.

미리보기는 copy index 0, 실제 출력은 각 unit의 copy index projection을 사용한다.

## 7. 실제 출력

### 7.1 group 생성

- row 순서와 copy index 순서대로 unit을 만든다.
- 모든 unit을 공용 materializer와 print job builder로 page payload에 추가하고 오류가 없는지 확인한 뒤에만 첫 group dispatch를 시작한다.
- 한 command의 모든 unit은 `LabelPrinterSnapshot`의 같은 backend를 사용하고 최종 physical page spec이 같은 인접 unit만 한 group으로 묶는다.
- PDF group은 같은 page format의 multi-page PDF 한 건, EZPL group은 각 label이 `^P1`인 RAW payload 한 건으로 만든다.
- spec이 바뀌면 새 group을 만들고 뒤에서 같은 spec이 다시 나와도 앞 group과 합치지 않는다.

### 7.2 dispatch

- 선택 printer를 command 시작 시 snapshot하고 출력 도중 다시 선택하지 않는다.
- command backend가 EZPL RAW이면 기존 EZPL builder와 `RawPrinterWin32.sendRaw()`를 사용한다.
- 지원하지 않는 profile 또는 명시적인 `FILE:`/`PORTPROMPT:` port라 command backend가 PDF이면 기존 PDF builder와 `Printing.directPrintPdf()`를 사용한다. port 조회 결과가 `null`이면 file port로 간주하지 않으므로 EZPL profile은 RAW backend를 선택한다.
- PDF document page와 `directPrintPdf(format:)`은 같은 group page format을 사용하고 반환값을 확인한다.
- PDF는 `directPrintPdf() == true`, RAW는 group의 모든 unit을 담은 한 `sendRaw()` call이 `EndDocPrinter` 확인까지 exception 없이 완료되면 해당 group의 모든 unit을 `accepted`로 본다. PDF `false`/exception 또는 RAW exception이면 해당 group의 모든 unit을 `failed`로 본다. 현재 API가 제공하지 않는 group 내부 page/label별 결과는 추적하지 않는다.
- EZPL build 오류는 첫 OS call 전 전체 preflight 실패로 처리하고 `sendRaw()` exception은 해당 group 실패로 처리한다. 두 경우 모두 PDF로 다시 만들거나 재전송하지 않는다.
- group 실패 후에는 다음 group을 보내지 않는다.
- OS 출력 call을 앱 cancellation로 강제 중단하지 않는다. call 실행 전 또는 group 사이에 취소를 확인하고, 실행 중 요청된 취소는 call 완료 후 다음 group부터 적용한다.
- 별도 timeout, spooler polling, job ID 추적과 앱 재시작 복구는 구현하지 않는다.

모든 unit을 한 OS print call로 합치지 않는다. command-wide backend에서 같은 page spec의 인접 unit만 group으로 묶어 기존 builder가 다룰 수 있는 단위로 순차 실행한다.

## 8. 데이터 저장

### 8.1 자동증가

`LabelPrintAutoIncrementDAO` 또는 동등 책임을 둔다.

- 자동증가는 DB를 변경하지 않는 순수 함수로 계산한다. 마지막으로 저장·조회된 원본값, copy index, `autoIncSize`, `autoIncRange`, `autoIncZeroDel`, barcode check digit와 time-barcode 설정을 입력으로 받는다.
- 증가 대상은 레거시처럼 지정 범위의 숫자 부분이며 `autoIncSize * copyIndex`를 더한다. 범위를 넘으면 해당 자릿수 안에서 순환하고, 앞자리 0 유지/제거와 barcode check digit/time-barcode 재적용도 레거시 순서를 따른다.
- barcode check digit와 date/time 값 생성은 기존 helper를 재사용한다. 자동증가 계산 자체는 새 공용 순수 함수로 작성한다.
- `autoInc == false`인 column은 변경하지 않는다.
- 해당 `(columnId,itemId)`의 accepted unit이 있을 때만 저장한다.
- accepted unit 중 가장 큰 copy index의 projection을 마지막 값으로 본다.
- `autoIncSave == true`이면 마지막 accepted copy 다음 값을, `false`이면 마지막 accepted copy에 출력한 값을 저장한다.
- `autoIncUpdate`는 활성 레거시 출력 결과에 영향을 주지 않으므로 저장 분기에 사용하지 않는다.
- 대상 row가 없거나 update affected row가 예상과 다르면 SQL 오류로 처리하고 transaction을 rollback한다.
- 여러 client/PC의 동시 번호 예약은 구현하지 않는다.

### 8.2 발행 이력

`LabelPrintHistoryDAO` 또는 동등 책임을 둔다.

- 기존 `BM_RICH_PRINT_LOG`, `BM_RICH_STATUS`, `BM_RICH_STATUS_DATA`만 사용한다.
- `BM_RICH_PRINT_LOG`는 기존 identity를 제외하고 레거시 insert field인 `RICH_USER_ID`, `RICH_USER_NAME`, `RICH_USER_GRADE`, `RICH_MARKET_ID`, `RICH_MARKET_NAME`, `RICH_CUSTOMER_ID`, `RICH_CUSTOMER_NAME`, `RICH_BRAND_NAME`, `RICH_LABELSIZE_NAME`, `RICH_ITEM_NAME`, `RICH_PRINT_COUNT`, `RICH_DATETIME`, `RICH_DATE_YYYYMMDD`, `RICH_PRINTER`, `RICH_COLUMNS`, `RICH_PRINT_CELLS`, `RICH_SAVE_IN_DB_CELLS`, `RICH_FORM_WIDTH`, `RICH_FORM_HEIGHT`, `RICH_PRINT_LEFT_MARGIN`, `RICH_PRINT_RIGHT_MARGIN`, `RICH_PRINT_TOP_MARGIN`, `RICH_PRINT_LEFT_PUSH`, `RICH_PRINT_TOP_PUSH`, `RICH_PRINT_APPENDANT`, `RICH_ITEM_ID`만 insert한다.
- print log의 user/market/customer/brand/label/printer 값은 immutable command snapshot, item ID/name과 폭·높이·margin/push는 해당 history parent의 row snapshot, `RICH_PRINT_COUNT`와 세 wire 문자열은 해당 history parent, `RICH_PRINT_APPENDANT`는 command `extraAreaMm`에서 가져온다. 새 column을 가정하거나 출력 완료 후 전역 값을 다시 읽지 않는다.
- `BM_RICH_STATUS`는 `RICH_STATUS_ID`, `RICH_ITEM_ID`, `RICH_MARKET_ID`, `RICH_CUSTOMER_ID`, `RICH_BRAND_ID`, `RICH_LABELSIZE_ID`, `RICH_USER_ID`, `RICH_PRINT_COUNT`, `RICH_PRINT_DATE`, `RICH_PRINT_ITEM_NAME`, `RICH_PRINT_ITEM_ELEMENT`, `RICH_STATUS_ORDER`, `RICH_LABELSIZE_NAME`, `RICH_USER_NAME`, `RICH_USER_GRADE`, `RICH_BRAND_NAME`, `RICH_DATE_YYYYMMDD`만 insert한다. ID/name/count는 같은 command/history parent snapshot을 사용하고 element는 해당 parent의 출력 projection에 포함된 주원료를 사용한다. user grade는 기존 table별 레거시 표현을 따른다.
- `BM_RICH_STATUS_DATA`는 `RICH_STATUS_DATA_ID`, `RICH_COLUMN_ID`, `RICH_STATUS_ID`, `RICH_PRINT_COLUMN_DATA`, `RICH_COLUMN_NAME`만 insert한다.
- 이 절의 자동증가 행은 현재 label-size의 `TColumn` 중 `autoInc == true`가 하나라도 있을 때의 모든 출력 row다. 자동증가 행은 accepted copy별 `printCount=1`, autoInc column이 하나도 없는 label-size의 일반 행은 accepted copies 합계 한 건으로 기록한다.
- `RICH_COLUMNS`는 레거시처럼 `주원료` 뒤에 command의 `(columnOrder, columnId)` 순서인 `TColumn` column name을 `|`로 연결한다. `RICH_PRINT_CELLS`와 `RICH_SAVE_IN_DB_CELLS`는 같은 위치에 각각 주원료와 column 값을 연결하며 세 문자열 모두 trailing `|`를 남긴다. 이름이나 값 안의 `|`도 레거시처럼 escaping하지 않는다.
- `RICH_PRINT_CELLS`에는 해당 accepted unit의 자동증가가 적용된 실제 출력 projection을 기록한다. `RICH_SAVE_IN_DB_CELLS`에는 command 생성 시점에 snapshot한 자동증가 미적용 마지막 저장·조회 DB baseline의 주원료와 column 값을 기록한다.
- autoInc가 없는 일반 row를 accepted copies 합계 한 parent로 기록할 때 모든 copy는 같은 `requestedAt` projection이므로 그 동일 projection을 `RICH_PRINT_CELLS`에 기록한다.
- 한 command에서 만들 history parent를 unit의 `(rowIndex, copyIndex)` 순서로 정렬한다. 자동증가 행은 accepted copy마다 해당 unit 순서 key의 parent 하나를 만들고, 일반 행은 accepted copies를 합쳐 가장 작은 accepted copy index의 unit 순서 key에 parent 하나를 둔다.
- 단일 T-SQL batch에서 같은 customer의 기존 `MAX(RICH_STATUS_ORDER)`를 한 번 구하고 위 history parent 순서의 `ROW_NUMBER()`를 더해 연속 order를 배정한다. 고객 이력이 없으면 1부터 시작한다.
- `RICH_STATUS_ID`는 `<customerId>-<brandId>-<order>`, `RICH_STATUS_DATA_ID`는 `<statusId>D<detailIndex>` 형식을 사용한다. `detailIndex`는 DB의 `RICH_COLUMN_ORDER - 1`이나 SQL 결과 순서가 아니라 command에서 부여한 0 기반 연속 index다.
- status detail은 주원료를 제외하고 command의 `TColumn` snapshot만 순회한다. 각 detail은 command의 `detailIndex`, 실제 `columnId`, `columnName`과 `RICH_PRINT_CELLS`의 출력 projection 값을 저장하며 첫 TColumn부터 `D0`, `D1` 순서로 ID를 만든다. transaction JSON 입력에도 이 네 값을 명시하고 SQL에서 index나 순서를 재계산하지 않는다.
- `RICH_BRAND_ID`, `RICH_BRAND_NAME`과 status ID의 brand ID는 command의 immutable brand snapshot만 사용한다. 출력 완료 후 전역 selected brand를 다시 읽거나 brand 조회 SELECT를 추가하지 않는다.
- 사용자 확정에 따라 현재 Flutter에서 구분 가능한 `User.SYSTEM` 특수 로그인만 print log와 status/detail 이력에서 제외한다. 일반 `SYSTEM_ADMIN_USER` grade 로그인은 이력을 기록한다. 현재 Flutter에 없는 master-key 우회 로그인은 제외 대상으로 간주하지 않으며, 향후 해당 인증 경로를 구현할 때만 명시적인 session boolean을 추가한다. 자동증가 저장은 로그인 유형과 관계없이 accepted unit 기준으로 처리한다.
- 라벨 내용의 날짜·시간/time-barcode projection은 command의 `requestedAt`을 사용한다. 발행 이력 저장 시각은 이와 분리해 단일 T-SQL batch 시작 시 `GETDATE()`를 한 번 읽은 `@historyAt`을 사용하고, 같은 command의 print log와 status parent 날짜·시간 field는 모두 이 값에서 만든다.
- 여러 client/PC의 동시 order 충돌 방지는 이번 범위에 포함하지 않는다.

### 8.3 transaction과 오류

- `requiresPersistence`는 accepted unit 존재 여부와 별도로 `자동증가 update 대상이 하나 이상이거나 이력 insert 대상이 하나 이상`일 때만 `true`다. `User.SYSTEM`이고 autoInc column이 없는 경우처럼 accepted unit은 있지만 두 대상이 모두 없으면 `false`다.
- `requiresPersistence == true`일 때만 accepted unit의 자동증가 update, print log와 status/detail insert를 기존 `DbClient.transaction()` 한 번으로 실행한다. `false`이면 DB를 호출하지 않고 persistence를 `notAttempted`로 둔다. `User.SYSTEM`이어도 자동증가 update 대상이 있으면 update만 transaction으로 실행한다.
- 현재 API는 `List<DbTransactionStatement>`를 transaction 시작 전에 받으므로, 현재 품목 저장과 같은 `jsonEncode` parameter/`OPENJSON` 패턴으로 accepted unit과 자동증가·이력 입력을 전달하는 단일 `DbTransactionStatement`의 parameterized T-SQL batch 안에서 customer별 다음 order 계산, status/detail ID 생성과 모든 update/insert를 수행한다. SELECT 결과를 Dart로 가져와 transaction 중간에 뒤 statement를 조립하지 않는다.
- SQL은 parameterized query를 사용하고 문자열을 직접 이어 붙이지 않는다.
- 기존 table/column이 없거나 문자열 길이·형식이 맞지 않으면 SQL Server 오류를 그대로 사용자에게 전달한다.
- transaction 입력에 자동증가 update와 이력 insert가 실제 포함되는지의 두 boolean으로 사용자 문구의 대상을 정한다. update-only는 `자동증가 값`, history-only는 `발행 이력`, 둘 다 있으면 `자동증가 값과 발행 이력`을 사용하며 별도 persistence 상태를 추가하지 않는다.
- transaction statement 오류는 가능한 경우 rollback하고 `인쇄 작업은 접수되었으나 <실제 저장 대상>을 저장하지 못했습니다.` 뒤에 원본 SQL Server 오류를 함께 표시한다.
- commit을 시도한 뒤 `DbCommitOutcomeUnknown`이 발생하면 가능한 rollback 시도까지만 수행하고 `인쇄 작업은 접수되었으나 <실제 저장 대상>의 저장 결과를 확인할 수 없습니다.` 뒤에 원본 commit 오류를 함께 표시한다. 이를 저장 성공이나 확정 실패로 치환하지 않으며 DB 재조회·관리자 판정·자동 재시도를 추가하지 않는다.
- `requiresPersistence == false`이면 persistence는 `notAttempted`, commit 성공은 `succeeded`, statement 오류는 원본 오류를 가진 `failed`, `DbCommitOutcomeUnknown`은 원본 commit 오류를 가진 `outcomeUnknown`으로 반환한다. 이미 accepted된 unit, accepted 매수와 `LabelPrintResult`의 물리 상태는 persistence 결과 때문에 변경하지 않는다.
- DB 저장 실패 후 물리 출력을 자동 재실행하지 않는다. 별도 DB 재시도 UI, durable recovery 상태와 관리자 commit 판정은 구현하지 않는다.
- commit 성공 후에는 자동증가 대상 `(columnId,itemId)`의 현재 session snapshot만 commit 값으로 갱신한다. 화면 동기화가 실패하면 DB 성공을 되돌리지 않고 현재 session reload를 안내한다.

## 9. 품목관리 발행 체크 연동

- `ItemManage`에 `publishCheckedItemIds`와 변경 callback 또는 동등 controller API를 추가한다.
- 상위 `HomePageManager`가 현재 label-size session의 checked item ID를 소유한다.
- 우클릭 발행 체크, checkbox와 전체 해제가 모두 같은 callback을 사용한다.
- label size 변경, 품목 삭제와 session reload 때 존재하지 않는 ID를 제거한다.
- 발행 체크 해제로 제거한 item ID의 출력 row/session edit도 폐기하고 재체크 시 현재 baseline과 preference로 새로 초기화한다.
- 기존 `_blockItemDraftContextChange()`의 브랜드·라벨크기·출력 미리보기 등 다른 호출부 동작은 변경하지 않는다. `HomePageManager._onTabSelection()`에서 target이 `label_print`일 때만 `hasActiveEditing || itemDraftCommandBusy || ItemManagerDraftController.isDirty`를 한 번에 판정하는 `_blockLabelPrintTabSelection()` 또는 동등 전용 helper를 가장 먼저 실행한다.
- `FortuneTableEditingController`는 inline text editor가 실제로 열려 있거나 editor 값 commit이 진행 중일 때만 `true`인 read-only `hasActiveEditing`을 제공하고 `ItemManageController`가 이를 위임한다. 셀 focus나 row 선택만 있는 상태는 active editing이 아니다. 상태 확인을 위해 `commitEditing()`을 호출하지 않는다.
- 마우스 tab 선택, `F3` 단축키와 programmatic tab 선택은 모두 이 label-print target gate를 거친다. 별도 진입 경로에서 라벨출력 index를 직접 확정하지 않는다.
- 차단 시 callback 안에서 즉시 품목관리 tab selection을 복원하고 `품목 편집 내용을 저장하거나 취소한 뒤 라벨출력을 이용해 주세요.`를 한 번만 표시한다. 자동 저장·자동 취소·draft를 사용한 출력은 하지 않는다.
- 차단된 요청에서는 label-print 화면 activation, row load, preview/materialize, printer 조회와 command 생성을 시작하지 않는다.
- 품목 저장이나 변경 취소가 완료되고 `hasActiveEditing == false`, `itemDraftCommandBusy == false`, `ItemManagerDraftController.isDirty == false`가 된 뒤에만 라벨출력 탭 전환을 허용한다.
- 라벨출력은 기존 item ID의 마지막 저장·조회 baseline만 사용한다. 품목관리 draft 전체를 저장하지 않으며 자동증가 대상만 8.1 경계에서 저장한다.

## 10. 발행 pipeline

1. 메모리 busy flag를 원자적으로 설정해 같은 앱 instance의 중복 발행을 막고, 획득 직후 `[발행]` 요청의 현재 시각을 `requestedAt`으로 한 번 정한다. 탭 진입 시각이나 미리보기 생성 시각은 사용하지 않는다.
2. 현재 UI/session 값을 candidate snapshot으로 읽고 출력 행 존재, 전체 copies 1 이상, printer 선택, 저장 workbook과 숫자 설정, 유효 출력 폭과 source/label clip 교집합을 command 생성 전에 검증한다. 실패하면 backend 조회나 command 생성을 하지 않고 물리 상태 `failed`, accepted 0, persistence `notAttempted`로 종료한다.
3. 검증된 printer의 profile/port로 PDF 또는 EZPL RAW backend를 한 번 정한다. 명시적인 file port만 PDF capability fallback으로 처리하고 port 조회 결과가 `null`인 EZPL profile은 RAW를 선택한다. 앞에서 저장한 `requestedAt`, label/customer/brand/market/user, printer/backend, 설정, row와 마지막 저장·조회 column/content baseline, saved workbook으로 immutable command를 만든다.
4. row/copy 순서대로 모든 unit과 자동증가 projection을 만든다.
5. 모든 unit을 같은 `requestedAt`으로 공용 materializer와 command-wide backend의 print job builder에서 materialize하고 같은 physical page spec별 인접 group payload를 완성한다. 하나라도 resolver/decode/materialize/build 오류가 있으면 대상 item/copy/column을 표시하고 물리 상태 `failed`, accepted 0, persistence `notAttempted`로 종료하며 어떤 group도 보내지 않는다.
6. group dispatch 직전에 cancellation을 확인하고 PDF 또는 RAW dispatcher를 순서대로 호출한다.
7. group이 failed이면 뒤 group을 중단한다. active call 완료 뒤 취소가 확인되면 뒤 group을 중단한다.
8. accepted unit에서 자동증가 update 대상과 현재 사용자의 이력 insert 대상을 계산해 `requiresPersistence`를 정한다. 둘 다 없으면 DB를 호출하지 않고 persistence를 `notAttempted`로 둔다.
9. `requiresPersistence == true`이면 필요한 자동증가와 발행 이력만 한 SQL transaction으로 저장하고 persistence를 `succeeded`/`failed`/`outcomeUnknown`으로 기록한다. 오류를 전달하고 가능한 경우 rollback한다.
10. commit 성공 시 대상 session snapshot과 선택 행 미리보기를 갱신한다.
11. 결과를 사용자에게 알리고 `finally`에서 busy flag와 UI lock을 해제한다.

출력 중 화면의 mutable 전역 데이터를 다시 읽지 않는다. 실패·취소 전에 accepted된 unit은 결과와 DB 저장 대상에 포함하고, failed 또는 보내지 않은 unit은 제외한다.

## 11. 오류와 취소

- 데이터 조회 실패: 기존 데이터를 빈 성공 결과로 바꾸지 않고 물리 상태 `failed`, accepted 0, persistence `notAttempted`와 원본 오류를 표시한다.
- 데이터/숫자 설정 validation, workbook 없음/decode/materialize/build 오류: 첫 OS call 전에 대상 item/copy/column을 표시하고 물리 상태 `failed`, accepted 0, persistence `notAttempted`로 전체 발행을 중단하며 어떤 group도 보내지 않는다.
- printer 미선택 또는 제거: 설정을 요청하고 물리 상태 `failed`, accepted 0, persistence `notAttempted`로 출력하지 않는다.
- 첫 group 실패: `failed`, accepted unit 0으로 종료하고 DB를 변경하지 않는다.
- 앞 group accepted 후 다음 group 실패: `partiallyAccepted`로 표시하고 accepted unit만 DB에 반영한다.
- 준비 중 또는 첫 group 전 취소: 뒤 group을 보내지 않고 accepted unit 0의 `cancelled`로 종료한다.
- 일부 group이 accepted된 뒤 group 사이 취소: 뒤 group을 보내지 않고 `partiallyAccepted`로 종료한다.
- active OS call 중 취소: call을 중단하지 않고 결과를 기다린다. call 결과를 먼저 accepted/failed로 반영하고, 미전송 group이 남아 있으면서 accepted unit이 있으면 `partiallyAccepted`, accepted unit이 없으면 call 실패 여부에 따라 `failed` 또는 `cancelled`로 종료한다.
- 마지막 group이 이미 accepted되어 미전송 unit이 없는 뒤 취소 요청이 확인되면 `completed`로 종료하고 이미 접수됐음을 안내한다.
- 자동증가/이력 SQL 실패: 물리 출력 결과와 구분해 표시하고 가능한 rollback만 수행한다.
- 화면 동기화 실패: DB 저장 성공과 구분해 표시하고 현재 session reload를 안내한다.

- inline editor open/commit 중에는 `hasActiveEditing == true`, 셀 focus/row 선택만 있으면 `false`
- 마우스 tab 선택, `F3`, programmatic 선택 각각에서 active cell edit, draft command busy 또는 `isDirty` 라벨출력 전환 차단과 품목관리 탭 유지
- 차단 안내는 요청당 한 번이고 자동 저장·자동 취소가 발생하지 않으며, label-print activation/row load/preview/printer 조회/command 생성이 호출되지 않음
- 저장 또는 변경 취소 완료 후 active editing/command busy/dirty가 모두 해소되면 라벨출력 전환 허용
- active-edit 조건 추가가 기존 브랜드·라벨크기·출력 미리보기 context-change 동작을 변경하지 않음
- 미저장 draft 값은 검색·미리보기·materialize·출력 command에 포함되지 않음
- 첫 행 선택, 선택·설정 변경 미리보기
- 검색 영역과 exact-match 선택
- `[프린터 설정] 프린터명 [발행]` 순서
- 발행 중 취소 button과 중복 발행 차단
- 설정 dialog의 항목, `[취소] [적용]`, 내부 발행/매수 없음
- printer 미선택 시 `[적용]` 비활성화와 preference/command-wide session/row 미변경
- 설정 적용 시 command-wide printer/extra area/방향을 갱신하고 모든 row에서 margin/push/line spacing의 preference fallback만 갱신하며 copies, label-size fallback과 item/session 값을 유지
- 설정 적용 후 선택 행 preview가 command-wide 설정과 row 설정을 모두 반영하고 `[취소]` 시 preference/command-wide session/row를 모두 유지
- preference 전체 없음/저장 printer 제거 시 기존 공용 기본값과 printer 미선택 상태
- 900x600과 일반 desktop viewport overflow 없음
- non-Windows에서 tab/command 미노출

## 14. 구현 순서

1. 품목관리 발행 체크를 controlled state로 올리고 `FortuneTableEditingController`/`ItemManageController`의 read-only active-edit 상태와 label-print target 전용 gate를 연결한 뒤 출력 row/session model을 구현한다. 기존 공용 context-change gate의 다른 호출부는 변경하지 않는다.
2. 품목 출력 materializer와 읽기 전용 preview를 공용 API로 추출한다.
3. right margin/signed push, 1:1 source 배치·공용 방향 transform과 줄간격을 기존 공용 설정·print job에 최소 확장한다.
4. 라벨출력 화면, table, 검색, 선택과 자동 미리보기를 구현한다.
5. 기존 PDF/EZPL dispatcher를 공용 service로 추출하고 단일 row·copy 출력을 연결한다.
6. 여러 row/copy와 page spec group 출력을 연결한다.
7. 자동증가와 발행 이력 transaction, commit 후 session snapshot 동기화를 구현한다.
8. focused test, analyze, 전체 test와 실제 printer 수동 검증을 수행한다.

각 단계는 관련 focused test를 통과한 뒤 다음 단계로 진행한다.

## 15. 완료 조건

- `라벨출력(F3)` 탭이 실제 화면으로 동작한다.
- 품목관리 inline editor open/commit 중, item draft command busy 또는 미저장 draft 상태에서는 어떤 진입 경로로도 라벨출력 탭을 활성화하지 않고 저장·취소 안내 후 품목관리 탭을 유지한다.
- 차단된 전환은 label-print 화면 activation, 데이터 load, preview, printer 조회와 command 생성을 실행하지 않으며 기존 다른 context-change 동작을 변경하지 않는다.
- 라벨출력 검색·미리보기·출력은 마지막으로 저장·조회된 품목 baseline만 사용하고 draft working value를 사용하지 않는다.
- 품목관리 발행 체크 행만 출력 목록에 나타나고 item ID 기준으로 동기화된다.
- 발행 체크를 해제한 row의 session edit는 폐기되고 재체크하면 현재 field별 item baseline/override 또는 label-size/printer preference fallback으로 다시 초기화된다.
- 행별 매수·크기·여백·밀기·줄간격이 레거시 우선순위로 초기화되고 session에서 편집된다.
- 출력 row는 field별 item baseline/override 또는 label-size/printer preference fallback으로 초기화되고 라벨출력 session edit가 최종값이 되며 품목관리 미저장 draft를 사용하지 않는다.
- 프린터 설정에서 printer 미선택이면 `[적용]`을 비활성화하고 아무 설정도 저장·갱신하지 않는다. 선택 후 적용하면 command-wide printer/extra area/방향과 모든 출력 row의 margin/push/line spacing 중 `preference fallback` 출처만 갱신하며 copies, width/height와 같은 row의 item override/label-size fallback/session edit는 유지한다.
- 줄간격 inline UI는 `null`을 `0`으로 표시하고 빈 값/`0`을 `session edited null`로 commit하며, preference의 `none`/레거시 `0`과 내부 `null` round-trip에서 명시적 100을 보존한다.
- 선택 행의 실제 출력 미리보기가 자동 표시되고 품목관리와 같은 materializer를 사용한다.
- 검색은 발행 목록의 레거시 exact 대상만 선택하며 자동 발행하지 않는다.
- 공용 printer 설정과 현재 hosted `printing`/PDF/EZPL/RAW engine을 재사용한다.
- source physical 크기는 preview/PDF/EZPL에서 확대·축소 없이 유지되고 row 크기는 page와 clip에만 사용된다.
- vertical content는 확정한 시계 방향 corner mapping으로 preview/PDF/EZPL에서 동일하게 출력된다.
- 유효 출력 폭이 없거나 source가 label clip과 만나지 않으면 물리 출력 전에 차단된다.
- command-wide resolved backend에서 같은 최종 page spec의 인접 unit은 순서를 유지해 group 출력되고 spec이 다르면 분리된다.
- 모든 unit의 projection과 materialize/group payload 생성을 첫 OS call 전에 완료하고 하나라도 실패하면 어떤 group도 보내지 않는다.
- 실제 출력의 모든 날짜·시간/time-barcode projection은 command의 단일 `requestedAt`을 사용한다.
- 취소 또는 group 실패 시 active call 결과를 보존하고 뒤 group을 보내지 않는다.
- 첫 group 전 취소는 `cancelled`, 일부 accepted 후 취소는 `partiallyAccepted`, 모든 unit accepted 후 늦은 취소는 `completed`로 종료한다.
- accepted unit에서 실제 자동증가 update 또는 이력 insert 대상이 있을 때만 필요한 작업을 한 transaction으로 저장하고, 둘 다 없으면 DB를 호출하지 않는다.
- PDF/RAW API 결과는 group 전체 unit 단위로 accepted/failed에 반영되고 API가 제공하지 않는 page별 결과는 추적하지 않는다.
- unsupported profile과 명시적 `FILE:`/`PORTPROMPT:` port만 발행 전 PDF capability fallback으로 처리한다. port 조회 `null`은 file port가 아니므로 EZPL profile은 RAW를 선택하고, EZPL build 또는 RAW send 실패 뒤 PDF를 재전송하지 않는다.
- label-size에 autoInc column이 하나라도 있으면 모든 출력 row의 accepted copy별 이력을 저장하고, brand 이력 값은 command snapshot을 사용한다.
- 발행 이력의 column name, 출력 projection, 자동증가 미적용 DB baseline wire와 status detail column mapping이 레거시 순서를 따른다.
- 기존 세 이력 table은 명시한 레거시 insert field만 command/row/history snapshot에서 채우며 새 schema를 가정하지 않는다.
- command의 `(columnOrder, columnId)` 정렬과 연속 `detailIndex`가 wire/status detail/SQL JSON에서 동일하게 유지되고 SQL은 이를 재계산하지 않는다.
- 라벨 projection의 `requestedAt`과 발행 이력의 단일 SQL `@historyAt`을 구분한다.
- SQL 오류를 context와 함께 사용자에게 전달하고 가능한 경우 rollback하며 자동 재출력하지 않는다.
- 자동증가와 발행 이력은 기존 `jsonEncode` parameter/`OPENJSON` 패턴의 단일 `DbTransactionStatement` batch로 저장한다.
- commit 결과가 불명확하면 저장 실패로 단정하지 않고 `DbCommitOutcomeUnknown`과 원본 오류를 전달한다.
- SQL 저장 실패나 commit 결과 불명은 물리 dispatch 상태와 accepted 매수를 변경하지 않고 별도로 표시한다.
- SQL 오류 문구는 실제 transaction에 포함된 자동증가 update와 이력 insert 대상만 표시한다.
- persistence 결과는 `notAttempted`/`succeeded`/`failed`/`outcomeUnknown`으로 구분하고 실패·불명에는 원본 오류를 보존한다.
- DB migration, local printing fork, native plugin 개조, durable recovery 기능을 추가하지 않는다.
- Windows desktop에서만 기능을 노출한다.
- 관련 focused test, `flutter analyze`, 전체 `flutter test`, `git diff --check`가 통과한다.
