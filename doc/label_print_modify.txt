# 라벨출력 탭 구현 작업지시서

## 0. 최우선 원칙

- 이 문서는 `doc/label_print.txt`를 대체하는 구현 기준이다.
- 동작 기준은 레거시 `.tmp/LabelManager`의 `LabelPrintDlg`, `LabelPrintModel`, `SearchPrintDlg`와 현재 Flutter 앱의 품목관리 미리보기·공용라벨 인쇄 구현이다.
- 레거시의 데이터 선택, 출력 작업 목록, 매수, 자동증가, 검색 대상, 발행 이력 의미는 유지한다.
- 화면은 현재 앱의 디자인과 공용 위젯에 맞춘다. MFC SpreadSheet, RichEdit, XPS 미리보기 구현을 그대로 옮기지 않는다.
- 현재 LabelSheet/FortuneSheet workbook을 유일한 라벨 렌더 원본으로 사용한다. 새 RTF 치환·인쇄 엔진을 만들지 않는다.
- 보완·예외 처리를 과도하게 추가하지 않는다. 실제 구현에 필요한 model, DAO, 공용 API만 작성한다.
- SQL은 parameterized query를 사용한다. SQL Server 오류는 사용자에게 전달하고 활성 transaction은 가능한 경우 rollback한다.
- SQL Server table, column, index, trigger, procedure를 생성·변경·삭제하지 않고 data/schema migration도 구현하지 않는다.
- 레거시 소스와 실행 파일은 읽기 전용 참조다. `.tmp/LabelManager`를 수정하지 않는다.
- 이번 기능은 Windows desktop 전용이다. 다른 platform에는 라벨출력 탭과 발행 command를 노출하지 않는다.
- 동일 품목의 자동증가 라벨을 여러 client/PC에서 동시에 발행하는 경우는 지원하지 않는다. 앱 instance 내부 중복 발행만 차단하며 server 번호 예약이나 client 간 lock은 구현하지 않는다.
- 배포 build, installer 생성, 원격 push는 별도 요청이 있을 때만 수행한다.

이 문서에서 `출력 작업 접수 성공`은 Windows 출력 API가 해당 print job을 오류 없이 반환했다는 뜻이다. PDF는 `Printing.directPrintPdf()`가 `true`를 반환한 경우, RAW는 `StartDocPrinter`부터 `EndDocPrinter`까지 성공한 경우를 `accepted`로 판정한다. file/interactive PDF port에서 사용자가 취소한 것으로 확인된 `false`와 API 호출 전 사용자 취소만 `cancelled`로 판정한다. 일반 direct printer의 `false`, 취소 여부를 확인할 수 없는 `false`, RAW API 실패와 exception은 `failed`다. 현재 PDF API는 Windows spooler job ID나 실제 queue 등록을 보장하지 않으므로 그 이상을 성공 조건으로 표현하지 않는다. 실제 용지 출력 완료, 용지 부족, API 반환 이후 printer 오류까지 보장하지 않는다. 발행 이력과 자동증가 DB 반영은 이 API 접수 성공을 기준으로 한다.

## 1. 구현 목적

- 메인 `라벨출력(F3)` placeholder를 실제 라벨 발행 화면으로 교체한다.
- 품목관리에서 `발행`이 체크된 품목을 출력 작업 목록으로 가져온다.
- 출력 작업 행을 선택하면 오른쪽에 해당 품목의 실제 출력 workbook을 자동 표시한다.
- 행별 발행매수와 레거시 출력 override를 적용해 여러 품목을 한 번에 발행한다.
- 공용라벨관리의 프린터 설정과 현재 PDF/EZPL 출력 엔진을 공용화해 같은 프린터 선택·여백·방향·추가 영역 설정을 사용한다.
- 물리 출력 설정별 print job 가운데 실제 `accepted`된 unit만 자동증가 값과 레거시 발행 이력에 반영한다.

## 2. 확인한 레거시 동작

### 2.1 출력 작업 목록

레거시 `CLabelPrintModel::SetPrintDatasByItemTable()`은 품목관리의 `IsCheckToPrint()` 행만 출력 목록으로 가져온다. 출력 목록은 단순 품목 목록이 아니며 다음 값을 가진 별도 작업 목록이다.

1. 발행매수
2. 라벨크기명
3. 품명
4. 출력 폭
5. 출력 높이
6. 왼쪽 여백
7. 오른쪽 여백
8. 위쪽 여백
9. 왼쪽 밀기
10. 위쪽 밀기
11. 줄간격

행의 기본값은 `BM_ITEM_OF_MARKET` override를 우선하고, override를 사용하지 않으면 현재 라벨크기와 프린터 설정 기본값을 사용한다. 출력 화면에서 수정한 값은 출력 session에만 적용하며 품목관리 원본 설정을 일반 저장하지 않는다.

발행매수 `0`은 개별 행에서 허용한다. 전체 출력 작업의 발행매수 합계가 `0`이면 발행하지 않고 안내한다. 음수와 숫자가 아닌 값은 허용하지 않는다.

### 2.2 선택과 미리보기

- 출력 목록을 만든 뒤 첫 행을 선택한다.
- 선택 행이 바뀌면 별도 버튼 없이 미리보기를 다시 만든다.
- 행의 출력 크기·여백·방향 등 미리보기에 영향을 주는 session 값이 바뀌면 같은 행 미리보기를 갱신한다.
- 레거시의 `미리보기` 버튼은 별도 OS 미리보기 창을 여는 기능이지만, 새 화면은 오른쪽에 항상 실제 출력 미리보기를 표시하므로 배치하지 않는다.
- 레거시 zoom 20~500%, +/-와 배경 전환은 필수 출력 의미가 아니다. 현재 공용 미리보기의 zoom/pan을 사용하고 중복 zoom control을 만들지 않는다.

### 2.3 발행

- 프린터가 선택되지 않았으면 발행하지 않고 프린터 설정을 요청한다.
- copies가 1 이상인 모든 row/copy를 순서가 고정된 `LabelPrintUnit`으로 펼친다. copies가 0인 행은 unit, payload, 자동증가 projection과 이력을 만들지 않는다.
- 자동증가가 없는 행은 같은 materialize 결과를 재사용할 수 있지만 각 unit은 항상 한 장만 나타낸다. 자동증가가 있는 행은 copy index별 값으로 workbook을 materialize한다.
- 모든 unit의 materialize·capture와 모든 job payload 생성을 먼저 완료한 뒤 첫 물리 출력 job을 전송한다.
- unit 순서를 유지하면서 인접 unit의 `(printer, backend, widthMm, heightMm, extraAreaMm, orientation)`이 같을 때만 같은 `LabelPrintJobGroup`으로 묶는다. profile이 바뀌면 새 group을 시작하며 뒤에서 같은 profile이 다시 나와도 앞 group으로 이동시켜 출력 순서를 바꾸지 않는다.
- PDF group은 같은 물리 page format의 page를 한 PDF document로 만들고 `directPrintPdf`를 한 번 호출한다. EZPL group은 같은 물리 설정의 label command를 한 RAW document payload로 만들고 `sendRaw`를 한 번 호출한다.
- group을 unit 순서대로 전송한다. 한 group이 `cancelled` 또는 `failed`이면 뒤 group을 전송하지 않는다. 이미 `accepted`된 group의 unit만 발행 완료 대상으로 확정한다.
- 전송이 끝나거나 중단된 뒤 `accepted` unit의 발행 이력과 자동증가 최종값을 하나의 DB transaction으로 저장한다. 첫 group부터 접수되지 않았다면 DB를 변경하지 않는다.
- 레거시는 발행 후 현재 선택 행의 미리보기를 다시 만든다.

### 2.4 검색

레거시 `CSearchPrintDlg` 검색 대상은 다음과 같다.

- 현재 label size의 품명과 입력 문자열이 같은 품목
- `TColumn.searchPrint == true`인 컬럼의 content와 입력 문자열이 같은 품목

레거시는 검색 성공 즉시 첫 결과를 발행하지만 새 화면에서는 검색이 곧 물리 출력으로 이어지지 않게 한다. 검색 범위는 현재 발행 체크된 출력 작업 목록으로 제한한다. 같은 검색 대상과 exact-match 의미를 사용해 첫 일치 행을 선택하고 미리보기만 갱신한다. 실제 출력은 반드시 사용자가 `발행`을 눌러 실행한다.

## 3. 현재 Flutter 구현과 재사용 경계

### 3.1 그대로 재사용할 데이터

- `ItemOfMarketDAO.selectByItemOfMarketAndLabelSizeId()`
- `TColumnDAO.selectByLabelSizeId()`
- `TColumnContentDAO.selectScopedByItemIds()`
- 현재 label size, customer, market, user session
- `ItemManagerDraftController`의 현재 품목 working value
- `LabelPrinterPreferences`
- `LabelSheetPrintOptions`, `LabelSheetPrintPageMetrics`
- `RawPrinterWin32`, `PrinterProfile`, PDF/EZPL builder

라벨출력 탭을 열 때 위 데이터를 동일 label-size session에서 이미 읽었다면 다시 조회하지 않는다. label size가 바뀌거나 품목 저장·공용라벨 저장이 완료되면 상위 session reload 결과로 출력 목록과 미리보기를 갱신한다.

현재 `LabelSheetPrintOptions`에 없는 오른쪽 여백, signed push, 행별 줄간격과 여러 unit/job group payload는 기존 option/job builder를 공용 확장해 지원한다. 라벨출력 wrapper에서 좌표·줄간격·PDF/EZPL 결합 로직을 따로 만들거나 지원하지 않는 값을 무시하지 않는다.

### 3.2 공용 API로 추출할 기능

현재 다음 기능은 `home_page_manager.dart` 또는 `label_sheet_workbench.dart`의 private 구현이므로 복사하지 말고 소유 모듈의 공용 API로 추출한다.

1. 품목 출력 workbook materialize
   - 현재 `_itemOutputPreview()`와 keyword/text/barcode/image replacement helper를 `lib/printing` 또는 `lib/page_home`의 공용 service로 이동한다.
   - 품목관리 `출력내용 미리보기`와 라벨출력 탭이 같은 함수와 입력 DTO를 사용해야 한다.
2. 읽기 전용 출력 미리보기
   - 현재 `_ItemOutputPreviewTab`의 표시 로직을 공용 widget으로 추출한다.
   - 원본 workbook을 수정하지 않고 매번 private copy를 렌더한다.
3. 프린터 설정 로직
  - `_LabelSheetPrintSettingsDialog`에서 preference load/save, printer picker, 입력 parsing/validation을 공용 controller/service와 공용 field widget으로 추출한다.
  - 공용라벨과 라벨출력 화면이 같은 preference key와 printer resolver를 사용한다.
  - 라벨출력은 공용라벨 dialog를 화면째 재사용하지 않고 4.4의 전용 설정 UI를 작성한다.
4. 실제 출력 dispatcher
   - 현재 `_handleIssuePrintSettings()`의 프린터 확인, DPI, PDF fallback, EZPL raw 출력 분기를 공용 service로 추출한다.
   - UI context와 SnackBar는 호출부가 소유하고 dispatcher는 typed result 또는 exception을 반환한다.

공용 dispatcher를 추출할 때 `RawPrinterWin32.sendRaw()`는 `StartDocPrinter`가 반환한 job ID를 결과에 포함하고 `StartPagePrinter`, `WritePrinter`, `EndPagePrinter`, `EndDocPrinter` 반환값을 모두 검사하도록 확장한다. PDF dispatcher는 `directPrintPdf`의 `true`/`false`/exception을 0절의 기준으로 mapping하고 job ID가 없음을 정상 결과로 표현한다.

## 4. 화면 구성

### 4.1 전체 레이아웃

- 상단 메인 검색 영역은 `라벨출력` 탭에서도 표시한다.
- 본문은 왼쪽 출력 작업 표와 오른쪽 미리보기의 2영역으로 구성한다.
- 넓은 화면에서는 좌우 분할을 사용하고 사용자가 splitter로 폭을 조정할 수 있게 한다.
- 좁은 화면에서는 표와 미리보기를 겹치지 않게 세로 배치하거나 탭 전환으로 표시한다.
- 하단 command bar는 전체 폭을 사용하며 왼쪽부터 `[프린터 설정]  선택된 프린터명  [발행]` 순서로 배치한다.
- 선택된 프린터명은 읽기 전용이며 긴 이름은 말줄임과 tooltip을 제공한다.
- `발행`은 출력 작업 존재, 전체 매수 합계 1 이상, 선택 프린터 존재, 출력 중 아님 조건에서만 활성화한다.
- Windows가 아닌 platform에서는 이 화면 자체를 구성하지 않는다.

### 4.2 왼쪽 출력 작업 표

- 품목관리와 같은 `FortuneTable`/공용 table style, row header, 선택 색상, keyboard navigation을 사용한다.
- `ItemManage` 전체를 재사용해 품목 추가·삭제·Excel·저장 footer까지 노출하지 않는다. 공용 table abstraction 또는 라벨출력 전용 widget을 작성한다.
- 표 컬럼은 2.1의 레거시 11개 항목을 기본으로 한다.
- 발행매수와 숫자 override만 inline 편집한다. 라벨크기명과 품명은 읽기 전용이다.
- 행 선택은 단일 선택이다. 여러 행의 출력 포함 여부는 품목관리의 `발행` 체크 상태가 결정한다.
- 표에서 바꾼 session 값은 DB에 저장하지 않는다.
- 품목관리의 발행 체크가 바뀌면 출력 목록을 item ID 안정 key로 동기화한다.
  - 새 체크 행은 현재 item order 위치에 추가한다.
  - 체크 해제 행은 출력 목록에서 제거한다.
  - 남아 있는 행의 사용자가 수정한 session 값과 선택은 유지한다.
  - 각 editable 물리 값은 `item override`, `preference fallback`, `session edited` 출처를 가진다.
  - 프린터 설정 변경 시 `preference fallback` 출처 값만 다시 계산한다. item override와 session edited 값은 덮어쓰지 않는다.

### 4.3 오른쪽 미리보기

- 선택 행이 없으면 `발행할 품목을 선택하세요.` 안내를 표시한다.
- 저장된 공용라벨 workbook이 없으면 빈 미리보기와 저장 필요 안내를 표시한다.
- 레거시 RTF만 있고 현재 workbook으로 변환되지 않은 라벨은 기존 품목 미리보기와 같은 `라벨을 편집 저장 후 가능합니다.` 안내를 표시한다.
- 선택 행 또는 출력 설정이 바뀌면 debounce 없이 다음 안정 frame에 미리보기를 갱신한다.
- 미리보기는 5.2의 page 크기, clip 영역, margin+push 좌표와 유효 줄간격을 실제 출력과 동일하게 적용한다.
- 미리보기는 읽기 전용이다. 셀 편집, 저장, 이미지/바코드 삽입, 인쇄 toolbar를 노출하지 않는다.
- 미리보기 전용 `미리보기` 버튼은 추가하지 않는다.

### 4.4 프린터 설정

- preference, printer picker, parsing/validation 공용 로직을 사용해 라벨출력 전용 설정 dialog를 작성한다.
- 전용 dialog에는 매수와 내부 `발행` 버튼을 두지 않는다. 매수는 출력 작업 행이 소유하고 실제 발행은 화면 하단 command bar에서만 실행한다.
- 지원 항목은 선택 프린터, 왼쪽/위쪽 여백, 자동 줄간격, 추가 영역, 가로/세로 방향이다.
- dialog 하단에는 `[취소] [적용]`만 배치한다. `적용`은 preference 저장만 하고 물리 출력하지 않는다.
- 라벨출력 화면의 하단 `발행`이 실제 출력 command의 유일한 진입점이다.

## 5. 상태와 model

필요 model을 `lib/models/label_print.dart`에 작성한다. 기존 mutable 전역 목록에 라벨출력 전용 상태를 추가하지 않는다.

### 5.1 `LabelPrintRowDraft`

최소 필드:

- stable `itemId`
- 원본 `ItemOfMarket`
- `copies`
- `widthMm`, `heightMm`
- `leftMarginMm`, `rightMarginMm`, `topMarginMm`
- `leftPushMm`, `topPushMm`
- `lineSpacing`
- 각 editable 물리 값의 `item override`/`preference fallback`/`session edited` 출처

생성 규칙:

- copies는 `TColumnType.TYPE_PRINTCOUNT` content가 있으면 그 값을 우선하고, 없으면 `ItemOfMarket.printCount`를 사용한다.
- item별 label size 사용 시 `labelSizeWidth/labelSizeHeight`, 아니면 현재 공용라벨 physical size를 사용한다.
- item별 margin 사용 시 item 값을, 아니면 현재 프린터 preference 값을 사용한다.
- item별 linefeed 사용 시 item 값을, 아니면 공용 설정 값을 사용한다.
- 모든 숫자 단위는 필드명으로 명시한다. 레거시 정수 단위와 현재 mm/logical pixel을 암묵적으로 섞지 않는다.

입력 규칙:

- `copies`: 정수, 0 이상. 개별 0은 허용하고 전체 합계는 1 이상이어야 한다.
- `widthMm`, `heightMm`: 양의 정수 mm.
- `leftMarginMm`, `rightMarginMm`, `topMarginMm`: 0 이상의 실수 mm.
- `leftPushMm`, `topPushMm`: signed 실수 mm. 음수는 왼쪽/위쪽 반대 방향 이동을 의미한다.
- `lineSpacing`: 정수 percent, 30~300. item override와 session edit가 없을 때 전역 `autoSpacingPercent`를 사용하며 전역 값도 없으면 100으로 계산한다.
- 소수 mm는 double로 유지하고 dot 변환 시 기존 DPI 기준으로 가장 가까운 정수에 반올림한다. margin은 음수 clamp를 적용하지만 push에는 clamp를 적용하지 않는 signed dot 변환 helper를 사용한다.
- 총 copies 합계는 1000 이하여야 한다. 각 unit의 DPI 적용 후 RGBA raster 예상량 `widthDots * pageHeightDots * 4`의 합과 최종 payload 예상량을 합친 보수적 예상 working set은 256 MiB 이하여야 한다.
- payload 생성 후 실제 payload byte 합계가 256 MiB를 넘으면 첫 물리 출력 전에 전체를 중단한다. 이 제한은 UI와 command validation 양쪽에서 적용하며 초과 작업은 여러 번 나누어 발행하도록 안내한다.

### 5.2 물리 출력 계산

- 회전 전 logical page 폭은 row `widthMm`, label 영역 높이는 `heightMm`, feed가 포함된 logical page 높이는 `heightMm + extraAreaMm`이다. `extraAreaMm`은 label content를 늘리지 않고 feed/page 뒤쪽만 연장한다.
- 저장 workbook의 print area는 row `widthMm x heightMm` 출력 bitmap으로 capture한다. 그 뒤 margin이나 push에 맞추기 위해 bitmap을 다시 축소·확대하지 않는다.
- 회전 전 content 원점은 `x = leftMarginMm + leftPushMm`, `y = topMarginMm + topPushMm`이다. signed push로 원점이 음수가 될 수 있다.
- 회전 전 label clip rectangle은 `left=0`, `top=0`, `right=widthMm-rightMarginMm`, `bottom=heightMm`이다. content를 원점에 배치한 뒤 이 사각형과 page 밖을 자르며, `extraAreaMm` 영역에는 content를 그리지 않는다.
- `leftMarginMm + rightMarginMm < widthMm`, page 높이와 clip 영역이 양수이고, 이동한 content rectangle과 label clip rectangle의 교집합이 양수여야 한다. 교집합이 없으면 물리 출력 전에 validation 오류로 처리한다.
- 유효 줄간격은 `session edited 또는 item useLinefeed 값 > 전역 autoSpacingPercent > 100` 순서로 결정한다.
- `fortune_sheet`에 immutable `FortuneOutputLayoutOptions({required int lineSpacingPercent})` 공용 출력 option을 추가하고 preview/capture/painter가 이를 받게 한다. 기본값은 100이며 줄간격 percent는 레거시 `RTFLineSpacer`와 같이 여러 줄 text paragraph의 line height에만 적용한다. row height, font size와 자동 줄바꿈 폭은 바꾸지 않는다. 공용라벨 자동줄간격도 같은 API를 사용하고 wrapper별 별도 계산은 두지 않는다.
- `horizontal`은 위 logical 좌표와 page 크기를 그대로 사용한다. `vertical`은 margin·push·clip·content를 포함한 완성 logical page 전체를 시계 방향 90도 회전하고 물리 page 폭·높이를 서로 바꾼다. PDF page format, Windows media profile, EZPL raster/native border/barcode가 같은 affine transform을 사용해야 한다.

### 5.3 `LabelPrintSessionController`

최소 책임:

- checked item ID와 출력 row 동기화
- item ID 기반 선택 유지
- row-local copies/size/margin/line-spacing 수정
- 검색 cursor와 exact-match 선택
- 총 발행매수 계산
- 출력 중 편집·중복 발행 차단
- label size/session 교체 시 이전 출력 row와 selection 폐기

### 5.4 출력 command/result

다음 immutable DTO 또는 동등 구조를 둔다.

- `LabelPrintCommand`: label/customer/market/user identity, printer, preference snapshot, row snapshot, column/content snapshot, saved label workbook snapshot
- `LabelPrintUnit`: item ID, row index, copy index, materialize에 사용할 column value projection. 한 unit은 정확히 한 장이며 unit-level print option의 copies는 항상 `1`이다.
- `LabelPrintJobProfile`: printer, PDF/EZPL backend, 회전 적용 후 physical width/height, extra area, orientation
- `LabelPrintJobGroup`: 순서가 연속되고 profile이 같은 unit과 그 단일 PDF 또는 RAW payload. unit 순서를 바꾸거나 비연속 group을 합치지 않는다.
- `LabelPrintDispatchResult`: group-level `accepted`/`cancelled`/`failed`, printer와 optional job ID, 오류. PDF job ID는 `null`을 허용한다.
- `LabelPrintResult`: 전체 요청 행·매수, group별 접수 결과, accepted unit/매수, DB 저장 결과와 aggregate outcome `completed`/`partiallyAccepted`/`cancelled`/`failed`/`dbFailed`. printer가 알려주지 않는 page/copy별 실제 출력 성공은 만들지 않는다.

버튼 클릭 시 command snapshot을 한 번 만들고 출력 도중 화면의 mutable 전역 데이터를 다시 읽지 않는다.

## 6. 데이터 조회와 DAO

### 6.1 기존 DAO 재사용

품목 목록, 컬럼 정의와 content 조회를 위해 새 SELECT DAO를 만들지 않는다. 다음 기존 DAO를 사용한다.

- `ItemOfMarketDAO`
- `TColumnDAO`
- `TColumnContentDAO`

검색도 현재 label-size session에 모든 대상 품목과 content가 있으므로 메모리에서 수행한다. 검색만을 위한 문자열 조립 SQL이나 `LabelPrintSearchDAO`를 추가하지 않는다.

### 6.2 자동증가 DAO

현재 앱에는 레거시 출력 자동증가 저장 경계가 없으므로 `LabelPrintAutoIncrementDAO`를 작성한다.

- 순수 함수가 원본 문자열, 증가 크기, 증가 범위, 앞자리 0 제거, barcode/check-digit/time-barcode 설정, copy index를 받아 출력값과 다음 저장값을 계산한다.
- `autoInc == false`인 컬럼은 변경하지 않는다.
- 각 copy는 copy index에 대응하는 값을 렌더한다.
- 활성 레거시의 최종 DB 상태만 재현하고 copy별 중간 DB update는 재현하지 않는다.
- 해당 자동증가 column의 unit이 `accepted`된 경우에만 최종값을 저장한다. `autoIncSave == true`이면 마지막 accepted copy 다음 값을, `autoIncSave == false`이면 마지막 accepted copy에 실제 출력한 값을 저장한다.
- `autoIncUpdate`는 활성 레거시 구현에서 결과에 영향을 주지 않으므로 라벨출력에서는 사용하지 않는다. column 편집 필드는 유지하되 projection/저장 분기에 넣지 않는다.
- job 취소 또는 접수 실패 시 자동증가 DB 값을 변경하지 않는다.
- 저장 대상은 `(columnId, itemId)` 정확히 한 행이며 affected row를 검증한다.
- 현재 DB에 해당 item/content가 없으면 임의 insert하지 않고 오류로 전달한다.
- 바코드 payload 계산은 기존 `BarcodeDataHelper`, `ItemCodeDataResolver`, date/time helper를 재사용한다.
- 화면 미리보기는 copy index 0의 projection을 사용하고 DB 값을 변경하지 않는다.
- 여러 client/PC가 같은 `(columnId, itemId)`를 동시에 발행하는 번호 예약·충돌 방지는 이번 범위에 포함하지 않는다. 같은 앱 instance에서는 출력 busy gate로 중복 발행을 차단한다.
- `ItemManagerDraftController.applyCommittedColumnContentUpdates(...)` public API를 추가한다. DB transaction commit 성공 후 이 API가 자동증가 대상 `(columnId,itemId)`의 scoped 원본과 working value를 commit 값으로 교체하고 해당 column draft만 정리한다. 다른 품목·컬럼의 draft와 선택은 유지하고 notify는 한 번만 수행한다.
- commit 결과가 불명확하거나 commit 후 draft 반영에 실패하면 재발행을 차단하고 사용자에게 DB 상태 확인과 session reload가 필요함을 알린다.

### 6.3 발행 이력 DAO

레거시와 같은 발행 이력이 현재 앱에 없으므로 `LabelPrintHistory` model과 `LabelPrintHistoryDAO`를 작성한다.

- 기존 물리 DB의 `BM_RICH_PRINT_LOG`, `BM_RICH_STATUS`, `BM_RICH_STATUS_DATA`만 사용한다.
- 앱 session 준비 또는 발행 command preflight에서 현재 배포 DB에 레거시 table/column이 존재하는지 읽기 전용으로 확인한다. 첫 print job 전 확인되지 않으면 발행을 차단한다.
- object가 없거나 구조가 레거시 계약과 다르면 DDL이나 migration으로 보정하지 말고 작업을 중단해 사용자에게 알린다.
- 문자열 연결 SQL을 사용하지 않고 parameterized JSON 또는 기존 driver가 지원하는 scalar parameter를 사용한다.
- `BM_RICH_PRINT_LOG`에는 user/market/customer/brand/label/item/printer, 접수 매수, 출력 컬럼명과 값, form 크기와 margin/push/extra area, item ID를 기록한다.
- 자동증가 행은 copy별 `printCount=1`과 실제 projected 값을 기록한다. 자동증가가 없는 행은 row별 copies 합계로 한 건을 기록한다.
- `RICH_PRINT_CELLS`에는 실제 payload에 사용한 projected 값을, `RICH_SAVE_IN_DB_CELLS`에는 job 시작 시점의 DB 원본값을 기록한다.
- `BM_RICH_STATUS`도 위와 같은 자동증가 copy/일반 row 단위로 기록하고 `BM_RICH_STATUS_DATA`에는 해당 이력의 동적 컬럼 값을 column ID/name과 함께 기록한다.
- history ID/order 생성은 customer 범위를 `UPDLOCK, HOLDLOCK`으로 잠근 뒤 수행한다. 자동증가 최종값 update, print log, status parent/detail insert는 하나의 SQL transaction에서 수행한다.
- 같은 출력 행의 detail은 column order로 저장한다.
- 관리자와 특수 로그인을 포함한 모든 사용자의 accepted unit을 발행 이력에 기록한다. 레거시의 로그 생략 조건은 적용하지 않는다.

이력 집계는 accepted unit만 대상으로 한다. copies가 0인 행, 실패·취소 group의 unit과 실패 이후 전송하지 않은 unit은 print log/status/detail 및 자동증가 update에 포함하지 않는다. 자동증가가 없는 한 row가 여러 accepted group으로 나뉘는 경우에도 같은 command 내에서는 row별 accepted copies 합계 한 건으로 기록한다.

물리 프린터 출력은 SQL transaction으로 rollback할 수 없다. print job 접수 후 DB 저장이 실패하면 `인쇄 작업은 접수되었으나 자동증가 값과 발행 이력을 저장하지 못했습니다.`로 분리해 알리고 자동 재출력하지 않는다. transaction은 가능한 경우 rollback하고 해당 session의 추가 발행을 차단한다.

## 7. 품목관리 발행 체크 연동

현재 `ItemManage`의 `_publishCheckedItemIds`는 widget private 상태다. 이를 출력 탭과 연결하도록 controlled API를 추가한다.

- `ItemManage`에 `publishCheckedItemIds`와 `onPublishCheckedItemIdsChanged` 또는 동등 controller API를 추가한다.
- 상위 `HomePageManager`가 현재 label-size session의 checked item ID를 소유한다.
- 품목관리 우클릭 `발행 체크/해제`, 개별 checkbox, 전체 해제가 모두 같은 callback을 통과한다.
- label size 변경, 품목 삭제, session reload에서 존재하지 않는 item ID를 제거한다.
- 품목관리 draft가 있으면 출력 materialize는 화면에 표시된 현재 working value를 사용한다.
- 활성 cell 편집이 남아 있으면 발행 command 전에 commit하고 validation 오류가 있으면 출력하지 않는다.
- 출력은 품목관리 draft 전체를 DB 저장하지 않는다. 자동증가 저장만 6.2의 명시적 DAO 경계에서 수행한다.
- 자동증가 transaction commit 후에는 6.2의 대상 content만 draft와 snapshot에 동기화하고 선택 행 미리보기를 commit된 DB 값 기준으로 다시 만든다. `autoIncSave=true`이면 마지막 accepted copy의 다음 값, `autoIncSave=false`이면 마지막 accepted copy에 출력한 값이 표시된다.

## 8. workbook materialize

### 8.1 source of truth

- 현재 label-size session에 마지막으로 저장·조회된 공용라벨 workbook을 사용한다.
- 공용라벨 편집 화면의 저장 전 mutable workbook을 몰래 참조하지 않는다.
- materialize는 항상 workbook private copy를 반환한다.

### 8.2 치환 규칙

품목관리 `출력내용 미리보기`와 완전히 같은 공용 materializer를 사용한다.

- `#ITEMNAME`: 품명
- `#ELEMENT`: 품목 working value의 주원료/함량 workbook 또는 text
- `# + TColumn.keyword`: 해당 item의 최종 column value
- 일반/날짜/시간: 기존 date format과 range 규칙으로 text 치환
- 바코드/QR/GS1: `ItemCodeDataResolver` 결과를 Fortune barcode object에 적용
- 연결 이미지: 현재 이미지 파일 resolver 결과를 Fortune image object에 적용하고 값/파일이 없으면 출력 workbook에서 제외
- 고정 이미지와 고정 바코드: 원본 workbook 값을 유지
- 라벨에 없는 keyword: 무시
- resolver 오류: placeholder를 실제 출력하지 말고 전체 사전 materialize를 중단해 사용자에게 item/copy/column 정보를 알린다.

미리보기와 실제 발행은 같은 `LabelPrintUnit`과 materializer를 사용해야 한다. 별도 문자열 치환 구현을 두지 않는다.

## 9. 검색 동작

- `itemManagerSearchVisibleForTab()` 또는 상위 검색 표시 규칙에 `label_print`를 추가한다.
- 검색 문자열은 빈 값이면 실행하지 않는다.
- 검색 대상은 현재 발행 체크되어 출력 작업 목록에 존재하는 행뿐이다.
- item order 순으로 다음 대상을 찾는다.
- 품명 exact match 또는 `searchPrint == true`인 column content exact match만 대상이다.
- exact 비교는 입력값과 대상값 양쪽의 앞뒤 공백을 제거하고 Unicode 소문자로 변환한 뒤 전체 문자열을 비교한다. 부분 포함 검색은 하지 않는다.
- 현재 품목관리 검색의 active-column `contains` 규칙을 라벨출력 검색에 그대로 사용하지 않는다.
- 일치 행이 있으면 출력 목록에 포함된 행을 선택하고 오른쪽 미리보기를 갱신한다.
- 일치 결과가 여러 개면 현재 선택 다음의 첫 행을 선택하고 끝에 도달하면 처음부터 한 번 찾는다.
- 일치 결과가 없으면 `발행 목록에서 일치하는 품목을 찾지 못했습니다.`를 표시한다. 전체 품목 DB를 추가 검색하거나 발행 체크를 자동 변경하지 않는다.
- 검색은 물리 출력이나 DB 변경을 실행하지 않는다.

## 10. 실제 출력 pipeline

1. table inline edit와 품목관리 pending edit를 확정한다.
2. 현재 label/customer/market session이 command snapshot과 같은지 확인한다.
3. 출력 row가 1개 이상이고 총 copies가 1~1000인지 확인한다. copies가 0인 row는 이후 단계에서 제외한다.
4. 선택 프린터가 실제 설치 목록에 존재하는지 확인한다.
5. 자동증가 update 대상과 발행 이력 DB schema/identity를 읽기 전용으로 preflight한다. 하나라도 불일치하면 아직 물리 출력하지 않은 상태에서 중단한다. 이 preflight와 물리 출력 사이에는 SQL transaction이나 lock을 유지하지 않는다.
6. saved workbook, item/column/content, printer preference의 immutable command를 만든다.
7. 각 row와 copy에 대해 순서가 고정되고 copies가 1인 `LabelPrintUnit`을 만든다.
8. 모든 unit의 자동증가 projection과 workbook materialize를 완료한다. 하나라도 실패하면 전체를 중단한다.
9. unit의 물리 크기와 printer DPI로 예상 working set이 256 MiB 이하인지 먼저 확인한다. 통과하면 모든 unit을 공용 layout/capture API로 bitmap과 print area로 만들고 순서를 유지한 `LabelPrintJobGroup` 및 payload를 전부 생성한다. 생성된 실제 payload byte 합계도 256 MiB 이하인지 확인하며 하나라도 실패하면 전체를 중단한다. 256 MiB는 `268435456` bytes로 계산한다.
10. group을 순서대로 dispatcher에 전달한다.
   - Windows raw EZPL 가능: group unit의 정밀 좌표 + EZPL border/barcode + raster fallback command를 한 RAW payload로 결합하고 각 label의 copies command는 `^P1`로 만든다.
   - file port 또는 raw 불가: group unit의 같은 physical page format page를 한 PDF로 결합하고 `directPrintPdf`에 해당 group의 명시적 `PdfPageFormat`을 전달한다.
11. group이 `accepted`이면 다음 group을 전송한다. `cancelled` 또는 `failed`이면 즉시 중단하고 뒤 group은 전송하지 않는다.
12. accepted unit이 없으면 DB를 변경하지 않고 종료한다.
13. accepted unit이 있으면 그 unit만 기준으로 자동증가 최종값과 발행 이력을 하나의 SQL transaction으로 저장한다. 이후 group이 실패했더라도 이미 accepted된 unit은 이 transaction에 반영한다.
14. commit 성공 후 자동증가 대상 draft/snapshot만 동기화하고 선택 행 미리보기를 commit된 DB 값으로 갱신한다.

다중 품목을 위해 OS printer picker나 설정 dialog를 group마다 열지 않는다. 한 번 선택한 printer와 command snapshot으로 group을 순차 실행한다. 중복 `발행` 클릭은 무시한다. 출력 API가 accepted를 반환한 뒤 실제 printer가 일부 page만 출력하는 상황은 앱이 판정하거나 이력을 부분 보정하지 않는다.

## 11. 오류와 취소

- 조회 실패: 기존 데이터를 성공처럼 비우지 말고 조회 오류를 표시한다.
- workbook decode 실패: 발행 버튼을 비활성화하고 라벨 저장 필요 또는 데이터 오류를 표시한다.
- 프린터 미선택/제거: 설정을 요청하고 출력하지 않는다.
- materialize/capture/payload 생성 실패: 해당 item/copy/column을 표시하고 물리 출력 전에 전체 중단한다.
- 첫 print job 접수 실패·취소: 전체 미발행으로 처리하고 DB를 변경하지 않는다. 자동 재시도하지 않는다.
- 앞 group 접수 후 다음 group 실패·취소: 뒤 group 전송을 중단하고 이미 접수된 매수와 미접수 매수를 함께 표시한다. accepted unit의 DB 반영은 실행하되 실패 group을 자동 재시도하거나 자동 재출력하지 않는다.
- 자동증가/history DB 저장 실패: print job 접수 여부와 구분해 표시하고 가능한 rollback 후 오류를 전달한다. 자동 재출력하지 않고 추가 발행을 차단한다.
- 출력 도중 탭/label size/customer 변경과 화면 종료는 command 완료 전 차단한다.

## 13. 테스트

### 13.1 순수 model 테스트

- checked item ID add/remove/reorder와 item ID 선택 유지
- row 기본값의 item override와 공용 설정 fallback
- printer preference 변경 시 fallback 출처만 갱신되고 item override/session edit는 유지됨
- copies 0 허용, 음수/비숫자 거부, 전체 0 발행 차단
- copies가 0인 row의 unit/history/자동증가 제외, 총 1000장과 256 MiB 제한
- 물리 설정: margin+signed push 좌표, 전체 label clip, content 교집합, extra area, orientation의 page swap/좌표 transform, mm→dot 반올림과 유효 영역 validation
- 줄간격: session/item > global > 100 우선순위와 30~300 범위
- exact search: trim+대소문자 무시, 품명, `searchPrint` content, 비대상 content, 미체크 품목 제외, 중복 결과 순환
- 자동증가: 범위, 증가 크기, leading zero, overflow wrap, barcode check digit, time barcode, `autoIncSave`별 마지막 출력값/다음 값과 `autoIncUpdate` 무시
- copy별 projection이 원본 working value를 변형하지 않음

### 13.2 materialize/print job 테스트

- `#ITEMNAME`, `#ELEMENT`, 일반/날짜/시간 치환
- barcode/QR/GS1 payload와 연결 이미지 materialize
- 품목관리 미리보기와 라벨출력 copy 0 workbook의 동등성
- 원본 workbook 불변
- row별 physical size/margin+push/label clip/paragraph line spacing/orientation/extra area 반영
- unit별 copies=1이며 PDF page 수와 EZPL `^P1` label 수가 총 copies와 일치
- 같은 physical profile의 인접 unit group과 profile 변경 시 순서가 유지된 job 분리
- group별 명시적 PDF page format과 `directPrintPdf` 호출 수
- 자동증가 copy별 서로 다른 payload
- Godex hybrid EZPL의 label size, border, native barcode, bitmap fallback과 group별 RAW payload/`sendRaw` 호출
- unsupported/file port의 PDF fallback
- unit materialize 하나가 실패하면 dispatcher가 호출되지 않음
- 사전 예상량 또는 실제 payload 256 MiB 초과 시 dispatcher가 호출되지 않음
- 첫 group 실패와 앞 group accepted 후 다음 group 실패의 전송 중단·accepted unit 집계
- PDF `true`/interactive 취소 `false`/unconfirmed `false`/exception 및 RAW `EndDocPrinter` 결과 mapping

### 13.3 DAO 테스트

- 기존 item/column/content 조회 DAO 재사용
- 자동증가 update의 `(columnId,itemId)` parameter와 affected row 검증
- 자동증가 `autoIncSave` 최종값과 commit 후 draft/snapshot 부분 동기화
- `applyCommittedColumnContentUpdates`가 대상 scoped 원본/draft만 갱신하고 unrelated draft를 유지함
- history/status/detail의 자동증가 copy/일반 row 집계, projected/DB 원본 값 mapping과 column order
- customer history order lock과 자동증가/history 단일 transaction rollback
- table/column 부재 시 DDL 없이 명시적 오류
- job 취소/접수 실패 시 history와 자동증가 update가 없음
- 일부 group accepted 후 실패하면 accepted unit만 하나의 transaction에 반영됨
- commit 결과 불명확 시 추가 발행 차단

### 13.4 widget 테스트

- `label_print` placeholder 제거와 실제 화면 렌더
- 품목관리 발행 체크가 출력 목록에 반영됨
- 첫 출력 행 자동 선택과 선택 변경 미리보기 갱신
- 표는 품목관리 table style을 사용하지만 편집 command footer는 없음
- 자동 미리보기이며 별도 `미리보기` 버튼 없음
- 검색 영역 표시와 exact-match 선택, 검색만으로 발행되지 않음
- `[프린터 설정] 프린터명 [발행]` 순서
- 라벨출력 전용 설정 dialog에 copies와 내부 발행 버튼이 없고 `[취소] [적용]`만 있음
- 출력 중 table/settings/발행/context 변경 비활성
- 900x600 및 일반 desktop viewport에서 overflow/overlap 없음
- non-Windows에서 라벨출력 tab/command가 노출되지 않음

## 14. 구현 순서

1. 품목관리 발행 체크를 controlled state로 올리고 출력 row/session model을 구현한다.
2. 기존 품목 미리보기 materialize와 읽기 전용 preview를 공용 API로 추출한다.
3. 라벨출력 화면과 table/search/selection/자동 미리보기를 구현한다.
4. 프린터 preference/picker/validation 공용 로직, 라벨출력 전용 설정 dialog와 group dispatcher를 구현한다.
5. 단일 row·단일 copy 출력부터 연결한다.
6. 여러 row·copies와 자동증가 copy projection을 연결한다.
7. 자동증가 저장 DAO와 발행 이력 DAO를 구현한다.
8. focused test, analyze, 전체 test, 실제 프린터 수동 검증을 수행한다.

각 단계는 관련 focused test를 먼저 통과한 뒤 다음 단계로 진행한다.

## 15. 완료 조건

- `라벨출력(F3)` 탭이 더 이상 placeholder가 아니다.
- 품목관리 발행 체크 행만 출력 목록에 나타나고 item ID 기준으로 안정적으로 동기화된다.
- 행별 매수·크기·여백·밀기·줄간격이 레거시 fallback 규칙으로 초기화되고 출력 session에서 편집된다.
- 선택 행 미리보기가 자동 표시되며 품목관리 `출력내용 미리보기`와 같은 materializer를 사용한다.
- 별도 `미리보기` 버튼이 없다.
- 레거시 검색 대상과 exact-match 의미를 사용하되 검색만으로 물리 출력하지 않는다.
- 프린터 설정은 공용 preference/printer/validation 로직을 사용하는 라벨출력 전용 dialog이며 매수와 내부 발행 버튼이 없다.
- 일반 프린터 PDF와 Godex EZPL 경로가 현재 공용 출력 엔진을 통해 동작한다.
- 여러 품목과 행별 copies는 unit 순서를 유지하며 같은 physical profile의 인접 unit끼리 spool job으로 묶이고 profile 변경 시 별도 job으로 접수된다.
- 모든 unit은 출력 전에 materialize·capture되고, 중간 group 실패 시 뒤 전송을 중단하며 실제 accepted unit만 자동증가 저장과 발행 이력에 반영된다.
- 자동증가는 `autoIncSave`의 레거시 최종값을 재현하고 commit 후 해당 draft/snapshot만 동기화한다.
- 행별 margin+signed push, label clip, page 회전과 paragraph line spacing 계산이 미리보기·PDF·EZPL 실제 출력에서 동일하다.
- 검색은 발행 목록에서 trim·대소문자 무시 exact 비교로만 동작한다.
- 기능은 Windows desktop에서만 노출된다.
- 필요한 model/DAO가 책임별로 작성되고 기존 조회 DAO나 materialize/print 코드를 중복하지 않는다.
- DB schema/data migration과 레거시 수정이 없다.
- 총 copies 1000장과 예상/실제 payload 256 MiB 제한을 물리 출력 전에 검증한다.
- 관련 focused test, `flutter analyze`, 전체 `flutter test`, `git diff --check`가 통과한다.
